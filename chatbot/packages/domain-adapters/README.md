# Domain adapters

领域自己定义 Policy/Store 契约，组合入口使用 `createAdapterRegistry` 注册实现，并在启动时 `resolve`。应用服务接收选定接口。注册表只管理实现身份、契约检查、重复拒绝和注销；不管理业务规则、数据库或确认协议。

注册表属于一次组合，不使用进程全局变量。外部扩展通过领域插件的 `create*Plugin({registry})` 传入注册表；独立进程也要用的实现，必须在领域持久 `adapters.js` 组合入口登记。这样插件捕获、多份包加载、测试和多个应用实例不会互相覆盖注册。

每次注册都有独立身份；注销句柄只删除该次注册，即使同一工厂以相同 ID 重新注册，旧句柄也不会影响它。`resolve` 固定策略方法表和存储工厂；注销仅影响后续组合，不热换运行中的实现。

Policy 和 Store 契约均同步。原生 `async` 方法在契约检查时拒绝；普通方法的返回值在每次调用时检查，Promise 或带可调用 `then` 的对象立即触发包含领域/方法名的错误，包括读、写、事务和 `close`。被拒绝结果的 Promise rejection 会被接收，避免额外的未处理拒绝；打开失败的资源尽力关闭，不静默回退。

`openStore` 返回固定契约方法表的视图，绑定原始对象，兼容冻结对象、原型方法、私有字段和 getter，并保留 `.db` 等附加属性的读取。它不修改原始存储对象，也不承诺返回同一对象或复制全部属性描述符；服务通过领域接口使用该视图。

返回值检查发生在方法执行后，不能取消已经启动的异步副作用，也不检查实现内部绕过接口的调用；方法存在或同步返回都不能证明事务语义。新增存储必须运行领域一致性用例，列表的业务数据、审计和请求账本必须在同一同步事务内提交/回滚。异步驱动需另行调整服务契约。

具体契约和例子见[文档 21](../../../docs/21_后端职责分层与代码整理.md)。回归在 `chatbot/tests/domain-adapters/`。
