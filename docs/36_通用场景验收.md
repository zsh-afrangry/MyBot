# 通用场景验收

## 功能

场景自动发送测试消息、处理多轮确认、核对业务结果并清理专用资源。已接入的独立场景无需主人在 QQ 发消息。

| 独立场景 | 核验范围 |
| --- | --- |
| `confirmation` | 一次性提醒的多轮确认、投递拒绝、正式 Cron 到点与对账。 |
| `coding` | 编码启动、续接、失败及回传，使用本地 ACP 替身。 |
| `knowledge-bills-access` | 用[文档23的账单查询](23_KnowledgeMap业务能力桥接.md#接口)验证[文档24的主人工具白名单](24_统一身份与权限管理.md#主人代办白名单)：确认写入待同步、重启后准入、成员拒绝、撤权与账单保留。业务使用 KnowledgeMap 的真实接口和临时 SQLite。 |
| `scope-proof` | 同一宿主内普通入站与测试回合的会话、确认和回传隔离，业务存储和后台处理使用夹具。 |

生产目标的 `deployment` 只读核对在用进程、插件、有效工具、身份策略版本、健康、配置与人格对齐。

## 接口

`--list` 显示场景；`--target` 选择 `isolated` 或 `production`，可用 `--scenario ID` 限定单项。生产交互入口未启用。

默认报告写入 `test-output/scenario-acceptance/`；`--out` 可指定 `test-output/` 下的新 JSON 文件。`--model` 仅用于独立目标的 `confirmation`，用合成对话调用已配置的付费模型，验证对话与确认。运行前按[仓库授权规则](../AGENTS.md#需要单独授权的操作)核对副作用。

## 原理

- 独立 Fusion 使用专用工作区、身份、会话和业务数据。回环 OneBot 经正式 WebSocket 入站发送消息；验收关联入站账本、投递回执、工具返回和业务状态，按场景清理专用资源。
- 生产只读核验将监听端口关联到 `kurumi-fusion.service`，前后复核进程与配置。有效工具目录反映配置及会话投影；能否执行由[运行时授权](24_统一身份与权限管理.md#执行)决定。

### 确认测试作用域

同一独立宿主的技术用例由可信宿主绑定测试主体、会话、消息和有效期。确认核心在打开库之前选择专用后端，预览回执和授权限于测试作用域；后台回传读取任务保存的归属和收件箱。普通 OneBot 回合继续使用原有确认后端。

## 限制与已知问题

- 默认使用确定性模型；模拟 OneBot 只能证明应用收发与回执，平台登录和送达按[文档32](32_QQ渠道与SnowLuma.md)单独验证。业务替身和临时数据库的结果不代表真实 DSH 或生产 MySQL。
- 生产部署核验不覆盖在用进程的逐文件代码证明、真实对话及业务写入。生产 `testIngress` 保持关闭。

## 如何验证

先按[文档9](9_QQ融合助手架构与开发计划.md#开发与验证)准备依赖并构建确认核心、确认入口和共享领域库。账单场景使用文档23的 KnowledgeMap HTTP 测试服务；可用 `KM_TEST_REPO` 和 `KM_TEST_PYTHON` 指定检出目录和 Python 环境。

```bash
node chatbot/scripts/scenario-acceptance.mjs --list
node chatbot/scripts/scenario-acceptance.mjs --target isolated
node chatbot/scripts/scenario-acceptance.mjs --target isolated --scenario knowledge-bills-access
node chatbot/scripts/scenario-acceptance.mjs --target production
```

## 进行中：通用场景验收

### 生产场景交互

让 AI 代替人工发消息、查看预览、确认、追问与等待后台回执；个人体验和平台专项操作由对应账号本人验证。生产目标首个场景用一次性提醒走通只读对话、确认写入和隔离通知。

- 本机认证入口只启动已登记场景，由服务分配专用主体、会话、工具范围和收件箱。普通 QQ 和模型参数不能选择测试作用域。
- 确认、业务库、调度和回执绑定同一测试归属，重启或超时后仍能识别遗留任务。核对普通私聊、受管配置、资料和回传目标不受影响；没有专用资源的动作留在独立实例。
