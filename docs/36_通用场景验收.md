# 通用场景验收

## 功能

独立场景替代人工发送消息、查看预览、确认和等待回传，按账本与业务状态核验结果。

| 场景 | 核验范围 |
| --- | --- |
| `confirmation` | 提醒的多轮确认、歧义、拒收、过期、重放、改期、取消、正式 Cron 到点和[反馈查询](34_统一反馈模块.md)。 |
| `coding` / `coding-recovery` | 独立宿主的编码启动、续接、失败和回传，以及编码服务的取消、检查超时与重启核对。编码工具使用本地 ACP 替身。 |
| `access-member` / `access-mail` / `knowledge-bills-access` / `access-exec` / `access-project` | 五类白名单的确认、写入回查、加载生效、覆盖及撤权，账单场景用真实 KnowledgeMap 查询接口和隔离 SQLite。 [文档24](24_统一身份与权限管理.md#主人代办白名单) |
| `qq-feedback` | 正式私聊回复、分段查询和引用回认，判据见[文档34](34_统一反馈模块.md)。 |
| `bills-feedback` | 账单增改删、响应丢失后的只读回执和旧回执，用真实 KnowledgeMap API 与隔离 SQLite。判据见[文档34](34_统一反馈模块.md)。 |
| `reminder-list-feedback` | 同一消息下成功项和版本冲突项的日志反馈，用真实 KnowledgeMap API 与隔离 SQLite。 |
| `mail-feedback` | 邮件工具和本地 TLS SMTP 的逐封受理、拒绝、提交后断连和回执回查。 [文档20](20_邮件能力与横切扩展.md) |
| `paper-feedback` | 译稿登记后逐份核对 QQ 上传和邮件草稿。 [文档22](22_论文PDF翻译与文件投递.md#如何验证) |
| `media` | QQ 引用、图片、PDF 和同一账号回传。图片使用本地暂存，PDF 下载返回本地样本。 |
| `scope-proof` | 同一宿主内普通入站与测试回合的隔离，涵盖过期、错主体、回执缺失和后台错路由。业务库与后台执行使用夹具。 |
| `deployment` | 在用生产网关只读核验，覆盖实际应用的配置版本、五类白名单、身份与工具、插件、配置对齐和健康。 |

## 接口

`--list` 显示场景，`--target` 选择 `isolated` 或 `production`，`--scenario ID` 可限定单项。省略场景会运行该目标的全部已登记场景。

报告默认写到 `test-output/scenario-acceptance/`，`--out` 可指定 `test-output/` 下的新 JSON 文件。`--model` 仅适用于独立目标的 `confirmation`，用合成对话和角色投影复验语言理解和确认。调用实际付费模型须按[仓库授权规则](../AGENTS.md#需要单独授权的操作)执行。

## 原理

- 场景声明脚本、依赖和时限。独立 Fusion 使用专用身份、工作区、会话和业务数据，以回环 OneBot 接入正式 WebSocket。脚本按入站账本、回执、工具返回和业务状态判断是否通过。
- 报告记录 Git 版本、已运行的场景及证据，区分失败、环境阻塞和未覆盖。超时或中断会通知场景关闭临时网关与业务服务，缺少完成或清理证据时在报告中标明。
- 生产目标关联 `kurumi-fusion.service` 和监听端口，比较网关实际应用的配置版本。核对已有会话的工具目录和当前授权配置，前后复核进程和配置版本。

### 确认测试作用域

独立宿主的可信测试装配绑定主体、会话、消息和有效期。确认核心在打开库前选择专用后端，预览和授权限于本测试作用域，后台回传使用任务保存的测试归属与收件箱。普通 OneBot 回合使用原有确认后端。

## 限制与已知问题

- 生产目标限只读，`testIngress` 保持关闭。生产核验覆盖应用的配置与插件启用状态。白名单变更、确认写入、调度与隔离通知在独立实例验收。
- 默认用确定性模型和回环 OneBot。真实 QQ 登录及收件按[文档32](32_QQ渠道与SnowLuma.md)验证。业务替身和临时数据的结果限于场景记录的层级。
- 已登记的生产成员即使尚无会话也会核对路由和工具配置。会话工具目录的结论只覆盖已建立会话的账号。

## 如何验证

先按[文档9](9_QQ融合助手架构与开发计划.md#开发与验证)准备 OpenClaw 和构建依赖。`knowledge-bills-access`、`bills-feedback` 和 `reminder-list-feedback` 使用文档23的 KnowledgeMap HTTP 测试服务，可用 `KM_TEST_REPO` 和 `KM_TEST_PYTHON` 指定检出目录与 Python 环境。

```bash
node chatbot/scripts/scenario-acceptance.mjs --list
node chatbot/scripts/scenario-acceptance.mjs --target isolated
node chatbot/scripts/scenario-acceptance.mjs --target isolated --scenario knowledge-bills-access
node chatbot/scripts/scenario-acceptance.mjs --target production
```

OpenClaw 2026.11.1 已通过生产只读核验。独立场景的覆盖范围和版本见每次运行的报告。
