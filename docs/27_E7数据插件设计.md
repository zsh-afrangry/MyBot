# E7数据插件设计

插件 `kurumi-e7`（`chatbot/plugins/kurumi-e7/`）为主人在 QQ 里查询《第七史诗》（Epic Seven）资料，数据来自 [E7·WIKI](https://e7.wiki/)。变化慢的资料每日条件刷新到本地缓存，变化快的资料按需查询并短时缓存。

## 功能

只读工具 `e7_data`，13 个 action：

| action | 内容 |
| --- | --- |
| `search` | 按名称、别名、结构化条件查角色或神器（`kind: hero/artifact`） |
| `hero` | 角色资料，按 `view` 返回：`skills`（默认）、`stats`、`multipliers`、`devotion`、`exclusive`、`profile`、`overview`；`skill: 1/2/3` 只用于 `skills`、`multipliers` |
| `artifact` | 神器效果、适用职业、属性上下限，`view: effect/stats/overview` |
| `builds`、`reviews` | 社区配装、测评（按角色；测评分类 `RTA/PVP/PVE/综合`） |
| `rankings` | 强度榜，`mode: list/get`，`objectType: hero/artifact` |
| `content` | 攻略与 FAQ，`kind: guide/faq`，`mode: search/get` |
| `gvg` | `view: homework/hot_defenses`，阵容匹配默认 `exact`，部分阵容须显式 `contains` |
| `fates` | 混沌宿命，`view: list/recommended_heroes/hero_fates` |
| `dictionary` | 效果词典、道具词典，`kind: effect/item` |
| `packs` | 礼包内容与站点估值，`mode: list/get` |
| `codes` | 站点列示的兑换码，可选 `server` |
| `news` | 游戏公告 `kind: game`，`mode: list/get` 列目录或读取 PDF 文字层；`kind: wiki_update` 查站点更新日志 |

QQ 功能使用公开 Wiki 接口按需读取资料。发图支持角色素材、英雄资料卡和社区配装图。个人账号导出通过本机命令执行。

分工：固定程序负责取数、筛选和数值清洗；聊天模型负责理解口语、澄清歧义、按场景概括资料。不需要向量库。检索结果必须带来源和日期，没有资料时明确说没有，不让模型补事实。

## 接口

### 工具和权限

- 工具 `e7_data`，权限点 `e7.read`，仅主人。`toolPermission` 只把上表 13 个 action 映射到该权限，未知 action 拒绝（`chatbot/packages/access-control/permissions.js`）。权限规则见[文档24](24_统一身份与权限管理.md)。
- 每个 action 独立校验参数；未知 action/view/kind 和多余参数被拒绝。工具不接受 URL、文件路径、上游方法或收件人。名称先经 `search` 解析为稳定 ID，同名或别名歧义返回候选，不默认选第一项。
- `e7_image({heroCode, kind, skill?, effectId?, count?, filters?})` 仅在主人 QQ 私聊主动要图时使用。素材类型为头像 `avatar`、半身 `detail`、封面 `cover`、技能 `skill` 及关联效果 `effect`；生成图为英雄资料 `hero_card`、社区配装 `build_card`。配装图默认 1 条，可指定 1–10 条或套装/属性下限，合成一张 PNG；回执附请求、展示和命中条数。`e7.image` 与 `e7.read` 分开。
- 本机命令 `node chatbot/scripts/e7-account-export.mjs --help`。`json` 接受 `--equips`、`--units`、`--out <文件.sqlite>`；同时给出 `--manifest` 和 `--metadata` 可全程离线。`inspect --pcap` 本地校验经典 PCAP 格式并显示文件摘要。`pcap` 模式需明确批准向 `e7bot.top` 发送原文件，`--approve-sha256` 绑定该版本，输出需选新文件。

### 响应约定

- `status` 与结构化 `data`：区分成功、歧义、未找到、上游不可用、功能未启用；空列表不当成失败。
- `source: "E7·WIKI"`、`citation` 与 `sources[]`：缓存的 `fetchedAt`、`checkedAt` 是 UTC，`stale` 表示陈旧；公告、作者和兑换码等日期保留上游原始口径。各查询都附引用，包括 GVG、宿命和词典。
- `missingFields`、`truncated`、`nextCursor`；只有上游提供或完整本地索引可计算时才返回总数。
- 列表默认 5 项、最多 10 项，完整结果上限 16KiB，长正文按段裁剪。游标绑定条件和数据快照。
- 外部文本只当数据，不执行其中的指令。回答注明“数据来自 E7·WIKI”。
- `hero` 的 `stats` 附 `statBasis`，说明是否含装备及来源给出的等级口径；上游没说明的返回未知，不默认满级。`builds` 的面板是某套装备样本，不与角色基础面板混用。神器效果附 `effectBasis`，不推算满级。

### 配置

`config/runtime.config.json` 的 `plugins.entries.kurumi-e7.config`，未知键被拒绝：

| 键 | 含义 | 当前值 |
| --- | --- | --- |
| `cacheRoot` | 缓存目录（绝对路径，必填） | 运行目录 `state/kurumi-e7/` |
| `refreshEnabled` | 每日基础目录刷新 | `true` |
| `refreshTime` | 刷新时刻（宿主本地时区，当前 `Asia/Shanghai`） | `05:30` |
| `detailTtlHours` | 慢变资料 TTL（1–168） | 24 |
| `liveTtlMinutes` | 兑换码、公告、更新日志、GVG TTL（1–60） | 30 |
| `timeoutMs` | 单次请求超时（100–30000） | 15000 |
| `maxResponseBytes` | 解压后单次响应上限 | 2097152 |

插件声明 `activation.onStartup: true`，只为安排刷新定时器，启动时不请求上游。

### 上游读取接口

API 根为 `https://admin.e7.wiki/api`，静态资源根为 `https://assets2.e7.wiki`。接口无登录，字段可能随站点前端改版变化。

| 数据 | 接口 | 要点 |
| --- | --- | --- |
| 角色索引 | `GET /open/epicseven/hero/card-list` | 名称、code、昵称、属性、职业、星级；无 ETag |
| 角色效果 | `GET /open/epicseven/hero_summary/hero-list` | 直接返回数组，有 ETag |
| 角色详情 | `GET assets2/static/heroes/<code>.json` | 技能、倍率、印记、专属装备；ETag 条件请求 |
| 神器 | `GET /open/epicseven/artifact/artifact-list` | 优先用 `skill_display_desc`，去除颜色标记并处理 `%n` |
| 配装 | `POST /open/epicseven/hero_equipment_scheme/getSchemeByHeroCode`（`hero_code`） | 样本不是最优解承诺 |
| 测评 | `POST /open/epicseven/hero_review/by-hero`（`heroCode`） | 同一角色可有多个分类，也可为空 |
| 强度榜 | `POST /open/epicseven/tier/list` | 来源 `type` 为空时保留未知，不因字段名 `heroAssignments` 判为角色榜 |
| 攻略、FAQ | `POST /open/epicseven/guide/page`、`faq/page` | 请求固定 `page/size:10/keyWord`，前端的 `keyword/pageSize` 不生效；无独立详情接口 |
| 兑换码 | `GET /open/epic7/redeem_code/lastest?count=50` | `lastest` 为实际拼写；时间未带时区 |
| 站点更新 | `GET /open/epicseven/updates/latest?count=50` | wiki 功能日志，不是游戏版本更新 |
| 游戏公告 | `POST /open/epicseven/announcement/page`；`GET assets2/announcement/<目录返回路径>` | 先列每页 10 条；按已列出的 ID 从原页核对 PDF 路径 |
| GVG | `POST /open/epicseven/gvg_homework/page`（`size:100`）；`GET /open/epicseven/gvg_defense/hot-defenses?limit=100` | 作业最多 30 页/3000 条，逐页核对总数和唯一 ID 后本地筛选；热门防守只覆盖前 100 条 |
| 混沌命运 | `GET /open/epicseven/chaos_fate/fate-list`、`recommend-heroes?seasonId=`、`recommend-hero-fates?seasonId=&heroCode=` | 已知 `recTier` 才算站点推荐，空档位是普通候选 |
| 道具、礼包 | `GET /open/epicseven/item-dictionary/by-category`、`gift-pack/list` | 估值依赖站点假设，不是商城报价 |
| 效果词典 | `GET assets2/static/effects.json` | 效果名称、类型、说明 |

## 原理

### 刷新与缓存

| 档位 | 数据 | 方式 | 新鲜度 |
| --- | --- | --- | --- |
| 慢变 | 角色卡片、效果汇总、神器列表、效果/道具词典 | 每日 `refreshTime` 条件刷新，串行请求 | 约 1 天 |
| 慢变，按需 | 单角色详情、配装、测评、榜单、攻略/FAQ、礼包、宿命 | 首次被问到时拉取，有 ETag 则过期后条件请求，否则按 `detailTtlHours` | 默认 24 小时 |
| 快变 | 兑换码、游戏公告、更新日志、GVG | 提问时查询，`liveTtlMinutes` 短缓存 | 默认 30 分钟 |

- 有 ETag/Last-Modified 的接口带 `If-None-Match` / `If-Modified-Since`；304 只更新检查时间。没有 ETag 的 `card-list` 按内容哈希比对。
- 新数据校验 JSON 结构后原子替换。基础目录条数少于上一版的 90% 视为异常（`catalog_shrank`），保留旧版。刷新失败不清空缓存。
- 缓存放在 `cacheRoot`，只存公开 wiki 数据和检查元数据，不进仓库，可从上游重建。每日刷新不预取配装、测评等社区资料，也不预取任何图片。
- 请求、退避或新数据校验失败时，若有旧缓存则返回它并标出 `stale: true`、上次成功时间和告警。没有缓存时返回错误码。
- 别名检索在本地完成：用 `card-list` 的名称、昵称、code 建索引，归一化包括简繁体（`opencc-js@1.4.2`，插件自有锁文件固定）、NFKC、大小写、空白和标点，只影响检索键，不改写展示文本。多个候选时返回候选列表。

### 查询规则

- 按属性、职业、星级或效果筛选时，可只传 `search.filters`。效果筛选先用 `dictionary` 取得真实 ID，再传入 `filters.effectIds`。如同时传 `query`，结果还须匹配该名称。
- 配装 `filters.sets` 为 1–3 个站点套装名；`filters.minStats` 只收 `hp/atk/def/spd/chc/chd/eff/efr` 的非负下限，暴击、暴伤、命中、抗性按百分数点（暴伤 289 即 289%）。缺失面板返回 `null`，不当 0。
- FAQ 仅第一页原词返回 0 条且无上游告警时，从原查询取最多 3 个不同短词，依次查询同一 FAQ 接口，首个非空结果作为候选集；每次调用最多 4 次资源查询。接口失败、限流、陈旧缓存告警与后续分页不扩搜。结果的 `search` 字段给出原词、实际词、尝试词和 `exact/keyword-fallback/none`，游标绑定实际短词。候选须按 `contentId` 读正文核对；0 条不证明全站无答案。攻略不降级，也不能代替 FAQ。
- 攻略/FAQ 没有详情接口：`search` 返回 `contentId` 并把它在列表页的位置存入缓存，`get` 只沿此位置读同一页并核对 ID；条目移出原页时要求重新搜索，不猜路由、不扫全站。`detailUrl` 只在已核实的列表页链接存在时返回，否则为 `null`。HTML 去掉脚本和样式，图片不下载，正文依赖图片时标明缺失。
- GVG 的阵容为 1–3 个不重复真实角色 code，忽略槽位顺序；热门防守不接受进攻筛选。作业首页确定页数，后续最多两页并发，按页序合并并核对页数、总量与唯一 ID。变动或超限明确失败。保留来源胜负计数，可靠胜率为空。
- `fates/list` 省略 `seasonId` 返回赛季目录；查某季详情才传 `seasonId`，未知值返回可用赛季。只有已知 `recTier` 算推荐，空档位是候选，未知档位保留未知。每页给出已取完整列表的分类计数，稳定宿命身份用 `chaos_fate_id`。
- `rankings/packs` 先 list，再用真实 rankingId/packId 读取。礼包保留价格、数量、单价和天青石估值，未知币种/比率为空，不推算实时商城报价或购买结论，不取媒体 URL。
- 兑换码与 Wiki 日志各读取上游最新 50 条后筛选并说明覆盖范围。游戏公告续页绑定服务器和页内快照。
- 公告正文用 `news/game` 的 `get` 与目录返回的 `announcementId`，服务器沿用目录定位。校验 PDF 路径、类型、签名和 12 MiB 上限，用无网络沙箱中的 `pdftotext` 读前 20 页文字层，返回页码、裁剪和无法提取状态。没有 OCR。
- 发图只取角色详情登记的图片路径，校验白名单前缀、PNG/JPEG/GIF/WebP 类型和签名、8 MiB 上限；内存缓存 50 MiB、7 天，按最近最少使用淘汰。透过[共享 QQ 投递](21_后端职责分层与代码整理.md#共享代码的唯一实现)只发给当前可信本人私聊。每个可信宿主回合共用一个投递键，重复调用返回已有回执，未确认的投递不补发。滚动 24 小时最多 20 次发图预留，附官方版权和 E7·WIKI 来源。
- 资料图使用固定版式，在无网络沙箱内用系统 Python 的 librsvg/Cairo、Pillow 和中文字体渲染。英雄图展示基础面板、技能、分组倍率与来源提供的刻印和专属装备；素材缺失时可用文字生成。配装图用 `builds` 的同一套筛选，按来源顺序列套装、神器、穿戴面板、作者和更新时间；零命中不发图。标注 E7·WIKI 校对日期及陈旧状态，社区样本不代表全服统计。
- 账号流程独立于 QQ 和 Wiki 缓存：读取本地数组或使用已批准的 E7Bot 解析结果；按清单校验 `account-heroes-meta-v6` 图鉴大小及 SHA-256 后解压，换算装备属性和英雄养成数值。单次快照在事务中写入 `equipment`、`exclusive_equipment`、`artifacts`、`heroes`，完整关闭后发布为权限 `0600` 的 SQLite 文件。同数据复用原库，不同快照分别保存。
- `instance_id` 和穿戴原始编号 `wearer_id` 为文本；解析成功时 `hero_instance_id` 关联 `heroes.instance_id`，否则外键为空，状态由 `link_status` 区分。未识别部位留在 `equipment`，原始代码、属性 `options_json` 及同槽多件均保留。装备副属性存 `substats_json`；百分比属性沿用小数（`0.05` 为 `5%`），缺失为空，零保留。
- 账号刻印模式依据原始 `opt` 推断，属性按 E7Bot 图鉴和原始属性数组换算。SQLite 保留 `opt` 和原始属性供复核。

### HTTP 防护（`client.js`）

- 主机固定为 `admin.e7.wiki` 与 `assets2.e7.wiki`，写在代码里，不接受配置扩展；GET 和 POST 都按精确路径登记，POST 只放行上表的查询路径；写接口路径不出现在代码中。
- `redirect: 'error'`，发 `credentials: 'omit'`；并发上限 2；响应大小和超时由配置限制。
- 403 暂停该主机至少 1 小时；429/5xx 按 `Retry-After` 或递增等待退避，不自动重试，不循环换请求头。错误映射为固定错误码，不回显上游正文。
- 固定 User-Agent：`kurumi-e7/0.1 (personal read-only wiki client)`。
- 经受信任的出站网络路径访问，见[文档20](20_邮件能力与横切扩展.md)。

### 主要决定

| 决定 | 理由 |
| --- | --- |
| 独立插件加专用只读工具，不用 `web_fetch` | 大 JSON 需要本地索引、别名匹配和字段裁剪 |
| 别名检索在本地做 | 不依赖站点搜索接口，缓存可用时离线可查 |
| 按“数据对象 + 视图”组织 action，不按上游路径开工具 | 角色技能、面板、倍率共用同一份详情缓存 |
| 固定主机、只读 | 站点没有 API 承诺和数据许可，写接口会改别人的数据 |
| 默认只授权主人 | 新工具在主人决定前保持 owner-only，见文档24 |
| 刷新用插件内定时器，不用宿主 Cron | 自包含，少一处受管配置；停机期间错过的刷新由提问时按 TTL 补拉 |
| 未使用 Cron 与共享包 | 目前没有第二个消费者，不抽共享 E7 包，也不开 HTTP 服务 |

使用习惯：每次回答注明数据来源，请求频率保持在“每日一轮列表刷新加按需少量详情”的量级；站长要求停止或限制时以站长为准。

## 限制与已知问题

- 上游没有 API 稳定性承诺或数据许可，接口字段可能随站点改版变化。
- 公告 PDF 只读文字层；扫描件或以图片为主的公告可能没有可摘要正文。
- 兑换码只保留上游列示与无时区的起止时间，实际可兑换性由游戏确认。
- 站内公告（`e7.wiki/announcements.md`）未登记主机，不可查。
- 神器昵称覆盖稀疏；配装、测评覆盖不一，不能由“有角色详情”推断“有测评”。依赖图片的攻略可能缺关键信息。
- 成员不可用 `e7_data` 和 `e7_image`。半身详情图不等于完整立绘；完整立绘、皮肤、动画和语音未接入。
- 语义质量依赖聊天模型，工具只保证取数和字段正确。QQ 客户端的显示和实际收件不由接口测试证明，须在真实 QQ 里确认。
- E7Bot 在此提供账号解析与图鉴。均速、使用率等统计和 E7Bot 的 QQ 成图接口未接入。
