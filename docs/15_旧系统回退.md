# 旧系统回退：归档保留 + 原路径复制恢复 + 显式切换

## 决定

旧系统**不重写内部路径**，保持归档现状。需要回退时把它复制还原到原路径，再显式切换服务。
这与"移出活动目录"不矛盾——两者对应不同阶段：

| 阶段 | 旧系统在哪 | 新系统 |
|---|---|---|
| 日常运行 | `/home/afrangry/kurumi-archive` | 独立工作，不依赖旧路径 |
| 明确回退 | 复制还原到 `/home/afrangry/.openclaw` 等原路径 | 消费者停止，让位 |
| 防误启动 | 服务屏蔽措施 | —— |

把旧目录长期留在原位会让"新系统是否又偷偷依赖旧路径"难以发现；归档则让它更容易暴露
（`verify-dependencies.mjs` 现在会把任何指向归档树的软链判为失败）。

## 工具：`scripts/fusion/restore-legacy.sh`

```bash
./scripts/fusion/restore-legacy.sh                      # 只检查（默认，不动任何东西）
./scripts/fusion/restore-legacy.sh --restore            # 预演：列出将要做什么
./scripts/fusion/restore-legacy.sh --restore --confirm  # 真正执行复制还原
```

设计约束（按主人要求）：

1. **默认只检查**：归档、备份、目标路径、服务状态都不改。
2. **执行前停止融合侧消费者**（`kurumi-fusion`、`snowluma-qq`、`snowluma`），
   且**不触碰** `/home/afrangry/.openclaw-fusion`——新系统配置与数据原样保留。
3. **复制而非移动**：归档原件永远保留；**目标已存在就停止，不覆盖不合并**。
4. **检查符号链接、依赖、配置与单元**。单元若仍指向原路径就无需修改（实测确实如此）。
5. **脚本不启动任何服务。** 启动是独立的显式步骤（见下），
   不把"自动启动验收"绑进恢复脚本。
6. 脚本明确提示：回退恢复的是**封存时的旧系统**，**不会**带回新系统里新增的记忆、提醒、会话。

## 启动前风险审计（脚本【6】段的实际输出）

这是本工具最重要的部分：**旧系统有自己的调度，启动后会按它自己的计划执行并可能真实外发。**

| 风险项 | 实测结果 |
|---|---|
| 旧 Cron | **3 个 enabled**。其中 `kurumi 每日天气简报` 为 `30 10 * * *` Asia/Shanghai，`delivery=announce/qqbot` —— **启动后每天 10:30 会真实向本人 QQ 外发**。另两个（Memory Dreaming Promotion、skill-collection-review）`delivery=none` |
| 旧提醒 | 全部终态（cancelled=3, delivered=6），启动后不会补投 ✓ |
| 旧外发白名单 | 私聊 1 个（本人），**群 1 个** —— 旧系统允许向群外发，而新系统是仅本人私聊 |
| 旧 bridge 模式 | `social-v2.paused = false`，**未暂停**，启动后会主动参与会话 |
| 旧单元 | `openclaw-gateway` 仅 `EnvironmentFile` 引用原路径（ExecStart 用全局安装）；`qq-bridge` 有 `WorkingDirectory`。还原后都能按原路径生效，**无需改单元** |

因此启动旧系统前必须先处理：禁用不再需要的旧 Cron、确认那 1 个群是否仍应可达、
决定 bridge 是否要先暂停。

## 防误启动

`openclaw-gateway` 与 `qq-bridge` 当前都是 `disabled` + `inactive`，但**不能依赖"路径失效"**：

- `EnvironmentFile=-/home/afrangry/.openclaw/gateway.systemd.env` 带 `-` 前缀，
  按 systemd 语义**文件缺失会被忽略**；
- `ExecStart` 指向**全局安装**的 `/home/afrangry/.npm-global/lib/node_modules/openclaw/dist/index.js`，
  该文件仍然存在。

所以手动 `systemctl --user start openclaw-gateway.service` **有可能真的把服务拉起来**。
要封死请执行：

```bash
systemctl --user mask openclaw-gateway.service qq-bridge.service
```

## 回退会带回什么、不会带回什么

**会带回**：封存时点的旧程序、旧配置、旧凭据、旧数据库（旧提醒与旧调度状态）、旧会话记录。

**不会带回**：你在新系统 `/home/afrangry/.openclaw-fusion` 里新增的**记忆、提醒、会话、配置**。
两套数据互不同步。若只想找回某条旧记忆或某条旧提醒，应当**单独从归档里读**，
而不是整机回退。

## 两套系统的边界

| | 旧系统 | 新系统 |
|---|---|---|
| 程序 | `/home/afrangry/kurumi-archive/legacy-openclaw` | `/home/afrangry/kurumi-fusion` |
| 运行数据 | 归档内的 `state/`、`.env`、`openclaw.json` | `/home/afrangry/.openclaw-fusion` |
| QQ 传输 | 经旧 `qq-bridge` | 经 `kurumi-qq` 频道（SnowLuma 3083/3084） |
| 调度 | 旧 OpenClaw 自己的 Cron | 原生 automations / 插件 reconciler |
| 外发范围 | 本人私聊 + **1 个群** | 仅本人私聊 |

两套系统**共用** QQ 客户端与 SnowLuma 传输组件，所以不能同时跑两个消费者。
