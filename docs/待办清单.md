# 待办清单

类型：永久任务清单。状态：持续维护；本轮只推进 **N9 文档整理**，其余业务任务不因整理自动关闭。

这里保存“现在做、接下来做、暂不做、已完成”。目标可拆成能独立验收的子目标；说明、实现方案和用例写普通文字，不给每句话加复选框。同一任务只保留一个正文位置，其他分区只链接。

## 维护约定

- `- [ ]`表示尚未验收，包括代码已完成、等待复验；`- [x]`只用于已有验收依据的完成目标。父项的必需子目标全部验收后才勾选。明确决定“不实施”可关闭决定项，不能据此声称功能已实现。
- 状态使用：待处理 / 处理中 / 待复验 / 已验收 / 阻塞 / 经用户确认延期。AI完成的业务实现先记“待复验”，由主人确认；只读文档/本地检查结果作为证据记录，不代替用户阅读复核。
- 沿用A–G、N编号；N11–N19为文档16既有缺口补充的追踪ID，未新增业务范围或改变排期。后续新需求用下一个N号，已有目标可拆成`E1.1`等子目标，测试用例沿用T1–T4。编号不复用、不因排期移动改号。
- 每项至少写目标、下一步、验收责任/边界和规则/证据入口；排期变化就移到对应分区。完成后提炼规则、保存证据，将简短结论移入“已完成”，不直接抹掉。
- 长过程进`verification/`或有来源的历史记录；清单只留当前问题、决定与下一步。完成记录积累过长时按日期归档并保留链接，不重编号。
- 真实模型、外发、重启、停写/恢复与远端写入按本次授权分别执行。测试前的旧授权不自动续期；不把本文用例当执行许可。
