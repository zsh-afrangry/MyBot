# 检索功能

## 功能

- 助手用宿主自带的 `web_search` 发现公开网页来源，用 `web_fetch` 打开具体页面读原文，回答里附真实链接。
- 搜索服务只负责找来源，它的摘要不作为最终依据。
- 主人、已登记成员和后台的 researcher 都能用。

不做的事：

- 不用浏览器，不处理需要 JS 渲染或登录的页面。重新评估的条件：出现一个真实场景，目标页面 `web_fetch` 读不到，而且信息无法从别处获得。
- 不为检索新增领域专属工具，不把搜索结果自动写入记忆。
- 搜索不替代天气这类专业数据源。

## 接口

| 工具 | 权限点 | 说明 |
| --- | --- | --- |
| `web_search` | `search.use` | 当前提供方是 Tavily |
| `web_fetch` | `search.use` | 宿主直接抓取并提取正文 |

配置在 `config/runtime.config.json` 的 `tools.web`：

| 键 | 当前值 | 作用 |
| --- | --- | --- |
| `search.provider` | `tavily` | 搜索提供方，必须显式指定 |
| `fetch.useTrustedEnvProxy` | `true` | 抓取走本机代理，否则部分境外站点连不上 |
| `fetch.maxChars`、`maxCharsCap` | 15000 | 单页进入上下文的字符上限 |

Tavily 插件的版本固定在 `config/plugins.package.json`，密钥在运行目录的 `runtime-env.json`。

## 原理

- **为什么让模型直接读原文**：早期方案是让另一个模型搜完再总结，主模型拿到的是二手摘要，细节丢失，也无法核实。现在主模型自己读原文。
- **为什么敢放开联网**：写操作的安全不靠“禁止联网”保证。提醒、资料、行程、邮件的提交都要主人在 QQ 里的原始确认消息，网页内容伪造不了它，见[文档6](6_二次确认.md)。网页内容一律当作不可信资料，不当作指令。
- **为什么限制单页长度**：整页内容可达几十万字符，全部进上下文成本很高。
- **为什么选 Tavily**：它是宿主内置的提供方，不用写代码，返回结构化的来源列表。直连 DuckDuckGo 和 Brave 在本机超时。
- 提示词里要求简单的时效性问题先搜索、再读原文、附链接，模板在 `scripts/fusion/templates/AGENTS.md`。

## 限制与已知问题

- 单次检索偏慢。模型会多次搜索和核实，一个问题可能调用多次工具。
- 需要登录或 JS 渲染的页面读不到。

## 如何验证

配置是否生效：`node scripts/fusion/sync-config.mjs --diff`。真实检索要在 QQ 里问一个时效性问题，看回答是否附了真实链接。

## 进行中：DeepSeek 提供方

主人已决定暂缓启用。代码已在仓库，生产没有加载，也没有发出过真实请求。

**需求**：在宿主原有的 `web_search` 和 `web_fetch` 下增加 DeepSeek 提供方，不新增工具名。

**已实现**：插件 `chatbot/plugins/kurumi-web-deepseek/`，`index.js` 注册搜索和抓取两个提供方（ID 都是 `deepseek`），`client.js` 是固定端点的 HTTP 客户端。

- 选择必须显式：宿主的自动发现不会选中它，要把 `tools.web.search.provider` 或 `tools.web.fetch.provider` 写成 `deepseek`。
- 配置：`credentialsFile`（必填，绝对路径，权限 0600，内含 `DEEPSEEK_API_KEY`）、`traceFile`（可选）、`timeoutSeconds`（1 到 60，默认 25）。
- 搜索只接受 `query` 和 `count`（1 到 10，默认 5）。其他过滤参数返回 `unsupported_parameter`，提示改写成查询运算符。
- 抓取不是全量代理。宿主先自己直取，只在可补充的失败路径上才用提供方。宿主因 SSRF 拒绝或请求被取消时，不会转给提供方。
- 插件不自动重试，避免重复计费。最多 4 个并发，响应上限 4 MiB。
- 配置了 `traceFile` 时，每次调用记一条日志，不含查询文本、URL、正文和密钥。

**官方接口**：`POST https://api.deepseek.com/v1/tools/search` 和 `/v1/tools/fetch`。每 1000 次成功且非空的请求 0.75 美元，失败和空结果不计费。模型读入结果的 token 照常计费。
