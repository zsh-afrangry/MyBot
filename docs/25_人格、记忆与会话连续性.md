# 人格、记忆与会话连续性

本文说明 kurumi 的人格、私聊信息边界、本人记忆与会话连续性。本人指权限配置登记的 `owner`，身份与授权见[文档24](24_统一身份与权限管理.md)，新版记忆见[文档29](29_记忆系统.md)。

## 功能

- **人格**：角色名为 `kurumi`，项目名为 `kurumi-fusion`。与本人保持平等的恋人关系，与成员是普通朋友。成员可知道 kurumi 已有恋人；恋人的身份、账号、可指认的线索和共同经历不公开。
- **私聊信息**：成员各用自己的会话，不获取本人记忆或其他账号的会话内容。本人可按需[查询其他账号的留存互动](18_跨模块链路日志查询.md#私聊互动视图)，查询结果不跨会话自动注入，也不作为长期记忆来源。
- **统一表达**：日常与通知用同一人格，业务关键事实以业务结果为准。需要查询或操作时可先自然回应，处理较久或遇到困难时说明进展；措辞由模型按语境决定。表达层职责见[文档21](21_后端职责分层与代码整理.md)。
- **本人长期记忆**：可信本人私聊可保存普通陈述，也可明确要求记住、更正或遗忘。成员没有长期记忆。
- **`/new` 连续性**：重开可见聊天历史，保留有效的长期事实和未过期的近期摘要。
- **主动唤醒（N3）**：固定周期给助手一次“自己决定是否开口”的机会，只面向本人账号，只读探索。**生产未启用**，见下文。

人格影响表达，不改变授权或业务结果。kurumi 不编造共同经历、线下活动或天气，不维护持久情绪、角色日记或自动成长。

## 原理

### 人格投影

- SOUL、IDENTITY 对所有账号相同；关系段按可信角色投影到各自的 `USER.md`。本人资料不进入成员文件。
- 日常称“你”或昵称，操作说明使用“当前用户”“本人账号”或直接描述请求。关系称谓与程序权限分别管理。
- QQ 发送者名称取与入站账号 ID 一致的平台昵称，清除控制字符、合并空白并限制 80 个 Unicode 码点；昵称缺失、无效或账号不一致时显示“用户”。昵称仅用于展示，不参与身份、权限、会话和投递目标选择。
- 角色背景不锁定随日期失效的学籍信息，不预置告白日期、学长关系等共同历史。
- 宿主每回合重新核对四份受管文件；同步的范围和生效条件见[人格投影契约](../config/README.md#人格投影契约)。

### 每次消息进入模型的内容

| 内容 | 来源 |
| --- | --- |
| 四份受管人格文件 | 宿主读取该 Agent workspace，按会话类型和 bootstrap 预算装配。投影入口见[文档24](24_统一身份与权限管理.md#代码入口) |
| 当前会话历史与宿主压缩摘要 | 宿主按所选 Agent/会话读取，不附带旧会话全文 |
| 本人长期事实与近期摘要 | 可信本人入站后，`before_prompt_build` 从 SQLite 生成 `KURUMI_PERSONAL_MEMORY_V2`，资料用 `prependContext`，固定使用规则用 `appendSystemContext`（`continuity/plugin.js`、`continuity/application.js`） |
| 当前消息、媒体、工具信息 | QQ 入口处理，规则见[文档9](9_QQ融合助手架构与开发计划.md)、[文档22](22_论文PDF翻译与文件投递.md) |

仓库 `docs/`、根 `AGENTS.md`、未选用的角色卡、`INNER.md`、`HEARTBEAT.md`、任意 `memory/*.md` 都不会随消息传入。运行工作区的 `MEMORY.md` 只作说明，记忆事实来自数据库。宿主对群聊、子 agent 和 Cron 裁剪 bootstrap 文件；成员使用独立 workspace。

### 记忆存储与检索

| 数据 | 位置与限制 |
| --- | --- |
| 当前对话与旧会话原文 | 宿主 agent 会话 SQLite；`/new` 后原记录仍保留 |
| 宿主压缩摘要 | 属于宿主会话，不是自动记忆的来源 |
| 长期事实/偏好 | 连续性 SQLite，最多 128 条，不按时间淘汰；满后写入明确失败，不自行淘汰 |
| 近期摘要 | 同一库，最多 32 条，默认 7 天；只有未过期的进入上下文 |
| 日志、任务账本、业务事项 | 各功能自己的库，不复制成陪伴记忆 |

- **单一事实源**：连续性 SQLite 是唯一可写来源，以单行 `version=2` 的有界 JSON 快照存事实、摘要、来源、回执和遗忘屏障，用事务加 revision 比较写入处理并发。
- **注入**：`context()` 从本次原文提取拉丁词/数字和连续两个汉字片段，按命中数、更新时间给事实排序，先放事实再按新到旧放摘要，超预算的整条跳过。`maxContextChars` 只限制资料部分，零命中事实也可能在预算内带入。
- 长期沟通偏好帮助选择回复的措辞和细节，以本次明确要求为准。偏好本身不授予操作权限。
- **检索**：`search` 是规范化文本的子串匹配，没有向量检索或跨会话 RAG。
- **会话工具**：`sessions_list`、`sessions_history` 登记为 `sessions.read`，`sessions_search` 未登记会被拒绝。连续性插件不遍历旧会话抽取事实，被遗忘后也不借会话工具找回。

### 写入、更正与遗忘

- 模型判断普通陈述是否值得记。后端校验来源、结构、版本和事务，拒绝敏感凭据；没有回合结束后的自动归纳。
- **术语**：revision 是状态版本号，写入须带读取时的 `expectedRevision`，不同即拒绝；generation 在更正文本或遗忘时加 1 并清空近期摘要，旧回合因此不能写回；遗忘屏障保存被更正/遗忘文本的哈希（最多 256 条），自动记忆遇到同文不再保存，本人显式要求重新记住时移除。屏障只是同文保护，不识别语义改写。
- **来源**：`observe` 只取当前可信本人原文，不从模型回复、旧聊天、角色虚构或业务库汇总。摘要标为模型归纳并带期限，不晋升为确认事实。
- **一条消息最多成功写一次**：成功回执最多保留 256 条。参数校验失败可修参重试，成功后只允许同参幂等重放。两种写入需分开提出。缺少或冲突的 `revision`、记录 ID 可用 `list/search` 重查。
- **批量遗忘**：一次 `delete` 带 `ids`，全部存在才提交，否则整批不提交并指出缺失 ID；generation 只加 1。
- **更正拼接**：带 `id` 且文字有变化的 `upsert`，新文字须能切成每段至少 2 字的片段，每段逐字出现在旧记录或本次 `evidence` 中，且至少一段来自 `evidence`。不带 `id` 的新增要求 `text` 逐字取自 `evidence`。
- **遗忘证据**：`delete` 的 `evidence` 必须逐字取自当前可信原文中的明确要求。问句、状态查询、引用、条件、否定以及明显带疑问的委婉请求都不能承接旧回合的删除意图，模型需澄清后等新消息。
- **参数校验**：`tool-contract.js` 同时生成模型可见说明和运行校验，错误只报位置和正确参数，不回显正文，不静默转换 `upsert + facts`。自动 `observe` 与显式 `upsert` 的区分由工具说明和[本人 AGENTS 模板](../scripts/fusion/templates/AGENTS.md)保持一致，后端不做聊天关键词匹配。

### 可信来源与会话生命周期

- `reply_dispatch` 只接受实际本人私聊的可信 `RawBody`（`inbound.js` 的 `trustedMemoryText()`）。原文超过 2000 字符、时间偏差超过 5 分钟或以 `/` 开头的消息，不注入也不授权写入记忆。
- `before_prompt_build` 核对 Agent、workspace、会话、sender/channel/account、实际 run 和短期授权后注入；工具调用再绑定真实 toolCallId。写入许可从收到原文起最多 5 分钟，插件与应用层各自复核；`agent_end`、`before_reset`、`session_end` 使其立即失效。
- 宿主 reset 保留 `sessionId`，推进 `lifecycleRevision`；用后者区分重开的会话轮次。

### 宿主压缩

生产用宿主默认压缩模式，无摘要质量守卫；压缩钩子没有可信发送者或 run，不能授权写入记忆。

### 主动唤醒（N3，生产未启用）

助手可围绕近期聊天、有效记忆、自身兴趣和真实公开资料，决定是否查询、维护自身记录、发言或保持安静。一次机会没有发言配额或未回复禁言。代码归属见[文档21](21_后端职责分层与代码整理.md#宿主控制与自主行动)。

1. 调度器按墙钟 slot 触发，先经本人账号的前台工作准入，再取得独立后台会话准入。前台正在处理或来了新消息时，后台让出。同一时刻只跑一个机会，跨进程由 SQLite 租约保证。
2. 公共 SDK 生成独立后台 sessionId，绑定本人身份、策略版本、当前记忆 generation、明确的工具集合和唯一 QQ 路由，签发进程内持有的凭据。参数里的 runId、owner、trigger 不能签发凭据。
3. 模型按上下文自主行动。工具调用及最终派发复核运行绑定、策略、代际和租约。深夜活动条件在 `notify` 和平台派发前核对。
4. 只有显式 `notify` 才会外发。最终文本是内部 JSON 的 done/silent，不会自动发 QQ。

[宿主时钟](21_后端职责分层与代码整理.md#宿主调度)只安排未来边界。停机或忙碌期间错过的 slot 跳过，暂停时不调用模型，恢复从新的边界继续。

**上下文**：宿主装配的四份人格文件加迁移说明版 `MEMORY.md`；当前 P2 的有效事实和未过期摘要（[只读投影](21_后端职责分层与代码整理.md#共享代码的唯一实现)，受 `maxContextChars` 限制）；最近 8 段、每段不超过 1000 字符、6 小时过期的聊天投影（仅内存）；自身记录最近 12 条；四类领域的简短目录；时间与本人最后活动。每个机会使用新的 sessionId，不续接上一次历史。

主动机会持有 main 的 `agent:main:kurumi-proactive:<owner>` 会话授权，每次模型回合使用该命名空间中的独立临时会话。宿主人格和 `KURUMI_PROACTIVE_CONTEXT` 分别装配和计预算；`contextInjection` 缺省为 always。人格、前台权限和会话名均不签发后台授权，后台不能使用本人日志工具。

后台 `query` 可读天气、行程、一次性提醒和提醒列表，不收路径、SQL、命令或收件人，也不写缓存或迁移。自身记录（interest/experience/intention）每条 1–1200 字符、期限 1–90 天、最多 200 条有效；到期后不自动注入，本人仍可管理。自身记录独立于人格和本人记忆，不经 `kurumi_memory` 写入。

`remember` 要求 1–8 个本回合实际已见且未过期的 sourceId，来源表保留种类、结果哈希和时效；失败来源只证明尝试失败，不证明取得事实。后台更新/遗忘、本人更正/删除都绑定真实 ID/version；删除清正文与来源，保留无正文版本墓碑。旧 generation 的记录不自动注入，本人可明确更正确认。来源可核对不证明推论正确或兴趣长期稳定。

**抢占与投递**：本人的真实私聊入站先撤销后台，再处理附件和模型。成员、群聊、合成或重复入站不算本人活动。新消息、pause、记录更正、reset/end、权限或配置变化、停机都会撤销在途运行。`/new` 清空本功能的短期投影，保留有效自身记录和暂停状态；P2 遗忘使 generation 变化，旧投影不再注入。同一 slot 不重跑，同一调用 ID 不重发。只有拿到平台 messageId 才记 delivered，其余记 unknown 并保留，不自动补发，不据此禁言。

缺失、未来、陈旧或乱序时间不能伪造刷新或回拨活动时钟。深夜新鲜活动只提供联系的必要条件，不要求开口，也不由助手自身探索推断本人在线；停机先撤销并等待模型、工具及已启动投递收束，再关库。

**启用方式与回退**：启用需本人审核参数，并在 `runtime.config.json` 增加 `proactive` 配置、给 main 登记 `kurumi_proactive`、为本人账号授予四个权限点，然后同步并重启，且先做匹配的恢复点，备份规则见[文档12](12_目录资产与Git备份整理.md)，权限见[文档24](24_统一身份与权限管理.md)。回退先 pause 并撤销用途、关闭组件再重启，保留库和回执。

## 限制与已知问题

- 主动唤醒的配置、工具权限、数据库和定时器均未在生产启用。
- 遗忘移除记忆事实和近期摘要，原聊天文本仍可能被当前会话引用；`/new` 可移出旧上下文，历史遮罩归[文档29](29_记忆系统.md)。
- 生产使用本文的 P2 记忆，[文档29](29_记忆系统.md)的新版尚未启用。
- 既有会话、记忆和业务数据中的历史原文保留；历史上下文仍可能影响当前称谓和自我介绍。
