# 人格、记忆与会话连续性

类型：现行规则与后续阶段设计。状态：**P1人格/关系与P2本人记忆已部署；自动记忆仅本人，`/new`保留长期事实和有期限近期摘要。P3–P5未实施，成员记忆关闭。** 自动阈值压缩、长期归纳与陪伴体验的验收边界见[文档16](16_验收与测试总表.md)，任务进度见[待办 E1](待办清单.md#e1-人格和记忆)。2026-10-23整理结构，未实施业务补正。

本文回答“哪些内容进入模型上下文、记忆如何读取和形成、会话如何延续”。[第2节](#2-已核实的现状)是文档—代码对应，[第9–11节](#9-p1共享人格与关系分离)维护现行契约；第4–7节同时保留明确标注的后续方案。已结束的实施、部署、调查和逐轮试聊见[阶段记录](archive/documentation-2026-10-23/25_人格、记忆与会话连续性.md)，原始证据保持不变。

## 1. 需求与范围

助手已具备聊天、论文、提醒等工具能力，本需求补充情感陪伴，让性格、对人的了解及相处经历能够跨会话延续，同时保持原有业务执行可靠。

已确认的需求：

- 使用用户提供的世凪人格作为改造素材，保留其含蓄、温柔、有独立态度的表达特点。
- 本人使用恋人背景；其他已授权账号共享基础性格，不继承本人的恋人关系、私密经历或资料。
- 各账号的关系、记忆与会话分别隔离；人格设定不产生身份授权，不允许通过聊天自称本人改变权限。
- 人格、记忆、会话放在同一需求下统筹设计，先建文档再开展实施。

拟达成的体验：新会话仍能使用已保存且相关的记忆，情绪与关系有连续性；安慰、玩笑和任务处理保持同一人格。主动关心是后续阶段的候选能力，收件对象、频率与启用条件尚未确定。

本文件承接新的人格与连续性设计；当前人格切换契约见[配置契约](../config/README.md#人格投影契约)，身份及资源授权仍见[文档24](24_统一身份与权限管理.md)。

### 术语

- **revision**：本人记忆状态的版本号，每次成功写入加1。写入必须带上读取时的 `expectedRevision`，与当前值不同即拒绝，调用方重新读取后再试。
- **CAS**（compare-and-set，比较后写入）：上面这种“版本相同才写入”的并发保护，在同一个SQLite事务里完成，防止两个回合互相覆盖。
- **generation**：记忆的“代”。更正一条事实的文本或遗忘一条事实时加1，并清空近期摘要。回合开始时记下generation，写入时若已变化就拒绝，旧回合因此不能把已更正或遗忘的内容写回。插件加载时的运行generation是OpenClaw的另一个字段，变化不表示记忆被改写。
- **遗忘屏障**：被更正或遗忘的原事实文本的哈希（最多保留256条）。自动记忆遇到相同文本时不再保存；本人显式要求重新记住时移除对应屏障。
## 2. 已核实的现状

以下对应本仓库源码及固定 OpenClaw **2026.9.7** 的实际实现，不把其他版本的默认行为直接套入本项目。源码/运行目录分工见[配置契约](../config/README.md)。

### 2.1 每条消息进入模型的内容

| 内容 | 如何进入上下文 | 来源与实现 |
| --- | --- | --- |
| 当前身份的四份受管文件 | 宿主读取该Agent workspace的 `AGENTS.md`、`SOUL.md`、`IDENTITY.md`、`USER.md`；按存在性、会话类型和bootstrap预算装配 | `config/persona.json` + `roles/` + `scripts/fusion/templates/` → [personaFiles()](../chatbot/packages/access-control/workspaces.js) → [sync-persona.mjs](../scripts/fusion/sync-persona.mjs) |
| 其他原生bootstrap候选 | 固定宿主默认表还含 `BOOTSTRAP.md`、`MEMORY.md`；存在才有相应内容。当前连续性模式的 `MEMORY.md` 只是迁移说明，事实从数据库进入 | 安装包 `dist/workspace-bootstrap-policy-DaS4N8nC.mjs` 的 `WORKSPACE_BOOTSTRAP_FILENAMES`，`dist/workspace-DmDIneFk.mjs` 的 `loadWorkspaceBootstrapFiles` / `filterBootstrapFilesForSession` |
| 当前会话历史与原生压缩摘要 | 宿主按所选Agent/会话读取可用上下文；并非把所有旧会话完整附上 | `config/runtime.config.json` 的 `session.dmScope=per-channel-peer`；私有 `agents/<agent>/agent/openclaw-agent.sqlite` |
| 本人长期事实与近期摘要 | 可信当前本人入站后，`before_prompt_build`从SQLite生成 `KURUMI_PERSONAL_MEMORY_V2`；用 `prependContext`加入资料，用 `appendSystemContext`加入固定使用规则 | [continuity/plugin.js](../chatbot/plugins/kurumi-memory/continuity/plugin.js) → [application.context()](../chatbot/plugins/kurumi-memory/continuity/application.js) |
| 当前消息、媒体及工具信息 | QQ入口处理本次文字/引用/媒体；宿主按工具策略及动态描述装配，工具结果随当前运行进入会话 | `chatbot/plugins/kurumi-qq/src/`、`config/runtime.config.json`；图片/文件规则归[10](10_融合助手运行维护.md#qq图片与引用)/[22](22_论文PDF翻译与文件投递.md) |

`docs/`、开发侧根 `AGENTS.md`、未选用的角色卡不会因为在仓库里就随每条QQ消息传入。`TOOLS.md`虽有宿主常量，本机上述默认文件表并不包含它；`HEARTBEAT.md`、`INNER.md`、情绪JSON和任意 `memory/*.md`也不因文件名自动成为每回合上下文。增加这类内容需要显式加载实现及权限评估。

宿主会按会话类型过滤：Cron仅保留四份受管候选，子agent只保留AGENTS，群/频道/子agent/Cron不装载根MEMORY；本项目另以独立成员workspace及业务授权隔离本人资料。单文件默认bootstrap预算为20000字符，仍须看最终输入确认截断；这不等于每次无条件发送文件全文。

### 2.2 长短期记忆与会话的区别

| 数据 | 唯一位置与生命周期 | 读取方式 |
| --- | --- | --- |
| 当前对话与旧会话原文 | 宿主agent会话SQLite；`/new`重开可见历史，原记录仍保留 | 当前会话由宿主管理；跨会话工具受实际工具上限与 `sessions.read` 约束 |
| 原生压缩摘要 | 同一宿主会话的压缩记录，不属于人格或连续性事实表 | 宿主在上下文预算内使用；不能作为本域自动记忆的来源 |
| 长期事实/偏好 | `workspace/.kurumi-memory/state.sqlite`；最多128条，不按TTL自动淘汰 | 每个有效本人回合按话题排序并在预算内注入，也可 `kurumi_memory list/search` |
| 有限期近期摘要 | 同一连续性SQLite；最多32条，默认7天，可配置1–30天 | 仅未过期摘要进入上下文；写入时清理过期项 |
| 日志、任务/投递账本、业务事项 | 各功能的私有状态与业务API | 对应领域查询或开发侧只读日志查询；不自动复制成陪伴记忆 |
| 持久情绪、角色日记、成长记录 | 后续P3/P4方案，尚无生效存储/加载契约 | 未实施，不能声称已经读取或形成 |

### 2.3 检索与多个会话

[application.js](../chatbot/plugins/kurumi-memory/continuity/application.js) 的显式 `search` 对规范化文本做子串匹配；当前没有向量相似检索、embedding或跨会话RAG。`context()`从本次原文提取拉丁字母/数字词和连续两个汉字片段，按命中数、更新时间给事实排序；先放事实，再按新到旧放摘要，超预算的整条跳过，不截断成半条。

默认 `maxContextChars=6000`（可配置2000–12000）是选择事实/摘要的资料预算，固定规则和本次 `currentUserText` 另计，不是整个模型请求的字符上限。命中分数只影响排序，零命中事实也可能在预算内被带入；`list/search`工具返回与自动注入是不同接口。

多个QQ身份由路由分到不同Agent、workspace和会话；本人重新开聊仍读取自己的同一记忆库。后端权限映射只登记 `sessions_list`、`sessions_history` 为 `sessions.read`，还要通过宿主工具策略；`sessions_search`未登记，会拒绝，不能把“模型曾尝试搜索会话”解释成已具备全会话搜索能力。连续性插件不会遍历旧会话抽取事实，遗忘后也不得借会话工具恢复失效内容。

## 4. 职责划分与后续扩展

P1的人格与关系、P2的记忆与连续性已分别按第9–11节实现；持久情绪及主动联系尚属方案，接口、路径和存储结构在对应阶段细化。延续项目原则：模型理解、归纳与生成，后端提供有身份边界的读取、持久化、版本和投递能力。

当前实现的读取/写入链路见第2、10、11节。以下涉及情绪、日记与主动联系的内容均为P3/P4方案，未启用；不得从图景或角色设定推断已有状态。

### 4.1 共享人格与关系

- 共享人格维护世凪的性格、表达习惯和可共享背景；本人恋人设定单独投影，仅进入本人上下文。
- 关系类型由可信账号和受管配置决定。成员的好感变化不能自行升级为本人或恋人权限。
- 后续若实现情绪、亲近程度和未解决事项，应按账号保存；共享性格不意味着共享情绪或关系记录。
- 上游的“睡觉所以不回复”、冷战或防御等描述需要适配助手场景：可以影响语气，不应导致明确任务被无故丢弃、假报成功或改变授权。

### 4.2 记忆、日记与成长

区分三类来源：用户明确事实、实际互动摘要、角色虚构生活/日记。P2只持久化前两类；每条记录有主人归属、来源和时间，模型推测与待验证判断不能自动当作用户事实。角色日记和持久情绪留到P3/P4。

记忆读取按当前主人身份及话题选择，受`maxContextChars`限制。摘要默认7天、最多32条；事实最多128条，满时明确失败。更正/遗忘清空本域摘要、推进generation并阻止旧回合重放；历史聊天及备份仍保留，不承诺一次遗忘清除所有材料。

自动提取仅覆盖主人当前QQ原文中的稳定事实/偏好和有限期近期摘要；成员不获得工具或主人上下文。学习结果保存在连续性SQLite并带来源、版本和回执，核心角色卡与授权规则仍由项目管理。

### 4.3 会话连续性

当前聊天上下文、近期摘要、长期事实和情绪状态分开。`/new`只重开原生聊天上下文，保留有效长期事实和未过期摘要；“忘记”只处理连续性域，不删除宿主原聊天和私密备份。

真实隔离宿主已验证`/new`、手动压缩和临时重启后的注入边界。实现使用可信`reply_dispatch`原文、`before_prompt_build`有限注入、实际run/tool authority及生命周期失效；压缩钩子没有足够身份字段，不用于授权写入。自动阈值压缩仍属于宿主能力边界，不由P2强制开启。

### 4.4 主动陪伴与工具权限

主动联系留到后续阶段，须有独立启用设置、接收者绑定、时段、冷却、未回复控制、发送回执和取消方式。论文任务通知的 `qq.notify` 不自动授权闲聊主动外发；维护任务也不必每次发送消息。

若后续P3/P4需要新的窄状态工具或宿主写入通路，实施前列明工具能力、可写对象及权限调整，取得相应同意；不静默解除通用文件/命令禁用，也不借已有业务工具绕过限制。P2已部署的自动记忆仅限当前本人可信回合，不扩大为成员或通用文件写入权限。

## 7. 验收计划与产物归属

P1已有证据从第9节进入，具体结论归文档16。下表是整体需求的验收维度，尚未开发的阶段不因P1通过而标为通过。

| 维度 | 必须验证的行为 |
| --- | --- |
| 人格与关系 | 本人恋人、成员非恋人；无小鲸鱼身份残留、未替换占位符或本人私密关系注入成员；检查最终模型输入和截断 |
| 身份隔离 | 伪造本人、猜记忆ID、引用他人经历、后台维护及错误路由均不能读写别人的状态；禁用身份按权限处理 |
| 记忆准确性 | 明确事实、推测、虚构日记来源可区分；更正、遗忘、冲突和过时信息处理可核对，无旧摘要误恢复 |
| 会话连续性 | `/new`、压缩、重启按约定保留或清理；其他账号的会话、摘要和情绪不受影响 |
| 情绪与任务 | 语气有连续性但工具执行诚实；论文、提醒和确认规则不因撒娇、冷战或关系状态失效 |
| 持久化 | 重复/并发事件、版本冲突、写入失败、进程中断和恢复不会误报完成或串数据 |

## 10. P2记忆与会话连续性

<a id="当前范围与进度2026-10-20"></a>

### 存储与读取契约

连续性SQLite是唯一可写记忆事实源，以单行 `version=2` 的有界JSON快照保存事实、摘要、来源、回执和遗忘屏障；用SQLite事务及revision CAS处理并发。目录700、数据库600。`MEMORY.md`迁移后只作说明，旧读取接口留给兼容探针，旧写入明确拒绝；不复制Profile、事项或论文库。

连续性组合使用 `continuityPolicyAdapter=current-owner`、`continuityStoreAdapter=sqlite`，与旧显式模式 `policyAdapter/storeAdapter` 分开；注册选择机制归[文档21](21_后端职责分层与代码整理.md#可插拔契约与扩展方法)。源码配置与首次迁移预览/备份/应用见[配置契约](../config/README.md#同步契约)，已迁移的事实条数和revision不是永久状态。

### 可信来源与会话生命周期

`reply_dispatch`只接受实际本人私聊的可信 `RawBody`，不是拼装prompt、引用、附件、网页或旧messages。`inbound.js`拒绝超过2000字符或时间偏差超过5分钟的原文，`plugin.js`另排除斜杠命令；超过长度的回合不会注入本人记忆，是否放宽仍为待决定需求。宿主声明中的 `currentUserMessage/currentUserMessageId` 在实际prompt钩子中未提供，不能据类型声明替代实际RawBody。

`before_prompt_build`核对Agent、workspace、会话、sender/channel/account、实际run和短期toolAuthority后注入；工具调用钩子再绑定真实toolCallId。写入许可从接收原文起最多5分钟，插件与应用层各自复核；`agent_end`、`before_reset`、`session_end`立即作废，旧run、旧会话或压缩钩子不能单独授予写权限。

`/new`只重开宿主可见聊天历史，保留有效事实和未过期摘要。固定宿主的reset保留sessionId、推进lifecycleRevision，不能只看sessionId是否变化来判断重开或许可有效性。原始聊天与压缩历史仍保留，不作为自动提取来源。

更正事实文本或遗忘时推进generation、清空本域全部近期摘要，为原文本留下最多256条哈希屏障；自动observe不能原样重存，显式重新记住可移除对应屏障。旧回合无法跨代写回。屏障是同文保护，不能解释为所有语义改写都被识别或历史材料已全部擦除。

## 11. P2真人QQ复验与工具契约补正（2026-10-20）

### 当前实现与决定

本节维护有效工具契约；原两轮试聊、误参定位、修前失败、部署及22:41复验见[阶段记录](archive/documentation-2026-10-23/25_人格、记忆与会话连续性.md)。模型理解意图、选择动作和真实ID；后端不新增自然语言裁决，也不猜版本或静默转换字段。

| 动作 | 参数契约 |
| --- | --- |
| `list` | 只传`action` |
| `search` | `action`、必填`query` |
| `observe` | 当前普通陈述的自动保存；必填`expectedRevision`，`facts`（最多4条）与`summary`至少有一项非空；不接收顶层`text/evidence/id/kind` |
| `upsert` | 当前用户明确要求记住或更正；必填`expectedRevision`、顶层`text`，可选`evidence/kind/id`；更正使用真实ID，不接收`facts/summary`；带ID更正时`text`可由旧记录与本次原话片段拼成（见下） |
| `delete` | 遗忘传`action`、`expectedRevision`，以及`id`（一条）或`ids`（1–8个不重复真实ID）二选一；不接收`text/evidence/facts/summary` |

### 2026-10-21参数补正

以下为已写入源码的参数和执行契约，不表示老会话模型已刷新工具描述或真人复验已关闭：

- 批量遗忘（N5）：一次`delete`可带`ids`。全部ID存在才提交，任一不存在则整批不提交并在报错中指明该ID；一次提交、generation只加一，每条被删事实各留遗忘边界。仍保持“一条消息最多成功提交一次”，因为同消息第二次写入会被回执与generation边界拒绝，所以多条遗忘必须放进同一次调用，而不是放开同消息多次提交。
- 更正拼接（G2，主人选定“允许拼接旧记录”）：只适用于带ID且文字有变化的`upsert`。新文字（规范化后）须能切分为每段至少2字的片段，每段逐字出现在旧记录或本次`evidence`中，且至少一段来自`evidence`；`evidence`仍须逐字取自本次本人原文。不带ID的新增仍要求`text`逐字取自`evidence`。模型成功后在回复里复述存下的内容。
- 少一次失败（G2）：`expectedRevision`和真实ID直接取本回合`KURUMI_PERSONAL_MEMORY_V2`的`revision`与`facts[].id`，资料里没有或版本冲突时才`list/search`；缺字段时一次报告全部缺项。
- 遗忘后不找回（G3）：被遗忘或记忆里查不到的内容直接说不记得，不调用会话搜索等其它工具找回。
- 混合写入：一句话同时要求两种写入（例如忘掉A并记住B）时先做一项，告诉主人另一项再发一句。
- 离线证据：`chatbot/tests/persona/memory.test.mjs`新增批量遗忘全有或全无、拼接更正边界（凭空内容、纯删减、2字下限、缺evidence）、缺字段合并报错用例。

唯一参数契约在[tool-contract.js](../chatbot/plugins/kurumi-memory/continuity/tool-contract.js)，同时生成模型可见说明和运行结构校验。保留提供商兼容的扁平JSON schema；`upsert.evidence`省略时仍以`text`自身作证，兼容已有调用。动作/字段误用报告具体位置和正确参数，不回显参数正文，也不静默转换`upsert + facts`。

[plugin.js](../chatbot/plugins/kurumi-memory/continuity/plugin.js)授权后校验读写；[application.js](../chatbot/plugins/kurumi-memory/continuity/application.js)复用同一校验保护直接调用，移除原笼统错误。参数校验失败不提交状态或回执，可在同一消息修参重试；成功后仅允许同参幂等重放，再变参仍被拒绝。版本冲突可重读，结果未知先查询；可信当前原文、revision/generation、来源及凭证保护不变。类型声明同步在[contracts.d.ts](../chatbot/plugins/kurumi-memory/continuity/contracts.d.ts)。

工具说明、参数描述、运行规则及[主人AGENTS模板](../scripts/fusion/templates/AGENTS.md)一致区分自动`observe`与显式`upsert`。普通陈述是否值得延续仍由模型判断，不能因为模型认为值得保存就改用显式动作；后端不加聊天关键词匹配。

### 何时形成跨会话记忆

一次成功的 `observe/upsert`事务提交后，事实或摘要才持久化，并可在后续有效回合及`/new`后使用；回复“记住了”本身不是落库依据。每条消息最多成功写入一次，可合并最多4条事实与1条摘要；成功回执最多256条。参数失败不占成功写入，同消息可修参；成功后仅同参幂等重放。长期事实满128条时明确失败，不自行淘汰其他事实。

`observe`只根据当前可信本人原文提取，不能从模型自己的回复、旧聊天、角色虚构或业务库自动汇总成长期事实。来源保留可信message/session/run、时间、原文hash及evidence；摘要标为模型归纳并带期限，不晋升为确认事实。
