# 人格、记忆与会话连续性

让助手的性格、对主人的了解和相处语境跨会话延续，同时不影响工具执行的可靠性。本文管人格来源、本人记忆的现行规则、`/new` 连续性和主动唤醒。新版记忆系统（记录、检索、迁移）见[文档29](29_记忆系统.md)，身份与权限见[文档24](24_统一身份与权限管理.md)。

## 功能

- **人格**：共享角色“世凪”，含蓄、温柔、有自己的态度。主人使用平等恋人关系，成员使用普通朋友关系。关系、记忆、会话按账号隔离，人格设定不产生任何权限，聊天中自称本人不改变身份。
- **统一表达**：通知与日常聊天用同一人格。称呼和语气由人格决定，数字等关键事实以业务给出的为准。表达层的技术职责见[文档21](21_后端职责分层与代码整理.md)。
- **响应习惯**：遇到需要查询或操作的请求，倾向先自然应一声；处理较久时说明在做什么；遇到问题时说明困难和打算，后续行动与说法一致。措辞由模型按语境决定，不要求每次都加前缀，任务进度不写成长期记忆。
- **本人长期记忆**：可信的主人私聊中，模型自行判断哪些普通陈述值得记住，也可按主人明确要求记住、更正、遗忘。只有主人有这套记忆，成员没有。
- **`/new` 连续性**：`/new` 只重开可见聊天历史，保留有效的长期事实和未过期的近期摘要。
- **主动唤醒（N3）**：固定周期给助手一次“自己决定是否开口”的机会，只对主人，只读探索。**生产未启用**，见下文。

不做的事：

- 不做持久情绪、角色日记、自动成长，也不做成员长期记忆。
- 人格表现（冷战、“睡觉”等）只影响语气，不能导致丢弃明确任务、假报成功或改变授权。
- 不编造共同历史、纪念日、当前线下经历和真实天气；被问到身份、工具和事实时诚实回答。

## 原理

### 人格投影

- SOUL、IDENTITY 对所有账号相同；关系段按可信角色投影到各自的 `USER.md`。本人资料不进入成员文件。
- 角色背景不锁定随日期失效的学籍信息，不预置告白日期、学长关系等共同历史。
- 投影只改四份受管文件，不改身份矩阵、模型、工具权限、会话历史、MEMORY 或数据库。宿主每回合重新核对 bootstrap 文件，所以只改人格文件时同步即可，无需重启。配置或路由变更按[文档24](24_统一身份与权限管理.md)执行。

### 每次消息进入模型的内容

| 内容 | 来源 |
| --- | --- |
| 四份受管人格文件 | 宿主读取该 Agent workspace，按会话类型和 bootstrap 预算装配。投影入口见[文档24](24_统一身份与权限管理.md#代码入口) |
| 当前会话历史与宿主压缩摘要 | 宿主按所选 Agent/会话读取，不附带旧会话全文 |
| 本人长期事实与近期摘要 | 可信本人入站后，`before_prompt_build` 从 SQLite 生成 `KURUMI_PERSONAL_MEMORY_V2`，资料用 `prependContext`，固定使用规则用 `appendSystemContext`（`continuity/plugin.js`、`continuity/application.js`） |
| 当前消息、媒体、工具信息 | QQ 入口处理，规则见[文档9](9_QQ融合助手架构与开发计划.md)、[文档22](22_论文PDF翻译与文件投递.md) |

仓库 `docs/`、根 `AGENTS.md`、未选用的角色卡、`INNER.md`、`HEARTBEAT.md`、任意 `memory/*.md` 都不会随消息传入。根 `MEMORY.md` 迁移后只是说明文字，事实从数据库进入。宿主对群聊、子 agent、Cron 会裁剪 bootstrap 文件，本项目另以独立成员 workspace 隔离本人资料。

### 记忆存储与检索

| 数据 | 位置与限制 |
| --- | --- |
| 当前对话与旧会话原文 | 宿主 agent 会话 SQLite；`/new` 后原记录仍保留 |
| 宿主压缩摘要 | 属于宿主会话，不是自动记忆的来源 |
| 长期事实/偏好 | 连续性 SQLite，最多 128 条，不按时间淘汰；满后写入明确失败，不自行淘汰 |
| 近期摘要 | 同一库，最多 32 条，默认 7 天；只有未过期的进入上下文 |
| 日志、任务账本、业务事项 | 各功能自己的库，不复制成陪伴记忆 |

- **单一事实源**：连续性 SQLite 是唯一可写来源，以单行 `version=2` 的有界 JSON 快照存事实、摘要、来源、回执和遗忘屏障，用事务加 revision 比较写入处理并发。
- **注入**：`context()` 从本次原文提取拉丁词/数字和连续两个汉字片段，按命中数、更新时间给事实排序，先放事实再按新到旧放摘要，超预算的整条跳过。`maxContextChars` 只限制资料部分，零命中事实也可能在预算内带入。
- **检索**：`search` 是规范化文本的子串匹配，没有向量检索或跨会话 RAG。
- **会话工具**：`sessions_list`、`sessions_history` 登记为 `sessions.read`，`sessions_search` 未登记会被拒绝。连续性插件不遍历旧会话抽取事实，被遗忘后也不借会话工具找回。

### 写入、更正与遗忘

- **谁决定**：模型判断普通话语是否值得记，调用受限工具。后端只校验来源、结构、版本和事务，不从回复末尾自动抓取，也没有 `agent_end` 后的后台归纳。敏感凭据拒绝。
- **术语**：revision 是状态版本号，写入须带读取时的 `expectedRevision`，不同即拒绝；generation 在更正文本或遗忘时加 1 并清空近期摘要，旧回合因此不能写回；遗忘屏障保存被更正/遗忘文本的哈希（最多 256 条），自动记忆遇到同文不再保存，主人显式要求重新记住时移除。屏障只是同文保护，不识别语义改写。
- **来源**：`observe` 只取当前可信本人原文，不从模型回复、旧聊天、角色虚构或业务库汇总。摘要标为模型归纳并带期限，不晋升为确认事实。
- **一条消息最多成功写一次**：可合并最多 4 条事实和 1 条摘要，成功回执最多 256 条。参数校验失败不占名额，可同消息修参重试；成功后只允许同参幂等重放。
- **批量遗忘**：一次 `delete` 带 `ids`，全部存在才提交，否则整批不提交并指出缺失 ID；generation 只加 1。
- **更正拼接**：带 `id` 且文字有变化的 `upsert`，新文字须能切成每段至少 2 字的片段，每段逐字出现在旧记录或本次 `evidence` 中，且至少一段来自 `evidence`。不带 `id` 的新增要求 `text` 逐字取自 `evidence`。
- **遗忘证据**：`delete` 的 `evidence` 必须逐字取自当前可信原文中的明确要求。问句、状态查询、引用、条件、否定以及明显带疑问的委婉请求都不能承接旧回合的删除意图，模型需澄清后等新消息。
- **一次成功**：`expectedRevision` 和真实 ID 取本回合注入资料里的 `revision` 与 `facts[].id`，缺失或冲突时才 `list/search`。一句话同时要求两种写入时，先做一项，另一项请主人再发一句。遗忘后被问到，直接说不记得。
- **参数校验**：`tool-contract.js` 同时生成模型可见说明和运行校验，错误只报位置和正确参数，不回显正文，不静默转换 `upsert + facts`。自动 `observe` 与显式 `upsert` 的区分由工具说明和[主人 AGENTS 模板](../scripts/fusion/templates/AGENTS.md)保持一致，后端不做聊天关键词匹配。

### 可信来源与会话生命周期

- `reply_dispatch` 只接受实际本人私聊的可信 `RawBody`（`inbound.js` 的 `trustedMemoryText()`）。原文超过 2000 字符、时间偏差超过 5 分钟或以 `/` 开头的消息，不注入也不授权写入记忆。
- `before_prompt_build` 核对 Agent、workspace、会话、sender/channel/account、实际 run 和短期授权后注入；工具调用再绑定真实 toolCallId。写入许可从收到原文起最多 5 分钟，插件与应用层各自复核；`agent_end`、`before_reset`、`session_end` 使其立即失效。
- `/new` 保留有效事实和未过期摘要。宿主 reset 保留 sessionId、推进 lifecycleRevision，所以不能只看 sessionId 是否变化判断是否重开。

### 宿主压缩

未显式选择压缩模式，所以实际为 default，没有摘要质量守卫。`memoryFlush` 显式关闭。safeguard 的隔离试验中，质量守卫耗尽取消后超阈值回合持续无回复，因此维持 default。压缩钩子拿不到当前 sender/run/授权，不用于记忆写入授权。隔离宿主入口 `chatbot/tests/persona/compaction-host.mjs` 仅使用本地确定性模型，运行前先读脚本头部注释。

### 主动唤醒（N3，生产未启用）

固定周期给助手一次“机会”：它自己决定查询、维护自身记录、发言、追问或保持安静。周期不是发言配额，没有次数上限、冷却或未回复禁言。代码在现有 QQ 插件内（`chatbot/plugins/kurumi-qq/proactive/`）和共享包 `chatbot/packages/proactive-core/`，不新增服务，不用 OpenClaw Cron，不改原生 heartbeat。

选题可来自近期聊天、有效记忆、已知兴趣和真实接触的公开资料，不要求预先交办任务。自身兴趣可暂时与主人话题无关，不强制分享，不把它记成主人偏好或已交办事项；不预定偏爱哪个技能、查询次数或评分公式，重复查询不证明有用，也不更新模型权重。提出工具缺口不等于已获准使用。

**一次机会的流程**

1. 调度器按墙钟 slot 触发，先经主人前台工作准入，再取得独立后台会话准入。前台正在处理或来了新消息时，后台让出。同一时刻只跑一个机会，跨进程由 SQLite 租约保证。
2. 公共 SDK 生成独立后台 sessionId，绑定主人、策略版本、当前记忆 generation、明确的工具集合和唯一 QQ 路由，签发进程内持有的凭据。参数里的 runId、owner、trigger 不能签发凭据。
3. 模型按上下文自主行动。工具调用及最终派发复核运行绑定、策略、代际和租约。深夜活动条件在 `notify` 和平台派发前核对。
4. 只有显式 `notify` 才会外发。最终文本是内部 JSON 的 done/silent，不会自动发 QQ。

**参数**（示例值，待生产审核）

| 参数 | 示例 |
| --- | --- |
| `enabled` / `notifyEnabled` | 均 false |
| `intervalMs` | 1800000（30 分钟）；允许 1 分钟到 1 天 |
| `timeoutMs` | 60000；允许 1–120 秒 |
| `night` | 23:00–08:00（Asia/Shanghai）；15 分钟内有可信主人活动才允许深夜外发 |
| `reads` / `publicSearch` | weather、planning、reminders、reminder_list；公开检索 true |

[宿主时钟](21_后端职责分层与代码整理.md#宿主调度)只安排未来边界。停机或忙碌期间错过的 slot 跳过，暂停时不调用模型，恢复从新的边界继续。

**上下文**：宿主装配的四份人格文件加迁移说明版 `MEMORY.md`；当前 P2 的有效事实和未过期摘要（[只读投影](21_后端职责分层与代码整理.md#共享代码的唯一实现)，受 `maxContextChars` 限制）；最近 8 段、每段不超过 1000 字符、6 小时过期的聊天投影（仅内存）；自身记录最近 12 条；四类领域的简短目录；时间与主人最后活动。每个机会使用新的 sessionId，不续接上一次历史。

实际用 main 与 `agent:main:kurumi-proactive:<owner>`，不是 Cron/子 agent。宿主人格 bootstrap 与 `KURUMI_PROACTIVE_CONTEXT` 分别装配，后者不是整个 prompt；当前 `contextInjection` 缺省 always，人格预算与 P2/自身记录投影预算分开。人格文本和会话形状均不能签发后台授权。

**工具 `kurumi_proactive`**

| 调用方 / 动作 | 权限点 | 作用 |
| --- | --- | --- |
| 后台 `query` / `sources` / `remember` / `forget` | `proactive.use` | 查四类只读领域；查看本回合实际 Search/Fetch 来源；维护自身记录（interest/experience/intention） |
| 后台 `notify` | `proactive.notify` | 1–2000 字符正文，固定发主人私聊，一次调用对应一条平台请求 |
| 主人 `status` / `records` | `proactive.read` | 查看调度状态；分页查看自身记录（每页 50 条） |
| 主人 `pause` / `resume` / `record_put` / `record_remove` | `proactive.manage` | 暂停/恢复（跨重启保留）；更正或删除自身记录 |

后台只读 query 的 kind 固定，不接收路径、SQL、命令或收件人；领域读取不写缓存、不迁移（`chatbot/packages/personal-domains/src/read-only.ts`）。自身记录每条 1–1200 字符、期限 1–90 天、最多 200 条有效，到期只停止自动注入，主人仍可查看、更正、删除。自身记录与主人事实、人格、权限分开，不用 `kurumi_memory` 写自我归纳，也不是任务队列。

`remember` 要求 1–8 个本回合实际已见且未过期的 sourceId，来源表保留种类、结果哈希和时效；失败来源只证明尝试失败，不证明取得事实。后台更新/遗忘、主人更正/删除都绑定真实 ID/version；删除清正文与来源，保留无正文版本墓碑。旧 generation 的记录不自动注入，主人可明确更正确认。来源可核对不证明推论正确或兴趣长期稳定。

**抢占与投递**：主人真实私聊入站先撤销后台，再处理附件和模型。成员、群聊、合成或重复入站不算主人活动。新消息、pause、记录更正、reset/end、权限或配置变化、停机都会撤销在途运行。`/new` 清空本功能的短期投影，保留有效自身记录和暂停状态；P2 遗忘使 generation 变化，旧投影不再注入。同一 slot 不重跑，同一调用 ID 不重发。只有拿到平台 messageId 才记 delivered，其余记 unknown 并保留，不自动补发，不据此禁言。

缺失、未来、陈旧或乱序时间不能伪造刷新或回拨活动时钟。深夜新鲜活动只提供联系的必要条件，不要求开口，也不由助手自身探索推断主人在线；停机先撤销并等待模型、工具及已启动投递收束，再关库。

**启用方式与回退**：启用需主人审核参数，并在 `runtime.config.json` 增加 `proactive` 配置、给 main 登记 `kurumi_proactive`、给主人身份授予四个权限点，然后同步并重启，且先做匹配的恢复点，备份规则见[文档12](12_目录资产与Git备份整理.md)，权限见[文档24](24_统一身份与权限管理.md)。回退先 pause 并撤销用途、关闭组件再重启，保留库和回执。

## 限制与已知问题

- **主动唤醒生产未启用**：`runtime.config.json` 没有 `proactive` 配置，main 没有 `kurumi_proactive`，身份未授予四个权限点，生产未创建 N3 库和定时器。示例的 30 分钟、60 秒、深夜窗口都是待审核参数。已登记的 Fusion 恢复点覆盖当前未启用形态。启用时还需核对启用配置和新增 N3 状态的采集、隔离恢复。真实模型与真实 QQ 下的话题质量、自然度、成本和长期习惯待验。
- **N3 的隔离验证用的是合成模型和合成 OneBot 对端**，只证明数据流和安全边界。后台读取的前台权限不会自动批准后台用途，主人日志工具也不授予后台读取权限。
- 持久情绪（P3）、日记与自动成长（P4）、成员长期记忆未开放，没有存储和加载契约。
- 输入原文超过 2000 字符的回合不注入本人记忆，是否放宽未决定。
- 遗忘只移除有效事实和近期摘要。原会话文本仍可能进入上下文，“遗忘后问句回合从历史复述”未关闭，历史遮罩由文档29统一实现。`/new` 可移出旧上下文，但不等于遮罩。
- 一句话忘多条时，模型是否仍拆成单条调用，真人环境下待复验；后端已支持 `ids`。
- 压缩：生产首次真实自动阈值压缩未观察；摘要质量、长期归纳质量、成员拒绝和陪伴体感都没有验收，真人 QQ 首次保存曾因漏填版本自动修参，不是零误参。
- 新版记忆（文档29）生产未迁移，本文记忆规则仍是现行规则。
