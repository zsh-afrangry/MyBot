# 配置来源、同步与备份恢复

本轮（第五步）把"只存在于运行目录里的配置"变成"有明确 Git 入口的配置"，并把备份与恢复
从一次性手工操作变成可重复执行的脚本。

## 一句话结论

**仓库是意图，运行目录是事实与私密状态。** 改行为改仓库再同步；改密钥只改运行目录。
两者不互相复制，也不会互相覆盖。

## 目录分工

| 位置 | 内容 | 进 Git | 权威性 |
|---|---|---|---|
| `config/runtime.config.json` | 运行配置权威副本：模型、agent、插件、频道、工具策略、日志 | ✅ | 意图方 |
| `config/README.md` | 同步契约与"改配置的正确姿势" | ✅ | — |
| `roles/` | 角色卡（人格来源） | ✅ | 意图方 |
| `scripts/fusion/` | 部署、同步、备份、恢复、自检 | ✅ | — |
| `docs/` | 运维与历史说明 | ✅ | — |
| `.openclaw-fusion/runtime-env.json` | 凭据平面（API Key、网关 token、代理） | ❌ | 事实方 |
| `.openclaw-fusion/{http,ws}-token` | SnowLuma 会话令牌 | ❌ | 事实方 |
| `.openclaw-fusion/state/`、`channel/`、`agents/` | 记忆、提醒、天气、Profile、行程、会话、账本 | ❌ | 事实方 |
| `.openclaw-fusion/plugins/` | 受控第三方插件安装（自带锁文件，可重建） | ❌ | 可重建 |

`runtime.config.json` 中**没有任何真实凭据**。它只通过两种引用指向运行目录：
`${OPENCLAW_GATEWAY_TOKEN}` / `${QWEATHER_API_HOST}` 这类由 `run-gateway.mjs` 从
`runtime-env.json` 展开的变量，以及 `{"source":"env","id":"DEEPSEEK_API_KEY"}` 这类
由 OpenClaw 运行时按名字解析的 SecretRef。写入前后都用真实密钥值做过泄漏比对。

## 新增脚本

### `sync-config.mjs` — 配置同步

```bash
node scripts/fusion/sync-config.mjs            # --check（默认）：只报告漂移，漂移时退出码 1
node scripts/fusion/sync-config.mjs --diff     # 逐项显示差异，并列运行态独有键
node scripts/fusion/sync-config.mjs --apply    # 把仓库意图合并进运行配置
```

保证：

1. **只写 `openclaw.json`**。不打开、不移动、不删除 `state/`、`channel/`、`agents/`、
   `workspace/`、`media/` 或任何数据库与 JSONL，因此不可能覆盖记忆、提醒或聊天历史。
2. **保留运行态独有键**。`--apply` 是合并而非替换：仓库里有的键覆盖过去，只有 OpenClaw
   自己写进去的键原样保留并列出，让漂移可见。
3. **写入前先备份**为 `openclaw.json.bak.<时间戳>`（mode 600）。
4. `--check` 返回非零码，可直接接进启停脚本或自检。

### `backup-state.mjs` — 一致性备份

```bash
node scripts/fusion/backup-state.mjs --label pre-change
```

输出 `/home/afrangry/kurumi-backups/<时间戳>-<label>/`：

| 子目录 | 内容 |
|---|---|
| `git/` | 三个仓库的全部分支与标签 bundle |
| `patches/` | 未提交改动，避免"备份看起来完整其实丢了工作区" |
| `config/` | 运行配置、凭据平面、受控插件锁文件、systemd 单元 |
| `state/` | 每个运行数据库的**一致性快照**，以及频道/agent 的 JSON 状态 |
| `meta/` | git 状态、服务状态、版本、体积 |
| `MANIFEST.sha256` | 全量校验 |

数据库用 `VACUUM INTO` 而非文件复制：运行中的库处于 WAL 模式，直接复制可能拿到撕裂快照；
`VACUUM INTO` 读取单个一致事务，因此**不需要停服**。

### `restore-verify.mjs` — 恢复演练

```bash
node scripts/fusion/restore-verify.mjs --backup /home/afrangry/kurumi-backups/<dir>
```

校验清单：备份内全部文件哈希 → 每个 bundle 有效且可克隆 → 未提交补丁可重新应用 →
每个数据库快照 `integrity_check` 与 `foreign_key_check` 通过。

**刻意保持惰性**：不启动网关、不连 SnowLuma、不发 QQ 消息、不启动提醒调度器
（避免恢复副本造成重复投递）。只读备份，只写 `--target`（默认临时目录）。

### `verify-dependencies.mjs` — 依赖自检

见 `config/README.md`。检查仓库内无依赖软链逃逸进归档树、各包依赖与锁文件一致（按
os/cpu/libc 正确跳过他平台可选依赖）、SDK 与受控插件版本正确。

## 与第四步的关系

第四步解除了对旧 `/home/afrangry/.openclaw` 的依赖：148 个符号链接改为真实安装、
Tavily 插件移入 `.openclaw-fusion/plugins` 受控位置、迁移脚本改为显式
`KURUMI_LEGACY_SOURCE`（无隐式默认）。第五步在此之上把配置本身纳入版本管理。
两步共同的效果是：**运行、部署、自检三条流程都不再需要旧目录存在**，并且
"只改了运行文件、忘了记进 Git"这种情况会被 `sync-config.mjs --check` 直接抓出来。

## 日常操作

```bash
cd /home/afrangry/kurumi-fusion

# 改配置的标准流程
$EDITOR config/runtime.config.json
node scripts/fusion/sync-config.mjs --diff     # 看会改什么
node scripts/fusion/sync-config.mjs --apply
systemctl --user restart kurumi-fusion.service
node scripts/fusion/health.mjs

# 改人格
$EDITOR roles/小鲸鱼.md
node scripts/fusion/sync-persona.mjs --apply
systemctl --user restart kurumi-fusion.service

# 改动前留检查点
node scripts/fusion/backup-state.mjs --label before-<变更名>

# 三项自检（都应通过）
node scripts/fusion/verify-dependencies.mjs
node scripts/fusion/sync-config.mjs
node scripts/fusion/health.mjs
```
