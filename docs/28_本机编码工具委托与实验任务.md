# 本机编码工具委托与电脑管理

## 功能

### 编码委托

主人可通过 QQ 把编码或实验交给本机后端。Git 项目使用独立工作树，登记的无 Git 目录使用私有副本。任务在后台运行，完成、失败或权限阻塞时主动回传。合入 Git 或回写目录需单独确认。

项目和目标明确且主人要求执行时才创建任务。主人可以用日常语言查询、续接或取消。助手按项目、简短任务标题和时间查找任务，存在多个候选时先澄清。回报说明实际改动、产物所在目录、提交与检查结果，查找产物时先核对对应任务工作树。

### 电脑管理

主人可查询端口、内存、进程、服务和目录，也可在登记的可写根内创建、读取、编辑、复制、移动、改名及删除普通文件。简单操作如 `touch test.txt` 可直接执行。改后缀只改文件名。遇到重名时保留现有文件，覆盖或批量删除前列明影响并取得明确指令。受管论文通过业务工具改名，见[文档22](22_论文PDF翻译与文件投递.md)。

## 接口

### `kurumi_code`

编码插件位于 `chatbot/plugins/kurumi-coding/`。动作权限见[文档24](24_统一身份与权限管理.md#权限)。

| action | 作用 |
| --- | --- |
| `list` | 列出启用的后端、登记的项目及本会话任务，返回可用的短标题与创建时间 |
| `archive` | 聚合任务档案：标识、状态、逐轮改动/检查/投递与合入信息；不带 taskId 列出本人全部历史任务（跨会话只读） |
| `status`、`result`、`diff` | 查状态、执行结果和代码差异 |
| `start`、`continue` | 启动后台任务或在本轮结束后续接原会话，运行中不排队 |
| `cancel`、`rollback` | 取消指定任务，或保存失败快照并将已停任务退回最近的验证提交 |
| `reconcile` | 核对中断的任务 |
| `preview`、`merge` | 验证并冻结候选，主人确认后本地合入或回写目录 |

`start` 接收登记项目 ID、任务文本和可选的简短标题、后端。标题只描述目标。默认使用 `dsh-acp`，也可明确请求已启用的 `codex-app-server`。续接沿用任务所绑定的后端。项目路径、命令和启动参数来自操作者配置。

配置位于 `config/runtime.config.json` 的 `plugins.entries.kurumi-coding.config`。

| 键 | 用途 |
| --- | --- |
| `pilot` | 必须为 `true` |
| `root`、`worktrees` | 执行围栏内的私有状态与工作树目录 |
| `dsh.command`、`dsh.home`、`dsh.model` | DSH 可执行文件、既有认证来源和两项模型标识。认证只读加载 |
| `codex.command`、`codex.model` | 可选的 Codex 可执行文件与模型。专用认证和线程状态位于 `<root>/backend/codex-home` |
| `projects[]` | 可留空。项目项含 `id`、`root`、`kind`（`git` 或 `directory`）、Git 分支与 `checks[]`。检查含 `name`、`argv`，可选 `skipExitCode` 和 `timeoutMs` |
| `writeBoundary.root`、`writeBoundary.launcher` | 编码可写根与执行围栏程序 |

项目和原生终端的额外可写根由操作者登记，也可走代办再同步。见[主人代办白名单](24_统一身份与权限管理.md#主人代办白名单)。旧 `kurumi_task` 的 `codeEnabled=false`，只支持论文研究及已有任务的查询和取消。

### 执行结果与完成回传

- 每次启动或续接有独立的 `executionRoundId`，关联实际外部会话、工具输出、后端报告和宿主检查。续接建立新的检查与投递状态，旧结果按原轮次读取。
- `result` 用 `roundId`、`section` 和 `offset`/`limit` 查询。默认 `execution` 返回实际执行输出，`agent_report` 返回后端报告供参考。后续页沿用 `roundId` 和 `nextOffset`。结果只保留可展示的文本，工具文本按不可信资料处理。采集启用前的轮次可能缺少执行结果。
- 私有 SQLite 保存原始事件。查询拼接文本后遮蔽常见凭据形态，再分页。公共日志只留关联、状态和私有记录位置。
- 深入查询和主动回传均读取持久化的同轮结果。查询不启动模型或检查，也不补发通知。回传由后台使用原会话人格生成并复核实际请求者权限。通知头部由插件自拼任务短 ID 与标题，生成正文不要求回显任务编号。生成失败记为 `generation_failed`。相同任务、轮次和状态的已受理、发送中或结果未知的投递不自动重发。
- 启动、续接、状态和执行结果可返回 `feedback`，显示该轮的宿主检查、合入或回写、通知状态。迟到的 QQ 回执归原执行轮次。配置 `plugins.entries.kurumi-coding.config.feedbackActions` 可独立启用 `coding.start`、`coding.continue`、`coding.complete` 和 `coding.delivery`，默认都启用。

### 主人原生exec

- 主人通过 `main` 原生 `exec` 同步执行。生产 `mode=full`，默认及单条上限均为 60 秒。身份与 `host.exec` 授权见[文档24](24_统一身份与权限管理.md#权限)。
- `plugins.entries.kurumi-host-control.config.exec` 定义默认 `workdir`、`timeoutSeconds` 和 `writeBoundary`。主写入根 `root` 是试点目录，默认在其 `source` 下执行。`additionalRoots` 额外登记 `/home/afrangry/下载` 和 `/home/afrangry/文档`。`workdir` 须是真实的根内目录，`title` 最长 120 字符。
- 拒绝远端 node、`elevated`、PTY、后台执行、覆盖环境和未知参数。配置变更见[同步契约](../config/README.md#同步契约)。

## 原理

### 工作树、检查与合入

- Git 任务从登记分支的已提交 SHA 创建独立分支和工作树，与源仓库共用对象库。源工作区的暂存、未暂存和未跟踪内容留在原处。
- 宿主停止本轮执行进程后运行操作者登记的检查。检查通过且前后内容一致，才创建验证提交。`skipExitCode` 表示该项不适用，所有检查均不适用时没有验证提交。未完成和失败改动保存在私有快照中。
- `preview` 整合目标最新提交，验证并冻结任务提交、目标基线、候选、差异与检查结果。取得 `coding` 域的确认后，`merge` 重验权限、目标、候选和当时登记的检查，再串行执行 `git merge --ff-only`。变化、冲突、复验失败或会覆盖原工作区的文件均阻止合入。合入检查另记 `mergeChecks`；`ready` 表示等待审阅，尚未合入或回写。确认规则见[文档6](6_二次确认.md)。
- 任务绑定原请求者和会话。执行动作复核当时的权限、项目登记、真实目录、仓库归属和任务提交。档案查询放宽为本人可读全部历史，写动作维持原绑定。代办变更待同步时，阻止新建、续接、回退及合入或回写。项目撤销或换路径后仍可查原任务历史，旧候选和授权失效。同名项目重新登记也不能续接旧任务。

### 无 Git 目录回写

- 原目录在登记根内，仅含普通文件和目录，不含符号链接、特殊文件或嵌套 Git，且不属于另一 Git 仓库。宿主在私有副本建立 Git 基线，记录完整内容与权限，包括匹配 `.gitignore` 的文件。
- 预览冻结逐文件增改删及内容指纹。原目录在确认后仍与基线一致时才回写并记为 `written_back`。空目录保留，文件和目录不能互换。
- 写入前私下保存日志和原件，移开并核对原件后排他创建目标。失败时只还原能匹配本次操作的路径。无法证明完整还原时记为 `needs_reconciliation`，重启只核对事实。回写不保证多个路径同时生效。

### 执行围栏

- `workdir` 只决定起始目录。Linux Landlock 限制普通文件写入，默认拒绝登记根之外的写入。根须为现存的真实目录，不能是 `/`、相互重叠或包含围栏程序。根失效或围栏不可用时拒绝执行。程序版本和树指纹见 `config/exec-fence-release.json`。
- DSH、登记检查和宿主 Git 写操作受试点根围栏限制，包含任务工作树和登记源目录。试点 Git 仓库须有独立 `.git` 目录，无远端或子模块，也不能和其他登记项目重叠。试点内保存运行用的 `DSH_HOME`、临时目录和任务状态。原生终端的额外可写根对编码后端无效。
- DSH 通过 ACP 保存外部会话，Codex 通过 app-server 保存线程和轮次。Codex 启动前运行原生沙箱探针，外层写入限制仅允许当前任务工作树和专用状态目录。开始模型回合前还会核对工作目录、禁用命令网络访问的原生写入策略和审批设置。
- 后端额外权限请求一律拒绝并记 `needs_permission`。私有权限日志保存原件、决定及对应任务、轮次和 RPC。公共日志与回传只留计数、已知范围和关联。
- 原生终端由宿主核验身份和权限，通过清理环境且不加载启动脚本的 Bash 执行，使用试点内的 HOME 和临时目录。准入日志记录决定、范围和会话关联。

### 中断与链路查询

- 任务保存进程启动时刻与进程组等身份。重启把未决任务标为 `needs_reconciliation`。`reconcile` 确认执行已停止后保存快照并标为 `interrupted`，此后可以明确要求续接。`cancel` 只停止能证明归属的任务进程。
- 合入中断时核对冻结候选与实际目标。已合入则登记事实，未合入则重新预览，事实不明时维持待核对。单次接口超时不会启动新轮次，后端不可用时报告原因。
- QQ 请求、可信宿主 session/run/toolCallId、任务与实际后端会话相互关联。编码事件用 `source=coding` 查询。终端全文、请求原件和私有会话不进入公共链路日志。见[文档18](18_跨模块链路日志查询.md)。

## 限制与已知问题

- 生产仅启用 DSH，登记的项目只有合成试点 `dsh-pilot`，源目录为 `/home/afrangry/.local/share/kurumi-coding-pilot-20261029/source`。Codex 适配器生产未启用。本机 Codex CLI `0.147.0` 的原生沙箱无法初始化用户命名空间，探针会在启动模型回合前拒绝执行。

- 普通文件围栏报告 `partial`。它限制写入，不能作为读取、网络、进程或元数据的完整隔离。额外可写目录内的覆盖和批量删除目前靠对话约定。提权、系统软件安装及桌面接管均未开放。
