# 本机编码工具委托与电脑管理

主人通过 QQ 委托本机编码和项目实验，也可执行主机诊断与普通文件操作。编码委托和电脑管理各有权限、执行入口和验收范围。

## 功能

### 编码委托

- Git 项目在任务工作树中执行。生产只登记合成项目 `dsh-pilot`（源目录 `/home/afrangry/.local/share/kurumi-coding-pilot-20261029/source`）。登记的无 Git 目录在私有副本中执行，确认后回写。
- 项目和目标明确、主人要求执行且在授权范围内时才创建任务。主人可用日常语言查询、补充或取消；助手自行找回唯一任务，指代不清时用项目或任务内容澄清，无需主人提供工具名、动作名或编号。
- 任务在后台运行，QQ 仍可聊天。完成、失败或权限阻塞时由任务服务主动回报，无需主人追问或建立 Cron 轮询。
- 回报应说清实际改动或结论、任务目录与产物、基准与任务提交、执行和检查结果、未运行的检查及下一步。查产物先核对任务工作树。

### 电脑管理

- 主人可查询端口、内存、进程、服务和目录，按实际终端输出回答。
- 普通文件读写、改名、移动、复制、删除和目录维护使用原生 `exec`。在登记的可写根内，创建文件、普通编辑和整理可以直接执行；改后缀不转换格式。
- 重名保留现有文件。批量或递归删除、覆盖既有文件前列明影响并取得明确指令。运行目录中的受管文件由业务工具维护，论文改名见[文档22](22_论文PDF翻译与文件投递.md)。

## 接口

### `kurumi_code`

插件 `chatbot/plugins/kurumi-coding/`。动作权限见[文档24](24_统一身份与权限管理.md#权限)。

| action | 作用 |
| --- | --- |
| `list` | 列出已启用后端、已登记项目（`git` 或 `directory`）和本会话任务，返回可用的短标题和创建时间 |
| `status`、`result`、`diff` | 任务状态、执行结果、代码差异 |
| `start`、`continue` | 启动任务；当前轮次结束后续接原会话，运行中不排队 |
| `cancel`、`rollback` | 取消该任务；保存失败快照并将已停任务退回最近的验证提交 |
| `reconcile` | 核对因重启中断的任务 |
| `preview`、`merge` | 冻结候选；主人确认后本地合入或回写目录 |

工具只接受登记项目 ID、任务文本、启动时可选的简短标题和后端，以及任务/轮次/分区/分页参数。标题用于澄清任务指代。启动默认 `dsh-acp`；明确选择的后端必须已启用，续接沿用任务绑定的后端。

配置在 `config/runtime.config.json` 的 `plugins.entries.kurumi-coding.config`：

| 键 | 含义 |
| --- | --- |
| `pilot` | 必须为 `true` |
| `root`、`worktrees` | 任务私有状态与工作树目录，位于试点目录内 |
| `dsh.command`、`dsh.home`、`dsh.model` | DSH 可执行文件；既有认证的来源（只读加载，不复制凭据）；两项模型标识 |
| `codex.command`、`codex.model` | 可选，生产未启用；操作者登记 Codex 可执行文件和可选模型，专用认证与线程状态放在 `<root>/backend/codex-home` |
| `projects[]` | `id`、`root`、`branch`、`kind`、`checks[]`（`name`、`argv`、可选 `skipExitCode`、`timeoutMs`） |
| `writeBoundary.root`、`writeBoundary.launcher` | 可写根与 Landlock runner |

项目名单可以为空。项目和原生 `exec` 的额外可写目录由操作者维护，或走[主人代办白名单](24_统一身份与权限管理.md#主人代办白名单)后由操作者同步。

旧 `kurumi_task` 的 `codeEnabled=false`：拒绝新编码任务，只保留论文研究和已有任务的查询/取消。

### 执行结果与完成回传

- 每次 `start/continue` 分配独立 `executionRoundId`，关联任务、外部会话、实际工具结果、执行工具报告和宿主检查。续接时清空上一轮的当前检查与投递状态，历史按原轮次查询。
- `result` 用任务、`roundId`、`section`、`offset`/`limit` 查询。`execution`（默认）返回后端实际命令输出，`agent_report` 返回编码程序最后一份报告，只作参考。后续页沿用 `roundId` 和 `nextOffset`。思考、文件正文、原始参数和非文本附件不进入接口；工具文本是不可信资料。
- 分页前先拼接原文再遮蔽常见凭据形态，避免切片后漏检；形态脱敏不证明识别所有敏感内容。原始事件保存在任务私有 SQLite，公共链路日志只记录关联和状态。采集功能启用前的旧轮次返回结果缺失，不虚构 stdout。
- 完成、失败、权限阻塞时，任务服务在独立的后台作用域把同轮持久结果交共享模型说明入口，沿用原会话人格并复核原请求者权限，不继承前台回合的工具授权。生成失败记录 `generation_failed`，不发固定文案。相同任务、轮次和状态的已受理、发送中或未知投递不自动重发。

### 主人原生exec

- 入口为 `main` 的原生 `exec`，身份和 `host.exec` 规则见[文档24](24_统一身份与权限管理.md#权限)。命令在 gateway 同步运行，`mode=full`，生产单条默认 60 秒，最多 60 秒。
- `plugins.entries.kurumi-host-control.config.exec` 登记默认 `workdir`（试点的 `source`）、宿主 `timeoutSeconds` 及 `writeBoundary` 的 `root`（试点根）、`additionalRoots`（`/home/afrangry/下载`、`/home/afrangry/文档`）、`launcher`。`workdir` 只接受这些根内的真实目录；`title` 是最长 120 字符的展示文本。
- 远端 node、`elevated`、PTY、后台运行、覆盖环境和未知参数均拒绝。

## 原理

### 工作树、检查与合入

- Git 任务取登记源分支在创建时的已提交 SHA 为基线，每个任务有独立分支、worktree 和外部会话。源目录的暂存、未暂存和未跟踪文件不进入任务，也不被自动清理或提交。worktree 共用对象库。系统写入边界是已登记的整个试点根，包含源目录和任务工作树。
- 执行后先停止本轮执行进程，再运行操作者登记的检查，核对检查前后内容一致，才由宿主生成最小单元的任务提交。失败或未完成改动保存到任务私有 `tasks/<ID>/snapshots/`，不混入正式提交，不降低检查标准换取通过。
- 检查返回登记的 `skipExitCode` 只表示不适用，所有检查都不适用时不得形成验证提交。试点 Python 检查 `chatbot/scripts/check-coding-pilot-python.py` 只证明指定排序产物的原地排序行为，不证明任意 Python 任务。
- `preview` 先整合目标最新提交并验证候选，冻结任务提交、候选、目标基线、差异与检查结果。主人通过[二次确认](6_二次确认.md)的 `coding` 域确认后，`merge` 再按届时登记的检查复验同一候选，才通过 `git merge --ff-only` 在本地合入。
- 合入前重验权限、项目、目标 HEAD/分支、候选和工作区内容。目标或候选变化需重新预览和确认；配置或内容在检查中变化、检查失败、冲突以及会被覆盖的未提交/未跟踪/忽略文件均阻止合入。对同一目标的最终合入串行处理。
- 任务绑定原请求者和会话。经白名单代办调整或移除项目，待同步时即阻止该项目新建、续接、回退和合入/回写；同步后旧登记的状态和历史结果仍可查，旧候选和授权失效。重新登记同名项目不能续接旧任务。
- 可执行的任务复核当前权限、项目登记、真实目录、仓库归属、任务分支和提交。旧 `policyHash` 不作准入凭据。
- 合入复验单列为 `mergeChecks` 并关联候选，不改写旧轮次的 `checks` 或执行结果。只读查询不运行检查、不启动模型、不补发通知。

### 无 Git 目录回写

- 原目录须在批准根内，只含普通文件和目录，无符号链接、特殊文件、嵌套 Git，也不在另一 Git 仓库内部。记录完整文件内容与权限基线，在任务私有副本建 Git；原目录不新增 `.git`。初始基线包含原目录被 `.gitignore` 匹配的文件。
- 预览冻结逐文件增改删计划、内容指纹和原目录基线，按当前检查验证，主人确认后回写并记 `written_back`，与 Git 项目的 `merged` 区分。原目录并行变化时保留双方并拒绝旧预览；保留空目录，不处理文件/目录类型互换。
- 写入前持久保存私有 journal 和原件，移开原件核对后排他创建新路径，不覆盖并行新建文件。失败只还原仍能匹配本次内容的路径；无法证明完整还原则 `needs_reconciliation`。重启只核对，不重放部分回写；不承诺多路径原子事务。

### 执行边界与额外权限

- 编码适配器管理自有 stdio 进程：DSH 绑定 ACP 会话，Codex 绑定 app-server 的线程和轮次。宿主保存实际外部 ID、运行登记检查和形成候选；后端结束回合不等于通过宿主检查。
- DSH、检查进程及其后代和宿主 Git 写操作通过 [Landlock 围栏](#执行围栏)执行。试点是唯一普通文件可写根，另保留 `/dev/null`；临时目录、实际 `DSH_HOME` 和私有状态位于试点内。原生 `exec` 新增目录不扩展 DSH 的授权。
- Codex 启动前必须通过原生写入沙箱探针。app-server 仅可写当前任务工作树和专用状态目录，核对生效的工作目录、原生写入范围和审批策略后才发任务；不使用桌面 Codex 的个人目录。
- 当前试点 Git 项目须有自己的 `.git` 目录，不得有远端、子模块或与其他登记项目重叠。额外权限请求全部拒绝，任务记 `needs_permission`，不向 QQ 发起等待审批、不自动换无限制模式。
- 请求原件追加到任务私有 `permission-requests.jsonl`，保存理由、任务/轮次/外部会话/工具/RPC 关联和真实决定。同连接重复 RPC 不重复计数，续接请求继续累计。公开日志和回报只给计数、范围、状态及私有记录位置；无法从结构化路径确认命令影响时标未知。
- 允许按任务需要读取项目外相关资料，不把登记项目当成全部读取白名单；私密资料不批量复制到提示词、仓库或公共日志。执行工具沿用其已有模型与认证，其他工具的 AGENTS、权限和审批机制须逐个核对。
- Git 和任务快照只恢复所含文件；Fusion 的恢复边界见[文档12](12_目录资产与Git备份整理.md)。

### 中断、取消与接续

- 运行中持久保存 PID、启动时刻、进程组/会话等身份，不能仅凭可复用的 PID 判断归属。重启把未决任务记 `needs_reconciliation`，不自动恢复、重发或重跑模型请求。
- `reconcile` 核对原进程和工作树：仍运行则保持待核对，确认停止后保存未完成快照并记 `interrupted`；后续明确 `continue` 才续接原外部会话。未知归属不自动终止。
- `cancel` 只处理有可验证启动身份和归属锚点的本任务进程树，核实停止才记 `cancelled`。PID 复用、cwd 变化或锚点不足时拒绝；不停止共享 DSH 服务或其他任务。
- 合入中断先核对冻结候选与目标。恰好已合入的只登记事实，未合入的重新预览；其余保持待核对，不补做未经新确认的合入。
- 单次接口超时不等于任务总时长耗尽，不自动重新启动。后端不可用时报告原因，不自动换后端。无输出不能证明没有进展。

### 日志与链路关联

QQ 消息、宿主 session/run/toolCallId、内部 taskId、执行后端与真实外部会话持久关联。宿主 runId 来自 `chatbot/packages/observability/tool-trace.js` 的可信调用钩子，外部 ID 来自实际执行接口，缺失时明确标缺失，不按“最近会话”猜测。

统一日志经 `trace-events` 的 `source=coding` 查询，只含请求/派发、检查/快照、确认/合入和投递的关联键、状态、耗时、错误及私有记录引用；终端全文和权限请求原件留在任务私有状态。后端允许、拒绝和主人本人确认分别记录，自动允许不能冒充主人合入或 push 授权。查询与脱敏契约见[文档18](18_跨模块链路日志查询.md)。

### 原生终端执行与审计

- 宿主核验请求方和权限，`chatbot/packages/host-exec` 重写参数，通过 `env -i` 和不加载启动文件的 Bash 执行；独立 HOME 和临时目录位于试点根。主人提示词的默认目录和可写根取自同一份配置。
- 允许或拒绝、作用范围与会话关联写入准入审计，命令正文不入审计。工具结果留在私有会话，经[文档18](18_跨模块链路日志查询.md)关联查询。

### 执行围栏

- `workdir` 只决定起始目录，Linux Landlock 围栏限制普通文件写入。可写根须为现存的真实目录，拒绝 `/`、重复、相互包含或包含 runner 的根；缺失、符号链接替换或围栏不可用时拒绝执行。
- 辅助程序由 Fusion 保存在 `.openclaw-fusion/tools/node-addon-system-linux-x64`。包名、版本与树指纹见 `config/exec-fence-release.json`；`scripts/fusion/install-exec-fence.mjs` 默认核验，`--apply` 导入已校验的包。

## 限制与已知问题

- 生产未登记真实项目或无 Git 目录。成员、群聊、后台任务和 Cron 不可调用 `kurumi_code` 或原生 `exec`。生产操作和外部写入遵守 [AGENTS.md](../AGENTS.md#需要单独授权的操作)。
- 未另设协调层任务并发、总时长、tokens、费用、GPU 或下载量硬上限，后端自己的额度、速率与接口期限仍有效。资源不足或反复同类失败时报告或暂停受影响任务，不无限重试、不终止其他任务。
- 任务工作树和快照保留，不自动清理。
- 围栏报告 `partial`：隔离用例覆盖登记根内写入，以及拒绝根外创建、覆盖、截断、删除、移动和经符号链接写入。网络、进程和元数据不在保证范围。登记根内的覆盖与批量清理确认目前依靠对话约定。
- 电脑管理当前不支持提权、系统软件安装或桌面接管。资料目录的恢复边界见[文档12](12_目录资产与Git备份整理.md#限制与已知问题)。

- [ ] 确定新增可写目录、关键路径，以及普通编辑与覆盖、批量清理的分界。`touch test.txt` 等普通操作在登记范围内直接执行；批量删除、覆盖同名目标、系统配置及服务变更等敏感操作走授权，在执行层验收普通 shell 也受这项限制。
- [ ] 受控 `sudo` 通过独立入口执行，只接受白名单内的固定动作和目标。仅 QQ `365999865` 的可信本人私聊可按[二次确认](6_二次确认.md)对冻结的动作、目标和影响授予一次性权限。首个候选是重启 `todeskd.service`，可能中断远程连接，实施前先确认范围。
- [ ] 先在隔离环境验证受控 `sudo` 的拒绝和单次执行：未确认、错误账号、候选变化、授权过期或重复消费均不执行，普通 `exec` 与编码后端均不能触发提权；实际操作获准后核对执行结果和事后状态。
