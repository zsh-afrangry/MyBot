# 本机编码工具委托与实验任务

类型：现行规则与需求范围。建立日期：2026-10-28；更新：2026-11-07。任务入口：[N23](待办清单.md#n23)；实施状态与验证边界统一见[验收总表](16_验收与测试总表.md)。结果回传见[结果修复记录](verification/coding-delegation-plan-2026-10-28/results-fix-2026-10-30/README.md)，配置升级后旧任务的兼容验证见[当前条件检查记录](verification/coding-delegation-plan-2026-10-28/policy-compatibility-2026-10-30/README.md)。

## 背景与需求来源

主人希望通过QQ把本机任务交给助手，让助手调用已有的专业编码工具，协助修改代码、维护现有仓库和开展实验。整体需求也包含项目之外的日常文件操作，以及文件读写、终端命令和主机状态分析。面向事先确定的任务目标与写入范围，执行工具应能按需自行阅读、修改、运行检查并根据结果继续迭代，不要求主人守在电脑前逐步操作。

主人已经配置好OpenCode、Claude Code和Codex，均可通过终端启动；DeepSeek Harness已运行在本机3080端口。Claude与Codex桌面端也已安装并经常使用。本需求以复用这些现有工具和配置为出发点，不以重新部署一套编码服务为前提。

主人认为这些专门工具更适合承担编码工作，因此希望OpenClaw负责QQ对话与任务协调，把实际开发委托给选定工具。这里记录的是主人的使用动机，不据此作模型能力排名。

现有QQ助手在项目初期统一禁用了若干文件与执行能力。主人已说明：这些限制会随项目发展逐步开放，不是永久禁止编码。需求与局部测试已记录；具体向QQ开放哪些能力、允许作用于哪些项目和操作，仍随实施方案明确。

## 开发范围与阶段

主人于2026-10-28确认以下需求范围。阶段安排说明开发顺序，自主程度和信息获取原则见后文；具体执行权限随接入方案落地。

| 范围 | 具体需求 | 阶段 |
| --- | --- | --- |
| 编码与实验 | 围绕指定仓库、实验目录修改代码、运行检查和实验，也能整理这些目录里的文件 | 首期 |
| 日常文件操作 | 修改项目之外的普通文件，例如给下载目录里的PDF改名、移动文件、整理资料 | 第二期；一并纳入本文设计 |
| 主机只读查询 | 按需求执行查询命令并分析真实输出，例如检查端口占用、通过`free -h`查看内存 | 首期 |

### 普通文件与受管PDF的边界

普通项目文件的重命名可以由获准的编码工具执行；论文库中的受管PDF还有稳定文档ID、目录记录、翻译任务和投递引用，不能因开放编码工具就直接修改它的运行目录。受管PDF对外名称维护作为关联需求归[论文模块](22_论文PDF翻译与文件投递.md#受管pdf重命名关联需求)和[N24](待办清单.md#n24)，不由本需求自动实现或启用。

第二期扩展到下载目录等项目外位置时，同样按文件是否由业务系统管理区分；普通PDF可以作为一般文件处理，受管论文仍通过所属模块维护。

2026-10-28核对代码确认：论文库的内部文件名按内容哈希生成，但独立记录`filename`，QQ文件发送使用该字段。“没有重命名接口”是当前缺口，不能据此解释为哈希存储不允许修改对外名称；内部文件本身改名与对外名称更新是两种操作。

## QQ入口与执行工具的职责

上述三类需求都可以沿用“把要求和必要路径交给本机执行工具”的交互方式。编码工具具备的文件与终端能力，也可用于获准的普通文件处理和主机操作。实际可执行范围仍取决于所选工具及其运行身份、权限和接口。

主人已确认由QQ/OpenClaw承担远程入口和任务协调，选定工具承担实际执行。底层接口与具体执行权限仍需明确：

| 部分 | 职责 |
| --- | --- |
| QQ/OpenClaw | 接收需求、确认必要信息、关联主人与目标目录、选择工具、维护任务与会话关联；传递补充要求、转达执行工具的提问或权限请求，并回传进展与结果 |
| 本机执行工具 | 在约定范围内理解项目或文件、读取修改、运行命令、检查结果并继续修正；给出实际输出、产物和未完成项 |

从主人的使用体验看，QQ相当于向本机工具下达任务的远程对话入口。协调层应完整传递原始需求和有效补充，避免在转述中丢失限制或改变意图。可靠使用还需要保持会话关联、等待输入、继续、取消和结果回传，不能只启动一个进程后返回“已完成”。

## 能力目标

1. **QQ是任务入口。** 主人用自然语言表达需求，不必在QQ手写终端命令、进程管理或编码工具的协议参数。
2. **本机工具实际执行。** 复用本机已配置的工具及其模型、登录和工作流，完成开发、实验及纳入范围的其他操作；助手负责传递需求、协调任务与汇报。
3. **在授权范围内自主迭代。** 阅读项目、修改文件、执行约定检查和根据失败继续修正应形成闭环；缺少关键决策、超出权限或工具确实受阻时才请求主人介入。
4. **长任务异步运行。** 启动后QQ仍可正常聊天；支持查询、补充要求、继续、取消和完成/失败回报，不能把终端窗口消失视为任务完成。
5. **结果可核对。** 汇报实际执行工具、目标目录、代码/文件或系统状态变化、检查结果和未完成项；主机查询应依据真实命令输出分析，进程退出成功不等于需求已完成。
6. **任务可以可靠关联。** QQ请求、内部任务、编码工具会话及输出应能对应；查询或继续某任务不能误接其他项目或另一个并发任务。

### 当前执行通道与试点边界

### 专用工具与任务服务

`chatbot/plugins/kurumi-coding/`提供主人专用`kurumi_code`，与旧`kurumi_task`分开。`coding-runtime/acp-client.js`只处理协议与自有进程；插件的`inbound/policy/store/workspaces/service`分别负责可信身份、值校验、持久事实及确认事务、Git/检查和任务编排。`results.js`负责选择与呈现持久结果。可信runId由宿主调用钩子提供，共享实现位于`observability/tool-trace.js`；旧KnowledgeMap导入地址保留转发。统一事件进入`trace-events`查询来源，外部会话和工具ID留在事件事实中，不写原始需求、代码和终端正文。

工具支持`list/start/status/result/continue/cancel/rollback/diff/preview/merge`。任务基线固定为登记分支已提交SHA；同一调用重试不重复启动或续接模型。检查前关闭当前执行进程，比较检查前后工作内容，再生成正式任务提交；失败改动保留私有快照。`rollback`只在已停止的任务中保存失败快照并退回该任务最近验证提交，不回退源分支。合入候选先整合目标最新提交并复验，以`coding`领域冻结预览；下一条主人消息经共享确认机制签发一次性grant后才本地合入。目标HEAD、分支、未提交/未跟踪内容或候选变化会拒绝旧预览，受影响的未跟踪/忽略文件也不得覆盖。投递未知与执行结果分开，不自动重跑任务。

[产品试点](verification/coding-delegation-plan-2026-10-28/product-pilot-2026-10-29/README.md)保存本机处理器、续接/取消、测试夹具确认和隔离宿主证据；[真人回溯](verification/coding-delegation-plan-2026-10-28/qq-review-2026-10-30/README.md)与[结果修复](verification/coding-delegation-plan-2026-10-28/results-fix-2026-10-30/README.md)保留真实QQ观察与后续分层验证。合成身份和投递器不能替代真人入站或收件，结论不跨层累计。

试点只允许无远端、无子模块的登记合成Git项目；额外ACP权限一律拒绝并报告`needs_permission`，没有实现QQ内审批等待或Auto review。正在运行时的补充不排队，须待本回合结束后续接；重启后的未决任务标为`needs_reconciliation`，不自动恢复或重跑。快照不承诺保存Git忽略的构建缓存。worktree不是OS隔离，DSH原生`workspace-write/native`不能视为对任意命令和所有副作用的完整防护。其余缺口与分层验收统一见[验收总表](16_验收与测试总表.md)。

### 单目录QQ试点授权（2026-10-30）

主人已明确同意按上述方案启用并测试真实QQ链路，当前仅开放`/home/afrangry/.local/share/kurumi-coding-pilot-20261029`。登记项目为`dsh-pilot`，源项目、独立任务工作树、检查、临时文件和私有记录均在此目录；不登记其他仓库或下载目录。原先按需读取信息的原则继续适用，既有DSH认证只通过原有加载器读取，不复制凭据，不授予其所在目录的新写权限。配置`dsh.home`只作为既有凭据来源；子进程实际`DSH_HOME`是试点的`state/backend/dsh-home`，避免启动器重写共享profile。

执行进程及其后代、项目检查命令使用显式Linux Landlock写入边界；唯一普通文件可写根为上述目录，另保留`/dev/null`设备用途。DSH自己的`workspace-write/native`限制继续生效，其默认允许的宿主`/tmp`不能因此成为新增可写目录，临时目录、后端会话/存储/附件改放试点目录。runner不可用时拒绝运行，不回退为无限制进程。当前内核的runner报告`partial`；应单独验证创建、覆盖、截断、删除、移动及符号链接越界，不将文件内容写入测试解释为网络、进程、元数据或全部系统副作用均已隔离。

提示词将编码/实验路由到`kurumi_code`；旧`kurumi_task`设`codeEnabled=false`，拒绝新编码任务且不再列出旧fusion项目，保留论文研究和旧任务查询/取消，不能用旧副本扩大本次目录授权。

所有额外ACP权限请求逐项拒绝，任务标为`needs_permission`；请求内容和理由、时间、真实任务/会话/工具/RPC关联、决定来源与结果追加至任务私有`permission-requests.jsonl`，不再覆盖最后一条。按任务保留请求次数、时间范围、类型、明确目录范围及请求模式；同连接重复RPC不重复计数，续接的新请求继续累计。命令实际影响无法由结构化路径确定时标为未知，不猜测为目录内或合理。统一链路日志和QQ只给计数、状态及私有记录位置，不转存完整命令、理由或私密参数。

主人根据申请频率和具体内容决定后续开放程度；试点不自动批准任何目录外申请。具体测试合入须审阅冻结候选后另行确认，启用授权不代替合入确认。不包含push、共享DSH启停、生产数据清理、系统安装或额外仓库写入。部署依据见[单目录试点记录](verification/coding-delegation-plan-2026-10-28/qq-pilot-2026-10-30/README.md)；真人观察与修复验证从[验收总表](16_验收与测试总表.md)进入，只有实际完成的层次才记为通过。

### 主人原生exec

执行隔离原生依赖由Fusion独立保管在`.openclaw-fusion/tools/node-addon-system-linux-x64`；批准包名、版本与完整树指纹固定于`config/exec-fence-release.json`。`install-exec-fence.mjs`默认只检查，`--apply`从完整已校验包导入，保留许可证，不修改DSH安装。依赖自检同时核对实际工件与两个配置引用；配置迁移仍走同步契约。此路径调整不改变可写目录、权限或partial隔离的适用范围。

主人于2026-10-30明确同意开放main的原生`exec`。简单目录/文件查询、端口和内存等主机只读查询由OpenClaw直接运行命令，再依据真实输出回答；不为这些查询启动DSH。编码、实验、任务续接和合入仍使用`kurumi_code`。查询任务产物时先核对任务工作树，不能把工作树中的文件说成已进入源目录。

`exec`映射到独立的owner-only权限`host.exec`。宿主先检查可信主人、频道、account、Agent与私聊会话一致，再由`packages/host-exec`重写原生执行参数。成员、后台任务、Cron、缺少可信请求者或被撤权的调用均不得取得此能力。`process`及其余禁用工具保持原限制。

原生调用固定在gateway同步执行，默认工作目录为试点`source`，可指定同一试点内的真实目录。目录外工作目录、远端node、提权、PTY、后台工具模式、模型环境变量覆盖及未知参数均拒绝。单条命令默认且最多60秒；这是简单命令的执行期限，不是DSH任务总时长上限。长开发任务走原有异步任务服务。

原生`title`是可选的显示标题，接受最长120字符的字符串。它只透传给原生工具展示，不进入命令、环境或准入审计；不能把正常显示字段误判为未知执行参数。对应参数兼容与拒绝边界见[标题兼容记录](verification/coding-delegation-plan-2026-10-28/qq-2124-title-fix-2026-10-30/README.md)。

写入边界复用`coding-runtime/write-fence.js`的Linux Landlock runner。普通文件可写根仍只有[单目录试点](#单目录qq试点授权2026-10-30)，另保留`/dev/null`设备用途。工作目录本身不构成限制；命令中的绝对路径、shell串接和子解释器仍继承实际写入边界。临时目录及独立HOME位于试点，运行目录准备也在同一边界内完成。payload通过清空继承环境的`env -i`和不加载启动文件的bash运行，避免自动继承Fusion进程中的提供商凭据。runner不可用时拒绝，不回退宿主无限制执行。

按需读取相关信息的原则继续适用，不读取或输出无关聊天与凭据。Landlock只承担已验证的普通文件写入边界；当前内核报告partial，不据此承诺网络、进程、元数据及全部系统副作用隔离。授权范围内的普通命令不逐次确认，原生`mode=full`不表示启用了Auto review，也不扩大已有业务授权。安装软件、修改受管库/权限、启停服务、代替领域确认接口合入或push仍不在这项许可中。exec可以改写试点普通文件，不能据文件可写就推断任何业务动作均已获准；这些业务限制也不能冒称由Landlock完整强制。

可信准入审计沿用`channel/access-events.jsonl`，记录`host.exec`、最终允许/拒绝、作用范围及session/run/toolCallId，不复制命令正文。实际工具返回留在原生私有会话记录，经[文档18](18_跨模块链路日志查询.md)关联查询。原生exec的准入拒绝或执行失败与DSH的ACP额外权限申请分开核对，不混入其请求次数。验证边界见[原生exec记录](verification/coding-delegation-plan-2026-10-28/owner-exec-2026-10-30/README.md)，验收状态只在文档16维护。

### 执行后端替换与低耦合

任务入口、工作区管理、检查与提交规则、合入确认、日志和QQ回传应独立于具体编码工具。DSH优先作为首期后端，后续可通过执行适配器增加OpenCode、Claude等后端；迁移可行性建立在它们能提供所需接口并通过验证的前提上。

适配器负责启动、输入补充、状态/事件、继续和取消，并报告实际支持的能力。任务持久绑定执行后端、接入通道和真实外部会话标识；缺少某项能力时应明确返回限制。更换后端适用于新任务，已有任务仍按原绑定继续；不同产品之间的历史上下文、会话ID和权限不能直接互换或宣称无缝续接。

首期只要求一个通道通过完整闭环，同时支持多个任务独立关联和并行运行。协调层暂不设置人为并发上限，资源与后端限制见[并行任务与资源管理](#并行任务与资源管理)。

## 外部软件操作的理解与范围

AI可以通过API、MCP、CLI或界面自动化等工具操作外部软件。QQ的OneBot接入与[B站插件](https://github.com/c1overzz/dsh-bili-scroll)已经提供了对应操作的例子；自主性来自任务内的决策和工具调用，账号凭证提供的是执行身份，实际能力仍由工具实现与授权范围决定。

因此可以说“在已接入并获准的动作范围内，由AI代为操作账号”，不能仅凭登录成功推断它能够接管软件全部功能。社交媒体账号管理作为未来独立需求保留，本次两期范围不包含账号代运营、B站接入或自动发布互动；也不因委托DSH自动开放它已安装插件的全部能力。

## 工作树、检查点与合入

### 基线与并行隔离

主人确定代码任务采用Git worktree方案。每个任务使用独立工作树、任务分支和执行会话，记录来源仓库、源分支、基准提交、目标分支与工作目录。基线取任务创建时指定源分支最近一次Git提交，解析并固定为提交SHA；不将主目录的已暂存、未暂存或未跟踪文件带入任务。

主目录已有改动保持原样，不通过自动暂存、提交、清理或覆盖来建立基线。其他任务分支的未合入进度也不进入该任务。主人希望多个智能体按独立模块并行开发，继续遵循插件式低耦合；跨模块公共接口、清单或锁文件等共享变更仍需在整合时检查。

Git worktree与原项目共用Git仓库和对象库，具有独立检出目录、HEAD与暂存区，并不是彼此独立的Git仓库，见[Git官方说明](https://git-scm.com/docs/git-worktree)。这里要求的是工作目录和任务分支隔离；任务提交不会自动更新目标分支，也不默认修改其他工作树。

### 恢复快照与可提交单元

自动回档由任务系统和执行工具实现。未完成或检查失败的过程改动保存为任务私有补丁/文件快照，用于恢复、继续与排查；快照不作为普通Git提交混入任务分支。不能把建立了worktree或保存了快照视为已有通过检查的开发成果。

正式本地提交至少应是通过相关测试和必要检查的最小可用单元。提交前核对本任务diff与文件范围，只提交已验证的单元；必需检查失败或无法完成时继续修正、保留过程快照或等待处理，不提交半成品。检查对象必须与提交内容对应，不能用提交前已失效的测试结果替代。

有既定测试的项目沿用其相关检查；没有测试的实验应提供可重复执行的验证命令或明确验收步骤。原有失败与本次新增失败分别报告，不能为取得通过结果而降低检查标准、跳过必需检查或删除有效测试。尚不能证明满足要求时，不把结果标为通过检查的最小单元。

失败后可在任务工作树内修正或退回本任务恢复点，不回退源分支、其他智能体分支或主人的修改。过程快照保存在任务私有的`tasks/<任务ID>/snapshots/`；长期保留和清理策略另行确定，不自动删除运行证据。运行时资料不得混入项目Git或公共日志。

### 首期待确认合入

首期流程为完成最小单元 → 必要检查通过并形成任务提交 → 生成可审阅差异和检查结果 → 等待主人确认 → 合入目标分支。任务执行完成、已确认、已合入和已推送分别记录。`git push`等远端写入始终需要主人明确同意，合入许可不包括推送。

确认应对应明确的任务提交、目标分支基线与差异。合入前重新核对目标分支，并按[当前登记的检查](#当前条件检查与旧任务兼容)复验冻结候选；多个任务对同一目标分支的最终合入需串行处理。目标已变化时先整合并验证新的候选结果；原预览失效、存在冲突或检查失败时不得套用旧确认直接合入。

合入不能覆盖目标工作区的未提交修改。目标目录尚有其他进度或无法安全更新时，保留任务成果并报告待处理原因；不擅自清空、隐藏这些进度或强行更新正在使用的分支。具体整合方式需在实施时验证。[自动合入稳定性评估](#自动合入稳定性评估)作为未完成项保留，首期按待确认流程执行。

### 无Git实验目录

主人接受在独立副本里建立临时Git。开始时记录原目录文件基线，在独立副本开展实验、检查和版本管理，原目录不原地初始化Git。

完成后向主人提供差异与检查结果，待审阅确认再将约定变更回写原目录。回写前重新核对原文件与初始基线；发生并行变化或冲突时保留双方内容并先处理冲突。回写不代表完成Git合并、推送或部署。

### 恢复范围与已有实现

Git恢复覆盖的是纳入版本管理的项目变更，过程快照补充本任务未提交文件的恢复。项目外文件、已启动进程、外部服务、系统安装和数据库等副作用需按各自操作处理，不能承诺通过Git回档一并恢复。现有OpenClaw后台项目的独立clone仍按[副本契约](9_QQ融合助手架构与开发计划.md#后台开发副本契约)运行；专用编码任务按本节执行，不把旧clone或其他工作树当作当前任务。

## 权限逐步开放

### 已确认的原则

- 需求面向主人通过QQ发起的本机编码、实验、文件和终端操作，阶段安排见[开发范围与阶段](#开发范围与阶段)。首期沿用[统一身份权限](24_统一身份与权限管理.md)的真实身份与个人能力边界；成员和群聊不随此需求自动开放。
- 主人接受随项目推进逐步解封最初统一禁用的能力。需求确认不代表已经批准所有执行权限或全部仓库；本轮另行授权的本机接口与合成项目测试见[局部记录](verification/coding-delegation-plan-2026-10-28/local-pilot-2026-10-29/README.md)，不扩大为QQ生产权限开放。
- 实施前应把拟开放的能力、项目/目录、可执行操作与风险说明清楚，再按主人决定修改受管配置、同步并记录结果。已经授权的范围内应持续工作，不重复索取同一许可。

### 日常开发与自动审批

开发目标是在已登记项目和任务范围内自主阅读、修改、安装项目依赖、更新必要锁文件、联网查资料、运行检查与实验，并启动本任务需要的临时开发服务。常规开发动作不要求主人逐次确认；涉及写入的位置包括任务工作区、明确的临时目录和所选工具必要的依赖缓存，具体可执行权限在接入方案中列明。临时服务需记录归属、端口与生命周期，不接管其他任务或生产服务。

主人提出评估编码工具自身的“Approve for me”类机制，接入优先复用后端已有审批能力。Codex的[Approve for me](https://learn.chatgpt.com/docs/permission-modes)把符合条件的审批请求交给独立审查器，继续保留工作区写入边界；本机CLI帮助中也存在`--approve-for-me`。其[自动审查规则](https://learn.chatgpt.com/docs/sandboxing/auto-review)只处理实际触发的审批，不能据此声称每个动作都经过审查。

本机DSH带有实验性Web Auto review层，默认未启用，其说明为审查后使用Full access执行，与Codex保留workspace-write边界的机制不同；它的稳定性及适用性未验证。本轮只验证了ACP原生权限回调的单次允许与拒绝，固定夹具控制器不是AI自动审查器，也未测试QQ等待审批。其他后端需分别核对，不因名称相近视为同等机制。

适配器应记录所选审批模式及真实允许、拒绝或等待结果。后端没有适用的自动审批能力时，只在已授权范围内自主执行；实际产生的额外审批请求交给主人处理，不由OpenClaw对所有弹窗统一回答同意，也不静默切换为跳过权限检查的模式。

后端自动审查不能代替本方案保留的主人决定：首期合入、无Git目录回写、push，以及另行授权的系统或生产操作。相关约束需在宿主编排与后端实际执行边界落实，不只写进提示词。自动审查拒绝时记录原因并寻找符合原范围的可行路径；无法继续时回报阻塞，不绕过拒绝。

### 信息获取与写入范围

主人要求编码工具按任务需要自行获取本机信息。读取范围不人为收窄为工作树文件或由OpenClaw预先挑选的少量资料；工具可根据实际运行身份、文件权限和审批机制，读取项目外文档、共享依赖、配置、日志或其他相关资料。项目登记限定的是任务目标和写入归属，不充当全部信息读取的目录白名单。

协调层传递原始需求、有效补充、项目与工作区标识和适用规则，由执行工具按需发现信息，不预先复制全部磁盘内容或QQ历史。`AGENTS.md`等项目说明沿用所选工具的加载规则；后端自身的系统指令、权限配置和宿主约束仍然有效，不能认为只有`AGENTS.md`决定可执行范围。

读取信息不改变写入分期或发布权限。运行目录仍按[配置同步契约](../config/README.md)维护，私密状态不复制到仓库，凭据和聊天原文不进入QQ回报、提交或统一日志。工具登录优先复用其已有认证机制，不把凭据明文注入任务提示词。读取所需内容进入执行工具的上下文，沿用该工具已配置的模型与数据通道；协调层不再批量转存相关私密内容。

### 实施时必须明确的边界

外部编码工具通常需要读取和修改项目文件、运行命令，并可能联网安装依赖、调用模型或启动开发服务。风险包括改错目录、影响现有未提交修改、读取非任务资料、执行有副作用的命令以及产生费用；仅设置工作目录或创建Git worktree并不等于操作系统隔离。

main禁用`read/write/edit/apply_patch/process/message/sessions_spawn`等能力。编码使用专用委托工具；主人已批准的原生exec遵守[独立权限及写入边界](#主人原生exec)。新增通用能力或扩大专用工具范围时，应明确指出所需项、理由及实际授予外部工具的能力，不能以换接口规避告知与授权。

权限应分别覆盖“QQ助手能发起什么”和“编码工具能在本机做什么”。OpenClaw中的工具限制不会自动约束独立进程；不得默认使用跳过所有权限检查的启动参数。

首期项目选择使用登记ID及可信路径映射，先检查目标目录与现有修改。代码任务采用上节的工作树方案；实验目录也要有明确归属。第二期项目外文件修改需明确目标路径与可写目录，具体选择和校验方式待定；模型生成的路径本身不能充当宿主授权。

`apt install sl`等软件安装已列入需求，不代表本次已授权安装软件或授予提权能力。安装、更新、卸载的允许范围、是否需要主人确认，以及如何处理宿主身份或凭据要求，需与端口、内存等查询分别确定。

本需求中的编码不自动包含`git push`、远端分支/标签修改、生产服务启停、停写备份或恢复、生产数据清理及对外消息。实际任务若需要，应按对应规则取得具体授权。任务工作树内修改、过程快照和通过检查后的最小单元提交属于目标流程；首期合入及无Git目录回写均等待主人确认。

## 并行任务与资源管理

主人希望支持多个需求同时开发，暂不为并发数量、任务总时长、模型token、费用、GPU使用或下载量另设协调层硬上限。不能默认只允许一两个任务，也不依据会话数量推断所有任务均在持续满载。任务、会话、工作区、临时服务和取消操作均应独立关联。

首期保留运行状态和必要资源观测，支持主人查询与取消。后端自身的额度、速率限制和接口超时仍实际生效，需在接入时列明。接口单次调用的超时与任务总时长分别处理，不能因一次轮询超时就宣称长任务失败或自动重跑。

资源不足、额度耗尽、反复相同失败或持续没有有效进展时，应报告实际原因，等待资源或暂停受影响任务；不无限重复请求，不终止其他会话来释放资源。无输出本身不能证明没有进展。未来如需增加资源上限，依据实际观测提出具体值，再由主人决定；不预先虚构预算数值。

## 任务交互与完成标准

主人明确要求执行、项目和目标清楚且落在已授权范围内时，直接创建任务。讨论方案、询问能力或比较工具时保持讨论。项目不明或补充内容可能对应多个任务时先澄清；已有任务的补充进入原任务和真实编码会话。

交互顺序是：理解需求和项目 → 确定工具与本次范围 → 启动并返回任务标识 → 后台执行与处理补充 → 返回可审阅结果 → 等待主人确认合入或回写。

正常执行中可按请求查询进展；只有需要主人决定、权限阻塞、失败或完成等有意义变化时主动回报，避免逐行转发终端日志。补充要求应进入正确的编码会话；工具不支持直接续接时应明确说明实际采用的方式。

任务至少需要区分排队、运行、等待输入、等待状态核对、执行完成、待确认合入/回写、已合入/回写、失败、请求取消和已取消等情况，具体是否复用现有状态模型由实现决定。继续任务应保存并使用真实会话标识，不靠“最近一个会话”猜测。

取消应作用于指定任务的后端会话及其执行进程，核实停止后才标为已取消。保留工作树、过程快照和已有产物，清理由后续保留策略处理。取消一个任务不停止共享DSH服务、QQ入口或其他任务；暂不能确认停止时，继续显示请求取消及实际状态。

服务重启或连接中断后，先利用持久任务映射核对原会话与进程，再恢复跟踪。确认仍在运行则接续观测；状态不明时等待处理，不重复启动原实验。执行工具不可用时报告原因，未经明确选择不自动更换执行后端。结果回传需区分投递失败和未知结果，重试前核对回执，避免把重复执行当成补发结果。

完成回报应说明：

- 使用了哪个工具、哪个项目和工作目录，任务/会话如何继续。
- 实际改动或实验结论、可审阅的diff或产物路径、基准与任务提交，以及是否仍在等待确认或已合入/回写。
- 运行了哪些必要检查、结果如何；未运行的检查和仍存在的问题据实保留。
- 是否完成最初需求，后续还需要主人作出什么决定。

不把编码工具的自述直接当成全部验收证据；需能核对实际文件、检查结果和任务状态。执行日志与回报不应带出凭据、无关聊天原文或其他项目资料。

### 执行结果与完成回传

每次`start/continue`分配独立的`executionRoundId`，即执行轮次。轮次持久关联任务、外部会话、实际工具结果、执行工具报告和宿主检查。续接开始时清空上一轮的当前检查与投递状态，历史结果仍按原轮次查询。`status`说明当前任务状态，`result`读取结果，`diff`提供代码差异。

`result`沿用可信主人私聊与原任务绑定，使用`tasks.read`权限。接口只接受任务、轮次、分区和分页参数，不接受任意路径。默认`section=execution`返回ACP实际执行工具的文本结果；`section=agent_report`返回最后一份执行工具报告，其来源不等同于终端执行或宿主验收。思考、专用文件读取工具的正文、工具原始参数和非文本附件不进入该结果接口。工具输出属于不可信数据，不作为新的操作指令。

默认查询当前轮次，后续页使用返回的`roundId`和`nextOffset`。分页前先拼接原始文本并遮蔽常见凭据形态，避免凭据被切片后漏检。原始选定事件保存在任务私有SQLite；公共链路日志只记录关联和状态。形态脱敏不证明能够识别所有敏感内容，执行工具仍应只输出任务所需结果。采集功能启用前未记录的执行轮次明确返回结果缺失，不从工具总结或历史状态虚构stdout。

完成、失败和权限阻塞由任务服务直接回报，发送前复核原请求者权限。完成通知读取同一轮持久结果，并附实际执行输出的末尾片段、宿主检查、变更文件和待审阅状态。较长输出通过`result`继续查询。通知正文及其哈希留在任务私有记录，平台回执单独保存。相同任务、轮次和状态的已受理、发送中或未知投递不自动重发；查询不启动模型。等待编码完成不创建通用Cron或自动任务轮询，主动查询仍通过原私聊身份执行。

宿主检查由操作者登记。当前合成试点保留Node检查，并由`chatbot/scripts/check-coding-pilot-python.py`独立检查`quicksort_first_pivot.py`的原地排序行为。检查以`python3 -B`执行，避免生成缓存改变待提交内容。产物不存在且未被Git跟踪时，登记的退出码77表示“不适用”；已跟踪产物被删、路径变为符号链接或排序错误均失败。不适用不能记成通过，所有检查均不适用时不能形成验证提交。该检查不自动证明pivot策略、任意Python需求或其他语言已验收。

### 重启与执行状态核对

运行中定期持久保存本任务的进程身份（PID、启动时刻、进程组/会话），不只保存一个可复用PID。服务重启将未决任务标为`needs_reconciliation`并保留中断前状态；`reconcile`检查原进程与工作树，不重放模型请求、不重新外发。仍运行时保持待核对；确认停止后保存未完成快照并标为`interrupted`，由后续明确`continue`续接同一外部会话。未知进程归属不自动终止或声称已停止。

`cancel`可处理重启前保存的自有执行树：只按启动身份及仍存活的归属锚点确定进程，不接收模型提供的PID；重新核对并实际停止后才标`cancelled`。PID被复用、工作目录变化或进程组缺少可验证锚点时拒绝。共享DSH Web服务及其他任务不属于取消对象。原合入中断则核对冻结候选与目标：已恰好合入的结果只登记事实，尚未合入时退回待重新预览；其他情况继续等待核对，不补做未经新确认的合入。

### 当前条件检查与旧任务兼容

不生成或比较整体策略指纹。旧记录中的`policyHash`字段仅作为历史数据保留，不参与准入；增加检查或修改后端设置本身不阻断旧任务查询，也不要求主人手动“更新策略”。任务提交、差异与确认提案的摘要继续用于固定具体内容。

查询状态、结果或差异时，复核当前读取权限、原请求者与会话绑定、项目仍登记、目录仍在允许范围，以及任务工作树仍属于该项目Git仓库。续接还须具备当前编码权限，核对工作树实际分支和提交，按当前登记的检查执行。目录被迁移、映射到另一仓库、出现符号链接或移出授权范围时，报告具体条件失败，不删除任务或改写历史结果。只读查询不重新执行检查、启动编码工具或补发通知。

预览按当前检查验证候选；主人确认后，合入前再次按届时登记的检查复验同一候选。任务提交、候选、目标基线和差异必须仍对应原确认；权限撤回、检查失败、检查期间配置或内容变化均不得消费确认或合入。检查规则更新后，可对同一未变候选按新规则重试；目标或候选改变则重新生成预览并确认。

当前合入复验结果单列为`mergeChecks`，保留检查名称、实际结果及候选关联，不把旧轮次的`checks`或执行结果改成“已通过新检查”。尚未采集的旧执行输出继续明确返回缺失。实现与分层证据见[当前条件检查记录](verification/coding-delegation-plan-2026-10-28/policy-compatibility-2026-10-30/README.md)。

## 日志与链路关联

日志属于首期必需能力，复用[链路查询的统一事件与适配器契约](18_跨模块链路日志查询.md#适配器扩展契约)和`chatbot/packages/observability/index.js`。现有调用前后钩子可在宿主工具边界关联真实runId；它们不会自动记录独立DSH进程内部的全部执行，需由任务编排与后端适配器补充事件，再接入统一查询。

至少记录以下事实，事件具体命名与落盘位置在实施时确定：

| 边界 | 必需事实 |
| --- | --- |
| 请求与派发 | 可信请求者、任务ID、项目/目标、执行后端与通道、审批模式、真实允许/拒绝/等待结果、开始/失败/等待输入/继续/取消/结束 |
| 工作区与开发 | 源分支/基准SHA、任务分支和工作区标识、快照/恢复、变更摘要、必要检查的退出状态与耗时、已验证提交 |
| 合入或回写 | 候选差异标识、目标基线、主人确认与拒绝、检查/冲突结果、实际合入提交或回写结果；推送另记授权与结果 |
| 结果投递 | 原任务与QQ回报关联、实际投递回执、失败或未知结果；不把执行成功当成送达成功 |

QQ消息、宿主session/run/toolCallId、内部taskId、执行后端与外部会话之间建立持久映射。宿主关联键取自可信调用上下文；外部会话ID由实际执行接口返回，带后端命名空间保存，不冒充OpenClaw的sessionId/runId。后续继续、重启恢复和跨来源查询优先使用任务映射，不按时间或“最近会话”猜测；缺少关联时明确记录缺失。

审批事件区分既定权限策略、后端自动审查和主人本人确认，记录动作摘要、作用目标、决定来源与结果。后端自动允许不能伪记为主人已确认合入、回写或push。

统一日志只保留允许的关联键、状态、错误码、检查摘要与私有证据引用，不复制完整终端输出、代码、聊天原文、账号Cookie或凭据。通用脱敏规则不能替代字段选择；必要原始执行记录留在任务私有资料中。日志不是授权凭据，真实任务状态、权限复核及合入确认仍由对应业务契约执行。
