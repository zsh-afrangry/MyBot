# 本机编码工具委托与实验任务

主人通过 QQ 把本机编码、实验和文件任务交给助手。QQ/OpenClaw 负责接收需求、关联项目、传递补充并回传结果；实际执行由本机工具完成。

## 功能

| 能力 | 入口 | 范围 |
| --- | --- | --- |
| 编码与实验 | 工具 `kurumi_code`，由 DSH 通过 ACP stdio 执行 | 只在操作者登记的项目内；当前只登记合成项目 `dsh-pilot`（`/home/afrangry/.local/share/kurumi-coding-pilot-20261029`） |
| 主机只读查询 | main 的原生 `exec` | 端口、内存、目录等查询，由 OpenClaw 直接运行命令并依据真实输出回答，不启动 DSH |
| 普通文件管理 | main 的原生 `exec` | 试点目录，以及已登记的 `/home/afrangry/下载`、`/home/afrangry/文档` |
| 无 Git 实验目录 | `kurumi_code`，项目 `kind=directory` | 实现与隔离验证已具备；新增目录须先登记，在私有副本里开发，确认后回写原目录 |

行为约定：

- 主人明确要求执行、项目和目标清楚且在授权范围内时直接创建任务；讨论方案、比较工具时不启动。项目不明、补充可能对应多个任务时先澄清。
- 编码与实验走 `kurumi_code`，简单查询和文件整理走原生 `exec`。查任务产物时先核对任务工作树，不把工作树里的文件说成已进入源目录。
- 任务在后台异步运行，QQ 仍可聊天；支持 `status`、补充（`continue`）、`cancel`，完成、失败、权限阻塞时由任务服务主动回报，不创建 Cron 轮询。
- 完成回报包含：使用的项目与工作目录、实际改动或结论、diff 与产物位置、基准与任务提交、检查结果、未运行的检查和遗留问题、是否等待确认。执行工具的自述不当作验收证据。
- 普通文件的读、写、删、重命名、改后缀、移动、复制和目录维护都由 `exec` 处理，不按 `ls/mv/cp/rm` 新增业务工具；改后缀不转换格式。重名默认保留原文件，整理请求不等于删除请求；批量/递归清理或覆盖既有内容，先列明影响并取得明确指令。这些意图规则由对话遵守，后端强制的只有身份、目录、环境和模式边界，不解析每条 shell 命令的语义。
- 论文库里的受管 PDF 有稳定文档 ID 和投递引用，不能用 `exec` 改运行目录；改对外名称归[文档22](22_论文PDF翻译与文件投递.md)。

不做的事：

- `git push`、远端分支/标签修改、生产服务启停、停写备份与恢复、生产数据清理、软件安装和提权，均需另行授权，不在本需求许可内。
- 成员、群聊、后台任务、Cron 不能使用 `kurumi_code` 和 `exec`。
- 账号代运营、B 站接入等社交媒体操作不在范围内。

## 接口

### `kurumi_code`

插件 `chatbot/plugins/kurumi-coding/`。权限点见[文档24](24_统一身份与权限管理.md)：读类用 `tasks.read`，其余用 `tasks.code`。

| action | 权限点 | 作用 |
| --- | --- | --- |
| `list` | `tasks.read` | 登记项目（含 `kind`：`git` 或 `directory`）与任务 |
| `status`、`result`、`diff` | `tasks.read` | 任务状态；执行结果；代码差异 |
| `start`、`continue` | `tasks.code` | 启动任务；在原会话续接（必须等本回合结束，正在运行时的补充不排队） |
| `cancel` | `tasks.code` | 停止该任务的执行进程，核实停止后才标 `cancelled` |
| `rollback` | `tasks.code` | 已停止任务保存失败快照并退回任务最近验证提交，不回退源分支 |
| `reconcile` | `tasks.code` | 重启后核对被打断的任务，不重放模型请求 |
| `preview`、`merge` | `tasks.code` | 冻结合入/回写候选；主人确认后执行本地合入或目录回写 |

工具只接受登记项目 ID、任务文本和任务/轮次/分区/分页参数，不接受路径、启动参数或 PID。

配置在 `config/runtime.config.json` 的 `plugins.entries.kurumi-coding.config`：

| 键 | 含义 |
| --- | --- |
| `pilot` | 必须为 `true` |
| `root`、`worktrees` | 任务私有状态与工作树目录，位于试点目录内 |
| `dsh.command`、`dsh.home`、`dsh.model` | DSH 可执行文件；既有认证的来源（只读加载，不复制凭据）；两项模型标识 |
| `projects[]` | `id`、`root`、`branch`、`kind`、`checks[]`（`name`、`argv`、可选 `skipExitCode`、`timeoutMs`） |
| `writeBoundary.root`、`writeBoundary.launcher` | 可写根与 Landlock runner |

旧 `kurumi_task` 的 `codeEnabled=false`：拒绝新编码任务，只保留论文研究和已有任务的查询/取消。

### 执行结果与完成回传

- 每次 `start/continue` 分配独立 `executionRoundId`，关联任务、外部会话、实际工具结果、执行工具报告和宿主检查。续接时清空上一轮的当前检查与投递状态，历史按原轮次查询。
- `result` 沿用可信主人私聊与原任务绑定，使用 `tasks.read`。参数为任务、`roundId`、`section`、`offset`/`limit`：`section=execution`（默认）返回 ACP 实际执行工具的文本结果，`section=agent_report` 返回执行工具最后一份报告（不等同于终端执行或宿主验收）。后续页用返回的 `roundId` 和 `nextOffset`。思考、文件读取正文、工具原始参数和非文本附件不进入该接口。工具输出是不可信数据。
- 分页前先拼接原文再遮蔽常见凭据形态，避免切片后漏检；形态脱敏不证明识别所有敏感内容。原始事件保存在任务私有 SQLite，公共链路日志只记录关联和状态。采集功能启用前的旧轮次返回结果缺失，不虚构 stdout。
- 完成、失败、权限阻塞时，任务服务把同轮持久结果交共享模型说明入口，沿用原会话人格并复核原请求者权限；生成失败记录 `generation_failed`，不发固定文案。相同任务、轮次和状态的已受理、发送中或未知投递不自动重发；查询不启动模型。

### 主人原生exec

- main 的 `exec` 映射到 owner-only 权限 `host.exec`。宿主先核对可信主人、频道、account、Agent 与私聊会话一致，再由 `chatbot/packages/host-exec` 重写原生执行参数。成员、后台任务、Cron、缺少可信请求者或被撤权的调用均被拒绝。
- 固定在 gateway 同步执行，`mode=full`，不启用 `elevated`。单条命令默认且最多 60 秒（`agents.entries.main.tools.exec.timeoutSeconds`）。长任务走 `kurumi_code`。
- 默认工作目录是试点 `source`，可指定已登记可写根内的真实目录。未登记根中的 workdir、远端 node、提权、PTY、后台模式、模型环境变量覆盖和未知参数均拒绝。可选 `title`（字符串，最长 120 字符）只透传展示，不进入命令、环境或审计。
- 命令通过 `env -i` 清空继承环境、不加载启动文件的 bash 运行，不继承 Fusion 进程里的提供商凭据；临时目录与独立 HOME 在试点目录内。
- 可写根配置在 `plugins.entries.kurumi-qq.config.exec.writeBoundary`：`root`（试点目录）、`additionalRoots`（当前为 `/home/afrangry/下载`、`/home/afrangry/文档`）、`launcher`。`additionalRoots` 只由操作者在受管配置登记，模型不能通过参数添加。每个根必须是现存的真实目录，拒绝 `/`、重复或相互包含的根、包含 runner 的根；缺失、被替换为符号链接或边界失效时拒绝，不静默回退为无限制。
- 主人 AGENTS 由人格同步器从同一份配置投影默认工作目录和可写根，成员提示词不含这些范围。
- 准入审计写入 `channel/access-events.jsonl`：`host.exec`、允许/拒绝、作用范围、session/run/toolCallId，不记命令正文。实际工具返回留在原生私有会话，经[文档18](18_跨模块链路日志查询.md)关联查询。原生 exec 的拒绝或失败与 DSH 的额外权限申请分开统计。
- 执行隔离原生包由 Fusion 独立保管在 `.openclaw-fusion/tools/node-addon-system-linux-x64`，批准的包名、版本和完整树指纹固定在 `config/exec-fence-release.json`；`scripts/fusion/install-exec-fence.mjs` 默认只检查，`--apply` 从已校验的包导入。

## 原理

### 工作树、检查与合入

- Git 任务取登记源分支在创建时的已提交 SHA 为基线，每个任务有独立分支、worktree 和外部会话。源目录的暂存、未暂存和未跟踪文件不进入任务，也不被自动清理或提交。worktree 共用对象库。系统写入边界是已登记的整个试点根，包含源目录和任务工作树。
- 执行后先停止本轮执行进程，再运行操作者登记的检查，核对检查前后内容一致，才由宿主生成最小单元的任务提交。失败或未完成改动保存到任务私有 `tasks/<ID>/snapshots/`，不混入正式提交，不降低检查标准换取通过。
- 检查返回登记的 `skipExitCode` 只表示不适用，所有检查都不适用时不得形成验证提交。试点 Python 检查 `chatbot/scripts/check-coding-pilot-python.py` 只证明指定排序产物的原地排序行为，不证明任意 Python 任务。
- `preview` 先整合目标最新提交并验证候选，冻结任务提交、候选、目标基线、差异与检查结果。主人通过[二次确认](6_二次确认.md)的 `coding` 域确认后，`merge` 再按届时登记的检查复验同一候选，才通过 `git merge --ff-only` 在本地合入。
- 合入前重验权限、项目、目标 HEAD/分支、候选和工作区内容。目标或候选变化需重新预览和确认；配置或内容在检查中变化、检查失败、冲突以及会被覆盖的未提交/未跟踪/忽略文件均阻止合入。对同一目标的最终合入串行处理。
- 查询和续接按当前权限、原请求者/会话、项目登记、真实目录和仓库归属校验。续接还检查任务分支和提交；项目撤销、路径迁移或符号链接替换时报告具体失败，不删除任务。旧 `policyHash` 不作准入凭据，不因整体设置变化要求重建任务。
- 合入复验单列为 `mergeChecks` 并关联候选，不改写旧轮次的 `checks` 或执行结果。只读查询不运行检查、不启动模型、不补发通知。

### 无 Git 目录回写

- 原目录须在批准根内，只含普通文件和目录，无符号链接、特殊文件、嵌套 Git，也不在另一 Git 仓库内部。记录完整文件内容与权限基线，在任务私有副本建 Git；原目录不新增 `.git`。初始基线包含原目录被 `.gitignore` 匹配的文件。
- 预览冻结逐文件增改删计划、内容指纹和原目录基线，按当前检查验证，主人确认后回写并记 `written_back`，与 Git 项目的 `merged` 区分。原目录并行变化时保留双方并拒绝旧预览；保留空目录，不处理文件/目录类型互换。
- 写入前持久保存私有 journal 和原件，移开原件核对后排他创建新路径，不覆盖并行新建文件。失败只还原仍能匹配本次内容的路径；无法证明完整还原则 `needs_reconciliation`。重启只核对，不重放部分回写；不承诺多路径原子事务。

### 执行边界与额外权限

- DSH ACP stdio 由 `chatbot/packages/coding-runtime/acp-client.js` 管自有进程和协议；插件的 `inbound/store/workspaces/service` 管可信入站、持久事实、工作区与检查、编排。执行工具完成阅读、改动和实验，宿主保存真实外部 sessionId；`end_turn` 或窗口关闭不等于需求完成。
- DSH 和检查进程及其后代都经 Linux Landlock runner，普通文件可写根仍只有试点，另保留 `/dev/null`；临时目录、实际 `DSH_HOME` 和私有状态位于试点内。原生 exec 的额外两根不扩展 DSH。runner 缺失或失效时拒绝运行。
- runner 在当前内核报告 `partial`：已验证普通文件创建、覆盖、截断、删除、移动和符号链接越界，不承诺网络、进程、元数据或全部副作用隔离。设置 workdir、`mode=full` 或 DSH 自带 `workspace-write/native` 都不能替代围栏，也不表示 Auto review 已启用。
- 当前试点 Git 项目不得有远端或子模块。额外 ACP 权限请求全部拒绝，任务记 `needs_permission`，不向 QQ 发起等待审批、不自动换无限制模式。
- 请求原件追加到任务私有 `permission-requests.jsonl`，保存理由、任务/轮次/外部会话/工具/RPC 关联和真实决定。同连接重复 RPC 不重复计数，续接请求继续累计。公开日志和回报只给计数、范围、状态及私有记录位置；无法从结构化路径确认命令影响时标未知。
- 允许按任务需要读取项目外相关资料，不把登记项目当成全部读取白名单；私密资料不批量复制到提示词、仓库或公共日志。执行工具沿用其已有模型与认证，其他工具的 AGENTS、权限和审批机制须逐个核对。
- Git 和过程快照只恢复所含文件，不能撤销进程、服务、安装、数据库或项目外文件副作用。下载/文档不自动进入 Fusion 恢复点；隔离恢复副本移除其额外写入授权，见[文档12](12_目录资产与Git备份整理.md)。

### 中断、取消与接续

- 运行中持久保存 PID、启动时刻、进程组/会话等身份，不能仅凭可复用的 PID 判断归属。重启把未决任务记 `needs_reconciliation`，不自动恢复、重发或重跑模型请求。
- `reconcile` 核对原进程和工作树：仍运行则保持待核对，确认停止后保存未完成快照并记 `interrupted`；后续明确 `continue` 才续接原外部会话。未知归属不自动终止。
- `cancel` 只处理有可验证启动身份和归属锚点的本任务进程树，核实停止才记 `cancelled`。PID 复用、cwd 变化或锚点不足时拒绝；不停止共享 DSH 服务或其他任务。
- 合入中断先核对冻结候选与目标。恰好已合入的只登记事实，未合入的重新预览；其余保持待核对，不补做未经新确认的合入。
- 单次接口超时不等于任务总时长耗尽，不自动重新启动。后端不可用时报告原因，不自动换后端。无输出不能证明没有进展。

### 日志与链路关联

QQ 消息、宿主 session/run/toolCallId、内部 taskId、执行后端与真实外部会话持久关联。宿主 runId 来自 `chatbot/packages/observability/tool-trace.js` 的可信调用钩子，外部 ID 来自实际执行接口，缺失时明确标缺失，不按“最近会话”猜测。

统一日志经 `trace-events` 的 `source=coding` 查询，只含请求/派发、检查/快照、确认/合入和投递的关联键、状态、耗时、错误及私有记录引用；终端全文和权限请求原件留在任务私有状态。后端允许、拒绝和主人本人确认分别记录，自动允许不能冒充主人合入或 push 授权。查询与脱敏契约见[文档18](18_跨模块链路日志查询.md)。

- 当前仅登记 `dsh-pilot`。Fusion、SnowLuma 和其他真实项目未接入，换目录或增加项目名不足以取得写入权限。面向真实项目的目标保护、合入、部署和恢复入口尚未完成。
- 额外权限等待、后端 Auto review、Codex/Claude 等新后端、桌面接手、系统安装与提权、自动合入均未开放；一个 ACP 通道通过不能证明其他通道可用。
- 未另设协调层任务并发、总时长、tokens、费用、GPU 或下载量硬上限，后端自己的额度、速率与接口期限仍有效。资源不足或反复同类失败时报告或暂停受影响任务，不无限重试、不终止其他任务。
- 快照与工作树的长期保留、清理策略未确定；不自动删除运行证据。通知成功、执行完成、本地合入、push 和部署分别核对。

## 进行中：真实项目与完整 QQ 闭环

- 沿 DSH 先完成主人 QQ 发起、补充、查询、结果、取消和具体候选确认，再逐项登记真实仓库或实验目录，验证目标变化、原有修改与部署/恢复保护。
- 新后端要分别提供任务、真实会话、输入、状态、续接、取消和权限接口，声明实际能力。仅新任务选择新后端，旧任务按原绑定继续，不宣称跨产品会话无缝接续。
- 日常开发目标包括任务内依赖、必要锁文件、联网和临时服务；具体可写缓存、端口及生命周期随项目登记，不接管生产。软件安装与提权另定范围。
- 额外审批优先评估后端原有能力；无适用机制时让主人处理真实请求，不统一回答同意，不绕过拒绝。自动审查不替代合入、目录回写、push 或生产操作的具体授权。
- 自动合入须另定可靠性门槛，覆盖检查、并行整合、目标变化、冲突、失败恢复与授权追溯；未通过前保持具体候选待主人确认，自动 push 不在其中。
