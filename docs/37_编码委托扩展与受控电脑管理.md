# 编码委托扩展与受控电脑管理

本文承接[文档28](28_本机编码工具委托与实验任务.md)收口后的电脑操控与编码扩展能力，按“架构面向终极形态预留、开发与放权分阶段稳步验收”推进。

## 功能

### 受控系统操作通道（阶段 1）

- 主人可在 QQ 私聊通过独立窄工具执行操作者预先登记的声明式系统运维模板，绝不接受模型传入任意命令、参数或自由 root shell。
- 首期支持模板 `service.restart`（首个候选目标 `todeskd.service`），执行前冻结操作、目标、当前状态与影响提示（说明可能短暂断开远程连接），经主人后续自然语言二次确认后一次性执行，并前后核对服务状态。
- 不做的事：不在普通原生 `exec` 或 `kurumi_code` 内开放提权；不绕过[文档6](6_二次确认.md)在同回合自批自执行。

## 接口

### `kurumi_host_admin`

插件位于 `chatbot/plugins/kurumi-host-admin/`，工具名 `kurumi_host_admin`，仅主人私聊可用，权限点为 `host.sudo.read`（`list`、`status`）与 `host.sudo.manage`（`propose`、`commit`），对应[文档24](24_统一身份与权限管理.md#权限)。

| action | 参数 | 作用 |
| --- | --- | --- |
| `list` | 无 | 返回已登记动作（含 `leaseEligible` 标记）与最近执行摘要 |
| `propose` | `actionId` | 只读检查当前状态、冻结计划，返回短人话 `presentationFacts` |
| `commit` | `proposalId` | 核对配置未漂移后消费一次性授权，无 shell 执行并核验后置状态 |
| `status` | `proposalId` | 只读回查提案状态、执行前后事实与当前实时状态 |

配置位于 `plugins.entries.kurumi-host-admin.config`（生产暂未装配）：`sudoCommand`、`systemctlCommand`、`timeoutMs`、`proposalTtlSeconds` 与 `actions[]`（`id`、`template`、`target`、`label`、`impact`、`leaseEligible`）。对应确认域为 `host_sudo`（逐项确认）。

## 原理

- **物理隔离提权**：普通 `exec` 运行于 Landlock + `PR_SET_NO_NEW_PRIVS` 围栏内，内核层面禁止提权；受控提权独立由 `kurumi-host-admin` 以无 shell `execFile`、固定清理环境变量调用 `/usr/bin/sudo -n -- <systemctl> restart <target>`，依赖操作者安装的最小 `/etc/sudoers.d/` 规则。
- **先消费再执行与防漂移**：`commit` 在 SQLite `BEGIN IMMEDIATE` 事务内验证配置/目标/命令指纹未漂移（否则拒为 `host_admin_action_changed`）并先消费 `@kurumi/confirmation-core` 授权再执行；无论成功、失败或超时均禁止同提案重放。
- **QQ 精简预览与链路追溯**：`presentationFacts` 仅保留动作、目标、现状、影响与范围五条短人话，不含完整 UUID、64 位哈希或长路径；提案与执行写入 `channel/trace-events.jsonl`，可用[文档18](18_跨模块链路日志查询.md) `--source trace-events` 追溯，私有状态存 `<stateRoot>/state/host-admin/actions.sqlite`。
