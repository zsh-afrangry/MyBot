# 编码委托扩展与受控电脑管理

本文承接[文档28](28_本机编码工具委托与实验任务.md)收口后的电脑操控与编码扩展能力，按“架构面向终极形态预留、开发与放权分阶段稳步验收”推进。

## 功能

### 受控系统操作通道（阶段 1）

- 主人可在 QQ 私聊通过独立窄工具执行操作者预先登记的声明式系统运维模板，绝不接受模型传入任意命令、参数或自由 root shell。
- 首期支持模板 `service.restart`（首个候选目标 `todeskd.service`），执行前冻结操作、目标、当前状态与影响提示（说明可能短暂断开远程连接），经主人后续自然语言二次确认后一次性执行，并前后核对服务状态。
- 不做的事：不在普通原生 `exec` 或 `kurumi_code` 内开放提权；不绕过[文档6](6_二次确认.md)在同回合自批自执行。

### 分级文件工具与有界任务租约（阶段 2A，隔离已验，生产待启用）

- 按四级路径分层管理本机文件：`T0` 自由工作区/草稿区（`/home/afrangry/kurumi-space`）、`T1` 一般用户目录（阶段 2A 先放开 `下载`/`文档`）、`T2` 受控敏感区（代码仓/非凭据配置）、`T3` 不可触碰红线（凭据密钥、运行中唯一事实 SQLite 与账本、系统核心路径）。
- `T0`/`T1` 内新建、读写及单文件编辑/覆写/删除前先自动备份原件到私有恢复快照，再直接执行；批量操作、目录清理与可写 `T2` 修改须经主人二次确认或使用有效有界任务租约。
- `T3` 红线（含 `.env`/私钥/运行态）与符号链接逃逸读写一律硬拒绝；不接受自由删改各级根目录本身。
- 有界任务租约在主人交互私聊按明确用途、可租约动作白名单、精确目录、操作次数/字节配额及 TTL 授信并可随时吊销；高危系统修改与代码合入禁止租约化，后台 Cron 与主动唤醒会话不继承。

## 接口

### `kurumi_host_admin`

插件位于 `chatbot/plugins/kurumi-host-admin/`，工具名 `kurumi_host_admin`，仅主人私聊可用，权限点为 `host.sudo.read`（`list`、`status`）与 `host.sudo.manage`（`propose`、`commit`），对应[文档24](24_统一身份与权限管理.md#权限)。

| action | 参数 | 作用 |
| --- | --- | --- |
| `list` | 无 | 返回已登记动作（含 `leaseEligible` 标记）与最近执行摘要 |
| `propose` | `actionId` | 只读检查当前状态、冻结计划，返回短人话 `presentationFacts` |
| `commit` | `proposalId` | 核对配置未漂移后消费一次性授权，无 shell 执行并核验后置状态 |
| `status` | `proposalId` | 只读回查提案状态、执行前后事实与当前实时状态 |

配置位于 `plugins.entries.kurumi-host-admin.config`（生产已启用，登记 `restart_todeskd` 重启 `todeskd.service`）：`sudoCommand`、`systemctlCommand`、`timeoutMs`、`proposalTtlSeconds` 与 `actions[]`（`id`、`template`、`target`、`label`、`impact`、`leaseEligible`）。对应确认域为 `host_sudo`（逐项确认）。

### `kurumi_files`

插件位于 `chatbot/plugins/kurumi-files/`，权限点为 `files.read` 与 `files.manage`，对应确认域为 `host_files`（逐项确认）；列表与突变响应键名统一为 `snapshotId`、`proposalId`、`leaseId`，与入参一致。

| action 组 | 参数 | 作用 |
| --- | --- | --- |
| 只读 | `roots`/`list`/`stat`/`read`/`search`/`snapshots`/`status` | 查询策略目录、跳过 `T3` 列目录与搜索、文本分页读、查恢复快照与提案状态 |
| 单项执行 | `mkdir`/`write`/`edit`/`copy`/`move`/`delete`/`restore` | `T0`/`T1` 单文件变更前自动落快照，`restore` 按 `snapshotId` 完整性校验恢复 |
| 冻结与租约执行 | `propose` / `commit` / `apply_leased` | 处理 `batch_delete`/`batch_move`/`batch_copy`/`cleanup_dir`/`t2_*` 或单文件租约执行 |

配置键：`homeDir`、`defaultWorkspace`、`t0Roots`、`t1Roots`、`t2Roots`（含 `readOnly`/`allowLease`）、`t3Roots`、`maxReadChars`、`maxWriteBytes`、`maxBatchItems`、`maxSnapshotFileBytes`、`maxSnapshotTotalBytes`、`snapshotRetentionDays`、`proposalTtlSeconds`。

### `kurumi_lease`

同属 `kurumi-files/` 注册，复用共享包 `chatbot/packages/scoped-lease/`，权限点为 `lease.read`（`list`、`status`）与 `lease.manage`（`propose`、`commit`、`revoke`、`revoke_all`），对应确认域为 `scoped_lease`（逐项确认）。`propose` 指定 `label`、`actions`、`roots`、`maxOps`、`maxBytes`、`ttlSeconds`。

## 原理

- **物理隔离提权**：普通 `exec` 运行于 Landlock + `PR_SET_NO_NEW_PRIVS` 围栏内，内核层面禁止提权；受控提权独立由 `kurumi-host-admin` 以无 shell `execFile`、固定清理环境变量调用 `/usr/bin/sudo -n -- <systemctl> restart <target>`，依赖操作者安装的最小 `/etc/sudoers.d/` 规则。
- **先消费再执行与防漂移**：`kurumi_host_admin` 与 `kurumi_files` 的 `commit` 均在 SQLite `BEGIN IMMEDIATE` 事务内验证策略、配置及基线指纹未漂移后，先消费 `@kurumi/confirmation-core` 授权再执行；无论成功或失败均禁止重放。
- **QQ 精简预览与链路追溯**：两插件 `presentationFacts` 均为短人话，不含完整 UUID、64 位哈希或敏感正文；提案、文件操作与租约生命周期写入 `channel/trace-events.jsonl`，可用[文档18](18_跨模块链路日志查询.md) `--source trace-events` 追溯。
- **分级边界与恢复快照**：`kurumi-files` 与原生 `exec` 正交（阶段 2A 生产启用后将 `下载`/`文档` 移出 `exec` 可写根）；私有快照以 `0o600` 存于 `<stateRoot>/state/files/snapshots/` 并做 SHA-256 核验与限额淘汰；`resolveSafePath` 在主目录 `T1` 模式下自动将直属 `.` 隐藏项划为只读 `T2`（供阶段 2B）。`recovery-isolation` 恢复副本会自动禁用 `kurumi-files` 并清空目录根。
- **原子租约扣减**：`ScopedLeaseStore` 存于 `<stateRoot>/state/scoped-lease/leases.sqlite`，在事务内核验交互会话、有效性、目录与动作集合后原子扣减配额，超配或越界零部分消耗。
