# 编码委托扩展与受控电脑管理

本文承接[文档28](28_本机编码工具委托与实验任务.md)收口后的电脑操控与编码扩展能力，规范受控系统操作、全主目录分级文件与租约管理、真实外部 Git 仓库委托、本仓自维护安全闸门及多编码后端适配器。

## 功能

### 受控系统操作通道

- 主人可在 QQ 私聊通过独立窄工具执行操作者预先登记的声明式系统运维模板，不接受模型传入任意命令、参数或自由 root shell。
- 当前登记模板 `service.restart`（目标 `todeskd.service`），执行前冻结操作、目标、实时状态与断连提示，经主人自然语言二次确认后一次性执行并核对前后状态。
- 不做的事：不在普通原生 `exec` 或 `kurumi_code` 内开放提权；不绕过[文档6](6_二次确认.md)在同回合自批自执行。

### 分级文件工具与有界任务租约

- 四级路径治理：`T0` 自由工作区（`/home/afrangry/kurumi-space`）、`T1` 一般用户目录（覆盖 `/home/afrangry` 主目录，排除 `T2`/`T3` 与隐藏项）、`T2` 受控敏感区（代码仓/配置/隐藏目录/已知工具链如 `miniconda3`/`snap`/`Applications`/`kurumi-archive` 默认只读）、`T3` 不可触碰红线（`.env*`/私钥/系统路径/运行态及 `.xwechat`/`.local/share/keyrings`/浏览器/IM/代理配置等）。
- `T0`/`T1` 内新建及单文件编辑/覆写/删除前先自动备份原件至私有恢复区；批量修改、目录清理、可写 `T2` 变更须经自然语言二次确认或使用有效有界任务租约。
- `T3` 红线、符号链接逃逸、直接针对层级根（含 `homeDir` 根目录）的 `cleanup_dir` 与在主目录创建隐藏项一律硬拒绝；`search` 在广泛根目录按文件名遍历预算为 `25000`、`query` 内容搜索预算为 `3000`，并自动跳过非显式指定的只读 `T2` 子树及 `.git`/`node_modules` 等重目录。
- 有界任务租约在主人交互私聊按用途、动作白名单、精确目录、次数/字节配额与 TTL 授信并可随时吊销；高危运维与代码合入禁止租约化，后台 Cron 与主动唤醒会话不继承。

### 真实外部仓库、自维护闸门与多后端扩展

- **外部 Git 仓库**：`kurumi-coding` 支持显式登记 `externalRoot: true` 与 `allowRemote: true` 的真实本地 Git 仓库，保留 `origin` 等远端配置供只读对比，禁止 `.gitmodules` 且执行期全程 `-c protocol.allow=never`（绝不联网拉取或 push）。非 `externalRoot` 试点仓与目录写回项目保持原有强边界不变。
- **本仓自维护安全闸门**：`/home/afrangry/kurumi-fusion` 仅可在同时声明 `externalRoot: true` 与 `selfMaintenance: true` 时注册；强制要求至少一项非跳过离线检查全部通过才可冻结预览；禁止候选 diff 触碰 `.openclaw-fusion`、`.git`、`config/access-control.json`、`config/runtime.config.json` 或新增外逸符号链接；`merge` 仅做本地 `git merge --ff-only`，绝不自动写运行目录或重启服务。
- **可扩展编码后端注册表**：`kurumi-coding` 支持在 `backends.<id>` 注册声明式适配器（驱动 `acp`、`codex`、`cli`，提供 `claude-code`/`gemini-cli`/`opencode` 可选预设并兼容既有 `dsh`/`codex` 配置），通过 `kurumi_code(list)` 返回 `backendDetails` 能力摘要；`codex-app-server` 原生 `codex sandbox` 失败时仍强制 fail-closed 并向任务私有 `codex.stderr` 写入探测诊断摘要。

## 接口

### `kurumi_host_admin`

插件位于 `chatbot/plugins/kurumi-host-admin/`，权限点 `host.sudo.read` / `host.sudo.manage`，确认域 `host_sudo`（逐项确认）。提供 `list`、`propose(actionId)`、`commit(proposalId)`、`status(proposalId)`；配置位于 `plugins.entries.kurumi-host-admin.config`（`sudoCommand`、`systemctlCommand`、`timeoutMs`、`proposalTtlSeconds`、`actions[]`）。

### `kurumi_files` 与 `kurumi_lease`

插件位于 `chatbot/plugins/kurumi-files/`（租约核复用 `chatbot/packages/scoped-lease/`），权限点 `files.read`/`files.manage`（域 `host_files`）与 `lease.read`/`lease.manage`（域 `scoped_lease`），列表与写入响应统一使用 `snapshotId`/`proposalId`/`leaseId`。

- `kurumi_files`：`roots`/`list`/`stat`/`read`/`read_structured`/`search`/`snapshots`/`status`（只读；`read_structured` 通过 `@kurumi/office-reader` 支持 `csv`/`tsv`/`xlsx`/`docx` 分页解析、UTF-8/GB18030 自动识别与 Excel 日期还原，受 16 MiB/64 MiB 解压与禁用 XXE 保护）、`mkdir`/`write`/`edit`/`copy`/`move`/`delete`/`restore`（`T0`/`T1` 单项快照执行）、`propose`/`commit`/`apply_leased`（批量与可写 `T2`）。
- `kurumi_lease`：`list`/`status`/`propose`/`commit`/`revoke`/`revoke_all`。
- 配置：`homeDir`、`defaultWorkspace`、`t0Roots`、`t1Roots`、`t2Roots`（`readOnly`/`allowLease`）、`t3Roots` 及大小/条数/留存/TTL 上限。

### `kurumi_code` 扩展配置与接口

在[文档28](28_本机编码工具委托与实验任务.md)既有接口基础上新增：

- `projects[]` 扩展字段：`externalRoot`（布尔）、`allowRemote`（布尔）、`selfMaintenance`（布尔）、`protectedPaths`（可选相对路径前缀数组）。
- `backends.<id>`：`driver`（`acp`/`codex`/`cli`）、`command`、`args`、`model`、`promptMode`（`stdin`/`arg`/`flag`）、`promptFlag`、`homeDir`、`env`（禁止覆盖 `PATH`/`HOME`/`LD_PRELOAD`/`GIT_*`）。
- `autoPreviewOnReady`（插件全局布尔配置）与 `kurumi_code.autoPreview`（`start`/`continue` 可选覆盖参数）：开启后任务进入 `ready` 时在完成通知里自动冻结并附带待确认预览，被拦截时在通知事实标明真实错误码。
- 工具入参 `kurumi_code.backend` 采用合法后端 ID 正则；`list` 保持 `backends[]` 并返回 `backendDetails[]`；非持久化 CLI 适配器通过 `CliClient` 将标准输出录入 `result(section='agent_report')`；Git 合入预览展示分支合入方向、文件变更行统计、与本地/远端追踪分支的领先提交摘要及仅本地合入范围，不在预览文本暴露完整 UUID 与提交/差异哈希。

## 原理

- **物理提权与事务防漂移**：`kurumi-host-admin` 以无 shell `execFile` 调用 `/usr/bin/sudo -n -- <systemctl>`；与 `kurumi-files` 相同，`commit` 均在 SQLite `BEGIN IMMEDIATE` 内核验配置与基线未漂移后先消费 `@kurumi/confirmation-core` 授权，失败也不重放。
- **全主目录防护与搜索剪枝**：`resolveSafePath` 将 `homeDir` 下所有直属 `.` 项（含未创建文件）与 `HOME_PROTECTED_READONLY_ENTRIES` 映射为基于 `homeDir` 根检查符号链接的只读 `T2`（不阻塞存在性判定），`cleanup_dir` 额外禁止指向 `homeDir` 本身；恢复隔离 `disableOwnerFileRecovery` 清空文件根并禁用插件。
- **分阶段动态 Landlock 围栏**：`workspaces.projectGit` 对 `externalRoot` 仓库区分三档权限：`readonly` 与 Agent/Checks 阶段仅开放 `writeBoundary.root`（配合 `GIT_OPTIONAL_LOCKS=0` 避免写 `.git/index.lock`），`project.root` 保持内核只读；宿主机 `worktree add`/`commit`/`cherry-pick`/`rollback` 阶段以 `worktrees` 为 `cwd`、`git -C` 方式仅增开 `project.root/.git`；仅 `merge --ff-only` 瞬间对目标工作树放开写入。`directory-workspaces` 使用与 `LANG` 无关的码点排序。
- **适配器隔离与恢复排除**：自定义非 DSH 后端独立分配 `backend/<id>-home` + `task.cwd` 围栏与隔离进程树回收；`recovery-isolation` 的 `disableExternalCodingRecovery` 在隔离恢复验证中自动剥离 `externalRoot`/`selfMaintenance` 项目，防止沙箱误触宿主机仓库。

## 限制与已知问题

- 生产当前启用 `kurumi-host-admin`（`restart_todeskd`）、`kurumi-files`/`kurumi-lease`（`kurumi-space` 与全主目录 `/home/afrangry`）及 `kurumi-coding`（`autoPreviewOnReady: true`、外部项目 `repository` `master`、自维护项目 `kurumi-fusion` `main`）；外部编码后端适配器（`opencode`、`claude-code`、`codex`）在 `config/runtime.config.json` 中尚未启用，待专用凭据隔离与多后端实测时开启。
- `kurumi-fusion` 自维护仓库的 `dependencies.test.mjs` 依赖未跟踪的 `node_modules` 与 `dist/`，而 `recovery.test.mjs` 需在非 `PR_SET_NO_NEW_PRIVS` 环境下创建 `bwrap` 用户命名空间，因此 `landlock-run` 隔离 worktree 门禁运行纯 Node 无外部依赖检查（`access-control.mjs --check`、`scripts/fusion/test/` 中 6 项 `os.tmpdir()` 安全测试、全仓 JS 语法校验与 `git diff --check`），并由文档 36 的 `coding-extensions` 在真实 Landlock 下覆盖回归。
- 本机 Codex CLI `0.147.0` 原生沙箱受用户命名空间限制无法初始化，生产尚未启用。
- `kurumi_host_admin(list)` 返回键 `id` 与 `propose` 入参 `actionId` 命名不同；日常 QQ 表达风格与消息长度约束见[文档25](25_人格、记忆与会话连续性.md)。
