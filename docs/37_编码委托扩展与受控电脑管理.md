# 编码委托扩展与受控电脑管理

## 功能

本文承接[文档28](28_本机编码工具委托与实验任务.md)收口时未开工的扩展项，均为需求，尚未调研或实施。

- **真实项目接入**：选一个真实 Git 项目登记为编码项目，先确认目录、远端和子模块是否符合执行边界，再验证依赖和锁文件、联网、缓存、临时服务、基线变化和原有未提交改动保留，以及合入或回写后的恢复范围。
- **Codex 后端**：Codex 原生沙箱可用后确认专用认证、状态保护与恢复范围，再验收真实执行、权限拦截、续接和 QQ 回传。其他后端按同一验收边界逐个接入。额外审批优先采用后端自身的机制，自动审查与自动合入另定验收门槛。
- **可写目录扩展**：确定允许新增的可写目录和关键路径，落实普通编辑、覆盖及批量删除的执行层权限；验证普通命令依然可直接执行，敏感动作需要授权。
- **受控 sudo 入口**：单独提供受控 `sudo`，只接受登记的固定动作和目标。先送达冻结的动作、目标和影响，只由可信的 QQ 本人私聊的后续确认授予一次性权限；确认契约见[文档6](6_二次确认.md)。首个候选是重启 `todeskd.service`，确认范围时说明可能中断远程连接。

## 限制与已知问题

- Codex CLI `0.147.0` 的原生沙箱无法初始化用户命名空间，探针会在启动模型回合前拒绝执行；生产 Codex 适配器未启用。
- 受控 sudo 须先隔离验证未确认、错误身份、候选变化、过期与重复消费都拒绝执行，普通终端与编码后端均不能触发提权，获准后再核对执行结果与服务状态。
