### 核对真人测试的视图

```bash
node scripts/fusion/log-query.mjs --from '2026-10-21 21:05' --to '2026-10-21 21:16' --turns
node scripts/fusion/log-query.mjs --from '2026-10-21 21:05' --to '2026-10-21 21:16' --errors
node scripts/fusion/log-query.mjs --from '2026-10-21 21:05' --to '2026-10-21 21:16' --audit
node scripts/fusion/log-query.mjs --run-id 实际runId --kind agent.tool_ --exclude-source access-control
node scripts/fusion/log-query.mjs --run-id 实际runId --expand
node scripts/fusion/log-query.mjs --from '2026-10-21 21:05' --raw --kind openclaw.log
```

- 默认隐藏未分类的原生行 `openclaw.log`、`snowluma.log`，表头和 JSON `hiddenRaw` 给出隐藏数；`--raw` 或显式 `--kind openclaw.log` 才显示。`--kind`/`--exclude-kind` 按前缀匹配（`agent.tool_` 或 `agent.*`），`--exclude-source` 排除适配器；三者都可重复。
- 默认文本视图把同一次调用合并成一行 `[tool.call]`：真实工具名（经 `tool_call` 包装时注明“经 tool_call”，`arguments.id` 的 `openclaw:<插件>:<工具>` 和裸工具名两种写法都能还原）、成功/失败/拒绝/未返回、错误码、耗时和每条访问决定。配对键是外层 `toolCallId`；宿主为包装内的真实工具另写一条 `openclaw.nested-tool.v1` 记录（事件类型 `agent.tool_nested`），它的 `parentToolCallId` 指回外层调用，带内层 ID 的访问决定经此归到同一行。耗时取真实工具的 `timestamp - startedAt`，没有内层记录时取调用到结果的间隔。错误码优先用结果里的 `code`，否则按文本归为 `validation`、`timeout` 或 `tool_error`；宿主 `blocked` 和访问拒绝都算“拒绝”。
- `--turns` 以每条会话入站为一回合，列出“用户 → 工具 → 回复”；归属依次按 runId、QQ 消息 ID、回复 ID、同会话时间顺序。会话入站本身没有 runId，查询把它绑到同会话下一条带 runId 的事件，遇到 `/new` 停止。`/new`（`session.reset`）和上下文压缩（`session.compaction`，只显示 token 前后和摘要字数，不显示摘要正文）作为分段线显示。
- 工具调用分别给出`executionOutcome`与`businessOutcome`：宿主执行返回和结构化业务`ok/status`分别判断，无业务标记为`unknown`；摘要提取已有结果数、搜索覆盖、陈旧、缺失和裁剪标记。协议封装任一层失败均保留，支持旧`tool_call`及11.1的`dispatch_action`；不遍历业务文档内部任意`ok`字段，不由宿主未抛错推断业务成功。
- `--errors` 列失败/拒绝的调用、模型错误（`agent.model_error`、`agent.prompt_error`）、回合中断（`agent.turn_aborted`）、宿主 WARN/ERROR/FATAL 行、失败HTTP及业务事件，并按错误码计数；正常HTTP 304不算错误，列表`generation_failed`等业务失败可见。此模式保留原生告警行；宿主行的码只取 `子系统:级别`，形如正文的子系统字段归为 `openclaw`/`node`，不把日志文字带进错误码。
- `--audit` 每回合列出被拒绝的工具和同一工具的连续重试（至少两次且前面有失败）；文本只列需要注意的回合，JSON 保留全部回合。`--turns`、`--errors`、`--audit` 只能选一个。
- `--expand`（同 `--full`）在事件 `data.expanded` 中放完整调用参数、结果正文和宿主 details，已解 zstd、逐层解析 JSON 字符串；文本视图在合并行下缩进打印，且回合文本不截断。输出可能含私聊原文和工具结果，只在本机排查时用。
- 显式`--no-text`在关联、错误判断和回合审计之后投影技术摘要，文本/JSON使用同一结果；省略正文、参数、自由文本错误和路径，保留原样机器码及关联ID。该可选摘要不约束完整读取，保留的身份ID也不等于匿名材料。
- `--json` 保持`schemaVersion/from/to/total/shown/events`等既有字段，按视图增加`view`及相应结果、隐藏计数、分页字段和合并调用；消费者应读取实际游标，不能只看首批就宣称取完全部记录。
- `--stats`的耗时同时列测量次数与均值；模型用量来自原生assistant/transcript实际记录。宿主未记录回退标记时`fallbackKnown:false`，不能由模型变化推断是否发生回退。
- `--follow`采用5秒重叠窗口和不含文件行号的事件指纹去重，轮转不重复，自动取完当前批各页，Ctrl+C退出；回看窗口外旧事件的修改不保证发现。JSON输出为NDJSON。

命令只打开日志和 SQLite 的只读连接，不调用 Gateway、OneBot、模型、Cron，也不写生产运行目录。不要把 `--json` 输出直接提交到 Git：其中的 `sourceRef` 可能包含本机绝对路径，事件正文也可能包含私聊内容。

编码试点沿用`channel/trace-events.jsonl`与`trace-events`适配器，事件`source=coding`，可按`--source trace-events --contains 实际任务ID`查询。记录内部任务、可信宿主runId、外部DSH会话/工具ID、检查/确认/合入与投递状态，不记录提示词、代码或完整终端输出。`observability/tool-trace.js`只从可信调用钩子关联runId；工厂上下文或模型参数不能自报。[本地试点与离线查询](verification/coding-delegation-plan-2026-10-28/product-pilot-2026-10-29/README.md)通过；[单目录QQ试点](verification/coding-delegation-plan-2026-10-28/qq-pilot-2026-10-30/README.md)已部署待真人验收。额外ACP权限的内容/理由追加在任务私有`permission-requests.jsonl`，统一日志只记次数、拒绝状态与关联；启动期文件拒绝与ACP申请分别统计，不将离线诱发请求混作实际需求频率。

## QQ主人只读日志工具

`kurumi_logs`复用现有只读CLI，由插件组合入口启动固定Node脚本、固定配置根，无shell或模型指定命令/路径。部署者必须显式配置`backendRoot`，脚本固定为该根下的`scripts/fusion/log-query.mjs`；不得从`import.meta.url`推导仓库外脚本，因宿主会复制插件到临时捕获目录加载。启动前验证后端文件，模型不能传入或改写后端路径。主人私聊需显式`logs.read`；成员、群聊、天气Cron、编码/研究任务和自主行动后台不继承权限。执行前后检查当前身份、授权和有效调用。

主人于2026-11-10逐项批准诊断增强：身份白名单、只查询、既有来源和单查询并发保持；取消工具自设的7天窗口，不将存储保留时间当权限期限。默认仍最近2小时，允许显式起止、任意有效跨度或`since=all`查询仍留存的历史；没有数据不证明历史未曾出错。独立运维清理对logs/及runtime轮转副本有7天/60MiB策略，主runtime.log和会话库等不受统一7天期限，本轮不改其保留策略。

提供`view=overview/events/errors/stats`，overview显式返回错误概览、来源计数及稳定详情引用，其他视图保留完整读取路径。支持`contains`单关键词或`keywords`多关键词（`keywordMode=any/all`）、真实run/message ID、事件类型及`levels`原生级别筛选。搜索在正文和完整展开数据上匹配，摘要模式也不降低召回；仅返回层决定是否显示正文。`noText`缺省false，只有显式true才采用表层摘要；`expand=true`读取来源中已有的完整记录及调用参数/结果，`raw=true`包含未分类原生日志；不按内容字段或字符格式限制主人已授权的完整结果。写入时已经脱敏或未记录的信息无法恢复，不把日志原文当作可信指令。

`contextBefore/contextAfter`各0–1000，按所选来源的时间顺序返回命中事件前后指定条数，邻居不再被关键词/类型/级别筛掉，仍在本次时间窗和来源范围内；事件及错误视图均支持，概览/统计不混入上下文。默认最多50个命中、上限100个；传输预算内优先返回完整事件，实际shown可能较少，照抄nextOffset翻页。每条事件及错误条目均有稳定eventRef，可用view=events、eventRef和expand=true展开单条；引用仍受时间和来源范围约束，源位置改变或记录退役后可能无法解析。

大单条或全局上下文/统计过大才使用contentOffset/nextContentOffset分段序列化JSON，照抄contentHash并固定from/to与全部筛选，完整取完再翻行页；内容变化则重读该页，不静默删字段或丢失长记录。固定CLI同时控制单次18000字节及12000保守加权字符，为宿主现行自动文本预算与24KiB最终封装留余量；普通CJK按4字符、其余非ASCII按UTF-8最坏权重估算。核更新须复核预算，不能直接扩大字节上限；旧3000字节固定分段仅为前次部署事实。10秒超时及单查询并发保持，取消/超时等待子进程退出。错误counts/recordCount计记录；businessAttemptCount只按来源+明确eventKey计带键错误组，unkeyedErrorRecords单列，不把它们说成独立事故总数，也不按时间或同码伪造因果。

精确筛选code（含嵌套异常码）、eventKey（提醒列表slotKey）、cronJobId已纳入本轮实现。列表适配器同时读取audit及deliveries账本：ledger是当前保存状态，单独标明snapshotOfCurrentState；保留旧audit与账本冲突，delivered且正文空时显式给digest_delivered_without_body，不回写历史库。exceptionRecordedInAudit=false表示该审计未保存具体异常；通用业务失败码及命令退出码都不能冒充具体抛错原因。Cron历史从task_runs.detail_json读取原有diagnostics/exitCode/投递等字段，按分区、job和起始时刻精确附接回执及error_text；不使用当前任务配置充当历史命令。

“整理”若指按类型/时间归类、统计、关联并形成故障摘要，可以用只读结果完成；本工具不提供日志文件归档、轮换、删除或改写。现有日志轮换归运维程序，QQ助手主动维护日志文件的需求尚未实现，不能把只读接线等同于完整日志管理。

## 适配器扩展契约

以下面向开发者；日常使用以上面的参数、视图和示例为入口。

### 统一事件契约

所有适配器输出同一 envelope；`chatbot/packages/observability/index.js` 是写入契约与脱敏sink的唯一实现。查询缺省沿用归一化与脱敏；显式full-content通过`log-query-privacy.mjs`保留来源已有原文，不改变写入sink。查询编排仍归 `scripts/fusion/log-query.mjs`，共享包不反向导入查询脚本；代码归属见[文档21](21_后端职责分层与代码整理.md#共享代码与插件生命周期)：

```json
{
  "schemaVersion": 1,
  "at": "2026-10-10T17:12:35.000Z",
  "epochMs": 1791652355000,
  "source": "snowluma",
  "kind": "qq.inbound",
  "correlation": {
    "qqMessageId": "-1908656766",
    "sessionKey": "agent:main:kurumi-qq:direct:365999865"
  },
  "data": {"text": "1分钟之后提醒我做测试"},
  "sourceRef": {"path": "…", "line": 23}
}
```

`correlation` 只放关联键，不放凭据；当前支持 `sessionId`、`sessionKey`、`runId`、Trace/Span ID、QQ 消息 ID、回复 ID、提案 ID、payload hash、提醒 ID、Cron ID、event key、任务 ID 和会话 ID。`data` 保存适配器需要展示的事实，`sourceRef` 只用于回到原始证据。

写入sink及缺省查询会递归遮蔽名为 `token`、`secret`、`password`、`authorization`、`apiKey` 等字段，并遮蔽 Bearer/API key 形态的文本。新增适配器仍遵循同一envelope；显式full-content只在读取层保留原有内容，不新增第二套写入格式。

N3可选组件的技术事件归`state/proactive/trace.jsonl(.1)`，适配器与source均为`proactive`，按真实runId关联模型用量、只读查询来源哈希、自身记录ID/version及逐条投递结果；不写聊天、通知或记录正文。生产未启用时没有该日志，查询不创建空状态。

KnowledgeMap账单、事项与天气的对话调用通过共享 `chatbot/packages/knowledgemap-client/tool-trace.js` 取得真实runId：宿主before/after_tool_call钩子按会话和toolCallId关联，TTL/容量有界并在完成或重置清理；工厂上下文不提供runId，模型参数不参与关联。HTTP头、旁路事件及后端写入日志使用同一runId。固定Cron没有对话run时允许留空，不伪造。第二轮12条真实API事件及3条后端写日志核对见[专项证据](verification/knowledgemap-bills-round2-2026-10-17/README.md)。

查询会先按指定 ID 找种子事件，再沿 `qqMessageId`、`replyToId`、`proposalId`、`payloadHash`、`reminderId`、`cronJobId`、`eventKey`、`runId`、`taskId` 和 `toolCallId`（`parentToolCallId` 视为同一命名空间）做关联闭包。因此按一条 QQ 消息查询时，可以看到后续确认、创建 Cron、到点投递和对账结果；按提案查询时，可以看到授权、提交和提醒投递。

SnowLuma每条带时间戳的发送记录对应一次OneBot发送日志，正文换行是同一条预览的续行，不能作为额外发送计数。多次带时间戳的发送仍分别保留。原生消息日志可能只给截短预览，不能用它的长度证明完整消息已发送。适配器已拼接完整多行日志预览并保留先后顺序；上游截短不可恢复，严格内容核对需结合显式消息存储与回执。OpenClaw runtime可能记录重复Cron行，查询不擅自删除原始证据。

附件入口通过`paper.qq_receive`记录每项类型、状态、错误码与成功ID，`paper.qq_ingress_route`记录`assistant_notice/model`（历史记录可能是`direct_notice`）及`modelDispatched`。两者绑定可信QQ消息ID/会话，绑定模型说明分支在发送前记录决策，未知发送回执不会被误记为送达。查询用`--source papers --message-id 实际消息ID`；规则与验收见[文档22](22_论文PDF翻译与文件投递.md)及[附件证据](verification/paper-translation-2026-10-17/file-ingress-2026-10-19/README.md)。

五类快照只读当前状态，不重建历史；远端事项切换后只给本地设置和`remote_items_not_read_offline`，不访问API或回退旧库。文档快照不验证PDF字节完整性。记忆/E7及记忆v3旁路日志每文件4MiB轮转，只保留主文件与一代`.1`，单次事件可略超阈值；此策略不适用于业务账本或全部日志来源。

完整私聊消息库必须显式按ID/已登记peer读取，不读群聊和媒体表。默认给方向、文本长度/字节/SHA256及同ID预览匹配（equal/prefix/different/unavailable）；显式展开给已有文本段，图片/文件URL和下载密钥不输出。只匹配同ID文本段，不把相似文本当同一消息；这项消息适配器范围不等同于对主人日志完整结果追加通用内容白名单。

### 面向未来功能的扩展

没有把 OpenClaw 或 SnowLuma 改造成共享日志系统，也没有在每个业务函数里复制一套 AOP。两套程序有自己的日志格式和升级节奏，强行注入全局 hook 会增加升级冲突、私聊泄露和停机风险。当前采用“适配器 + 统一契约 + 可选旁路 sink”：

1. 先让新模块保留自己的业务日志和状态库。
2. 在模块边界调用 `createTraceSink(path).emit({...})`，或者为它增加一个只读适配器。
3. 只发送事件类型、关联键和必要摘要，不发送 token、完整请求头、数据库私密字段或不必要的聊天原文。
4. 给适配器添加离线测试，并在 `docs/verification/SCRIPTS.md` 登记脚本或证据。

频道通用 `trace-events.jsonl` 仍是可选扩展点；论文插件将同一契约的事件写入自己的 `events.jsonl`，由 `papers` 来源读取。读取时归一化事件、筛选时间范围，缺省按字段/字符串模式脱敏；显式full-content不追加该查询脱敏，当前不会拒绝未知 schemaVersion。提醒列表采用只读审计表适配器，接入方法和验收见[提醒列表的数据与测试边界](23_KnowledgeMap业务能力桥接.md#数据和代码边界)；论文任务用量明细在对应私有任务记录中，接入与验收见[文档 22](22_论文PDF翻译与文件投递.md)。

本机编码工具委托的日志需求见[任务日志与链路关联](28_本机编码工具委托与实验任务.md#日志与链路关联)：沿用统一事件，由任务编排与执行适配器记录外部任务、工作树、检查、待确认合入及投递。宿主工具钩子不会自动追踪外部进程内部执行；本地试点已接入现有`trace-events`来源，QQ单目录试点按上文授权与实际部署记录验收。

## 已知边界

- SnowLuma 文本日志只有秒级时间；同一秒内的多条消息以日志顺序和消息 ID 区分。
- OpenClaw 原生 transcript 的部分事件以 zstd 存储，查询器已支持解压；损坏或不可解压的单行会跳过并保留其他事件。
- runtime 日志没有稳定地重复 QQ MessageSid，因此时间窗关联是辅助关系，查询会显式标注；需要严格证明时以 SnowLuma 消息 ID、会话 transcript 和领域审计表为准。没有 sessionKey 的 runtime 行只归给它之前最近的一个回合（不分会话），且最多在该回合开始后 120 秒内；之后的行不归任何会话。
- SQLite 的 `reminder_proposals`、`reminders` 是当前状态快照，不是完整历史；历史动作使用 `reminder_audit_log`，模型提案原文使用 `openclaw-agent.sqlite` transcript。
- 无显式关联键的旧来源可能按时间窗进入候选链路，需要核验，查询不是关联正确性的自动证明；投递结论应同时查看 OneBot/频道回执和领域状态。提醒列表的定时审计没有聊天 sessionKey，不进入最近聊天时间窗。
- 频道`channel.sqlite`通用投递账本由`channel-delivery`适配器只读查询；SnowLuma `messages.db`需显式选`--source snowluma-messages`并带`--message-id`或`--peer`，仅查询运行策略中已登记的私聊；缺省不扫描消息库。`qq.outbound`是原生日志预览，不是完整发送正文或已读证明。现有`--audit`检查拒绝、失败、失败后成功及要求用户补充后仍继续调用，不自动判断空结果、漏检或答案正确性。实例与接口外核对边界见[E7 QQ报告](verification/e7-interface-2026-10-27/phase2/qq-review-2026-10-30/README.md#日志接口之外的信息与纳入建议)。
- `sourceRef`定位日志文件/表/记录，不能当作抛错源码位置；异常位置以已有`origin/stack`为准。旧审计未写入异常时保留未知，不由通用失败码或退出码补造具体原因。
- 宿主会话库的`trajectory_runtime_events`已有`context.compiled/prompt.submitted/model.completed`，当前`openclaw-session`仅读transcript，尚未接入这些上下文轨迹。原生轨迹也可能已在写入时截断；“同会话出现旧错误且输出相似”支持历史污染推断，不能证明模型实际看到了哪条、必然自锁或唯一根因。输出内容不能冒充输入历史证据。
- 日志查询不为判断漏检自动联网重查，不用当前缓存补造历史HTTP/记忆轨迹。完整消息存储或平台回执均不证明媒体加载、客户端排版或收件人已读；这些需独立业务/客户端证据。

## 后续增强与维护

已有P0/P1/P2需求以本文当前契约为准，旧阶段过程由Git和证据目录保存，不再以“待开发需求”重复列出。后续可评估只读接入宿主已有上下文轨迹及完整性标记、可信消息引用/数量与裁剪信息，以及QQ日志文件管理；均未实施，不阻塞本期收口，具体任务状态回到唯一全局手册。长期稳定性与推断严谨性持续观察，不据本期完成扩大后台权限或自动修复范围。

维护时保留以下验证约束：

- 新增/修改适配器有离线回归，使用合成数据，不把真实私聊复制为夹具。
- `--json`事件契约向后兼容；新增字段只加不改，未知/原始截断不能静默伪造为完整。
- 参数变化同时更新`--help`与本文；宿主升级复核工具输出预算及真实捕获执行。
- 只读核对、隔离真实模型、生产技术与真人使用分别记录，历史失败不改写为通过。
