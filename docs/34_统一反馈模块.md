# 统一反馈模块

## 功能

让 Kurumi 执行的、需要用户知道结果的动作都能产生可核验的反馈，而不是只有消息投递这一种事件。目标是把“动作完成/失败/未知/送达”做成横切能力，供需要的功能按需接入，而不是为单个业务单独实现回执。

首个驱动场景是消息的真实送达回执：当前平台回执只证明平台受理，不能说明客户端是否收到或已读（见[文档18](18_跨模块链路日志查询.md)、[文档21](21_后端职责分层与代码整理.md)、[文档23](23_KnowledgeMap业务能力桥接.md)）。

倾向于参考[二次确认](6_二次确认.md)的可插拔方式：业务插件声明需要的反馈类型，统一模块负责记录、核对和呈现；接入哪些动作、反馈分几层、是否需要用户可见，均待需求分析。

## 限制与已知问题

- 尚未进行调研和需求分析，可行性未知。
- SnowLuma/QQ 能提供的送达/已读能力未知，需先确认可核验到哪一层；不能承诺客户端已读。
- 与现有投递账本、日志查询、二次确认的职责边界未定，不能把同一个回执写成两套事实。
- 反馈是横切能力，涉及权限、重试、幂等和保留期，暂不确定是否复用现有 `qq-delivery` 与 `proactive-core` 的机制。
