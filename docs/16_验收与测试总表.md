### 制作与验证恢复点

以下操作按实际授权执行；文档整理不自动运行停写/恢复。

```bash
node scripts/fusion/backup-state.mjs --label rollback --quiesce
node scripts/fusion/restore-verify.mjs --backup /home/afrangry/kurumi-backups/<具体目录>
```

- `--quiesce`检查稳定状态，只停止原本运行的Fusion；完成、异常或可捕获中断后恢复，原本停止则保持。它只表示受管服务已停写，期间不能另起Gateway或手工编辑状态；在线快照只保证单库一致。
- 采集先写`INCOMPLETE.json`并持有`.backup.lock`，收集成功且恢复服务后才移除标记。SIGKILL/断电不可捕获：确认锁中PID已消失、检查并必要时恢复服务，再处理陈旧锁；不得删除不完整标记伪装成功。生产SIGTERM演练退出143、服务恢复和不完整拒绝的证据按最终恢复报告保留。

### 隔离恢复模式

`restore-verify.mjs`仅接受新建规范`/tmp/`目标，拒绝已有目录/链接，不覆盖生产或操作主机服务。先验manifest/仓库/数据库，再按EXPECTED中的版本和SHA256恢复内核/Python/执行边界辅助包工件及锁定依赖，沙箱内构建/实际加载插件、启动Gateway及模拟OneBot，执行项目检查；不借用全局已安装SDK。新版v3的`scope: fusion-only`不包含独立KnowledgeMap/DSH项目，编码探针使用独立还原的真实Linux辅助程序验证Fusion侧策略和写入边界；无scope的旧v3点仍按原契约恢复DSH配套材料。
