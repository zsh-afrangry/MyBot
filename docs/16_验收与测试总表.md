## 制作与验证恢复点

```bash
node scripts/fusion/backup-state.mjs --label rollback --quiesce
node scripts/fusion/restore-verify.mjs --backup /home/afrangry/kurumi-backups/<具体目录>
```

- `--quiesce`检查服务稳定状态，停止原本运行的融合服务，完成/异常/可捕获中断时恢复；原本停止则保持停止。
- 备份目录先写`INCOMPLETE.json`，成功收集并恢复服务后才删除。目录锁`.backup.lock`阻止并发采集。
- SIGKILL、断电不可捕获：保留中断标记和锁。先确认锁中PID已不存在、检查服务，必要时手动恢复服务，再移除陈旧锁；不要删除INCOMPLETE把失败目录伪装成成功备份。
- `quiesced=true`只表示本机受管融合服务已停写；操作期间不要另起手工Gateway或编辑工作区。在线快照只保证单库一致。
- Git以`--binary --full-index`补丁保存已跟踪修改，未跟踪非忽略文件单独tar；运行数据独立采集。Git忽略的源码侧任意文件不承诺全部保全。
- 旧系统全量归档和固定SDK包是独立恢复材料，不是每份新运行快照都会重复包含它们。
- 新工具默认要求EXPECTED.json；旧pre-consolidation结构使用其历史材料说明，不能直接当新格式恢复点。

## 隔离恢复模式

`restore-verify.mjs`只接受新建的规范`/tmp/`目标；拒绝已有目录和链接。它不会把备份覆盖到生产位置，也不操作主机服务。

1. 验证manifest、必需项、仓库和数据库，再组装副本。
2. 通过固定SHA256验证并解开OpenClaw 2026.9.7 SDK归档，安装锁定依赖；不读取全局已安装SDK。其他机器可用`--sdk-archive <复制过去的固定包>`。
3. 递归改写运行配置、项目注册表与符号链接。包括workspace、token、日志、提醒runner、项目root/fixture。历史聊天原文不改。
4. 验收副本写入不可用的测试凭据，禁用真实QQ与Cron。原始凭据与配置仍完整保存在只读备份。
5. Bubblewrap只挂载系统基础文件和副本，生产home、服务总线不可见，网络独立。所有构建、插件加载、Gateway启动与模拟OneBot均在该边界内进行。后台项目需要的固定SDK路径只读映射到恢复归档；实际运行注册表中的项目检查。
6. 模拟频道仅在探针运行期间开启，退出时关闭；没有真实消息投递。`verification.json`及`isolation-result.json`记录验收层级。

`--skip-deps`是材料检查模式，跳过构建和启动，不得称为可运行恢复。默认模式通过表示“隔离Gateway+模拟传输可运行”，仍不表示真实模型/API/QQ登录全部恢复。

**不要直接在主机启动恢复副本中的run-gateway.mjs。** 它是生产部署入口，保留原路径约定。唯一受支持的隔离启动方式是恢复工具内部的沙箱探针。正式灾难恢复应停机后按原路径还原原始配置/凭据并单独处理调度与投递对账，不使用测试凭据副本代替原始备份。

### 维护工具的安全前提（2026-10-10 事件后新增）

收尾期间编写项目注册表回归时，第一版测试没有隔离状态目录，**把一条 `probe` 条目写进了生产
`projects.json`**。处置与结论：

  这是“按字节恢复”的结论，不代表瞬时影响从未发生。
- `register-project.mjs` 因此增加 `--state-dir`（**仅供测试**），并有一条 `test.after` 守卫断言
  **测试前后生产注册表逐字节相同**。

由此确立两条要求，适用于一切会写运行目录的测试与维护脚本：

1. **测试必须指向临时状态目录**，不得依赖或改写生产路径；不能注入状态目录的脚本要先补入口再写测试。
2. **涉及生产文件的测试要加前后不变断言**，并在记录里写明检查对象与结果（MD5/字节比对），
   而不是只写“测试通过”。

- **本文维护验收标准与结论**：每项要写清证明到什么程度、**没有**证明什么、复现命令，以及所属版本。
- **`verification/` 保存证据**：脚本清单、副作用、授权要求与会写哪份证据见
  [`verification/SCRIPTS.md`](verification/SCRIPTS.md)；文件分组见 [`verification/INDEX.md`](verification/INDEX.md)。
- 领域文档只引用结论与证据链接，不复制长日志；`docs/archive/` 中的结果不代表当前版本。
- 覆盖检查是可执行的，不靠人工声明：

```bash
node scripts/fusion/evidence-coverage.mjs   # 证据文件必须命中恰好一个分类
node scripts/fusion/evidence-index.mjs      # 脚本必须有分类行（用途/副作用/授权/证据位置）
```

- **旧 harness 与当前融合验收不能混用**：`chatbot/tests/acceptance/` 测的是融合前频道与检索路径，
  它的 `*-acceptance.json` 只能按版本追溯；当前结论引用 `scripts/fusion/test-*.mjs`、
  `chatbot/tests/<领域>/acceptance-*.mjs`、领域单元测试与隔离恢复探针，并说明模型、宿主、QQ 是否真实。
  脚本分类与副作用见 `SCRIPTS.md`，不能用模拟入站证明真人 QQ 往返。

  `testIngress` 默认关闭，验收后由 `close-acceptance.mjs` 关闭，且从不重置发送账本。
