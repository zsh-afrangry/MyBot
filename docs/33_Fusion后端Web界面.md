# Fusion 后端 Web 界面

Kurumi 同时提供角色陪伴和工作协助。管理台让主人从浏览器检查项目组成、运行状态与数据，并维护明确支持的源配置。后端分层见[文档21](21_后端职责分层与代码整理.md)。

## 功能

| 页面 | 能力 |
| --- | --- |
| 总览、项目地图 | 服务拓扑、待同步提示、按职责展开模块树，查看插件、Agent、编号文档和未完成需求数 |
| 人格与关系 | 编辑共享 SOUL 的源角色卡和两类关系素材；预览 Markdown 和差异，逐身份核对四份受管文件；人格契约见[文档25](25_人格、记忆与会话连续性.md) |
| 记忆 | 查看 P2 长期事实、偏好及未到期摘要，默认隐藏内容，支持筛选 |
| 身份与白名单 | 维护 QQ 成员及邮件收件人；对照权限矩阵和运行副本，只读查看主人附加工具、可写目录、编码项目；权限规则见[文档24](24_统一身份与权限管理.md) |
| 链路日志 | 按时间、来源、事件与失败筛选，查阅关联 ID 与技术元数据，来源契约见[文档18](18_跨模块链路日志查询.md) |
| 任务与调度、运行配置 | 查看 Cron、宿主运行、编码、提醒、邮件、论文翻译和受管文件索引；查看本机端口、QQ 在线探测、插件及工具配置 |
| Git 工作树与分支 | 只读列出主仓库的工作树、本地分支、detached 状态、未合入提交和未提交改动，标记干净且已合入基准的可回收工作树 |

## 接口

- `http://127.0.0.1:3085/`，用户服务 `kurumi-admin-web.service`；相邻的 DeepSeek Harness（3080）、SnowLuma（3082）和 KnowledgeMap 业务 API（3086）各自独立运行。
- 首次启动创建 `~/.local/state/kurumi-admin-web/access-key`（0600）。在本机终端运行 `cat ~/.local/state/kurumi-admin-web/access-key`，把内容粘贴到登录页。同目录保存管理台的变更摘要。
- 安装或更新：`/usr/bin/node scripts/fusion/install-admin-web.mjs`。脚本只安装管理台代码和自己的用户服务，默认以主仓库为配置来源。可用 `--source`、`--runtime`、`--port` 显式选择目标。

## 原理

- 管理台只监听 IPv4 回环。私有数据和编辑都要求登录；会话限定在当前网页来源和标签页，不通过同一地址下不同端口共享的 Cookie 传递。写请求另核对来源，浏览器只接收各页面所需字段。
- 编辑后需预览并确认同一候选，服务校验源文件指纹，再原子替换仓库文件。白名单复用原有编译校验并递增修订。运行副本的生效仍按[配置同步契约](../config/README.md#同步契约)处理。
- 运行页区分配置声明、端口可达和 OneBot 的 QQ 在线状态。调度、账本、日志与记忆直接读取原有数据源，不另外维护一份业务状态。
- Git 页只运行查询命令（worktree list、for-each-ref、rev-list、merge-base、status），每次刷新实时读取，不写仓库。

## 限制与已知问题

- 主人 QQ、群聊准入、执行围栏和工具开关由现有配置入口管理。记忆和任务只读；管理台不展示聊天原文、凭据或业务附件。
- 管理台不代替配置同步、运行启停、恢复和真实外发。当前记忆页面只支持 P2；任务列表每类最多 80 条，日志时间窗最长 7 天。
- 业务模块的详情按项目地图查阅。各领域业务数据的管理入口、远程访问和多角色 Web 登录不在当前范围。
- Git 页不提供删除工作树或分支的动作；“可回收”只是干净且已合入基准分支的提示，回收仍在终端执行。

## 如何验证

```bash
/usr/bin/node --test chatbot/tests/admin-web/*.test.mjs
systemctl --user is-active kurumi-admin-web.service
curl -fsS http://127.0.0.1:3085/api/session
```

v0.1.0 通过隔离 HTTP 和桌面、移动浏览器验收，覆盖成员与收件人增删改、SOUL 编辑、版本冲突和访问隔离；生产验收只读核对界面和数据源。Git 页通过隔离仓库验收工作树、分支、未合入距离和可回收判定。
