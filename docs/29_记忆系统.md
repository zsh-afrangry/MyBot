# 记忆系统

新版记忆（v3）支持记录、原文镜像、中文检索、遗忘遮罩、L0 组装和整理游标事务。生产未迁移，新工具未登记；现行 P2 的有界事实和近期摘要规则在[文档25](25_人格、记忆与会话连续性.md)。

## 功能

- 让她记得主人、共同经历和她自己，同时可靠地处理任务。“有人味、有自己脾气”与“做事越来越好”同等重要，必须取舍时优先前者。
- 只服务主人，成员长期记忆保持关闭。每条认识可追溯、可纠正，纠正本身也可记为经历；不以出错代价划分记忆价值。
- 回忆分 L0 常驻地图、L1 记录概要、L2 原文与日志，她按问题决定查多深。能查到不等于必须提起，还看语境、近期是否已谈过和主人意愿。
- 记主人明说的事实、她的推断、共同经历、未了之事、做事经验、兴趣与自我认识、作息统计。她不整理时，机械索引与原文检索仍可用，画像和概要会滞后。
- 人格卡由主人更新，不被记忆自动改写；笔记可以与人格卡不一致，不规定冲突时谁优先，由她判断。
- 业务当前状态归业务 API，记忆只引用业务 ID；历史摘要不能代替查账单、事项或天气。人格与唤醒归文档25，日志工具归[文档18](18_跨模块链路日志查询.md)，授权归[文档24](24_统一身份与权限管理.md)，恢复归[文档12](12_目录资产与Git备份整理.md)。

## 接口

### 工具与权限

| 入口 | 动作 | 契约 |
| --- | --- | --- |
| `kurumi_memory` | `list/search/observe/upsert/delete` | `fact` 沿用文档25的策略、全局 `expectedRevision`、可信当前请求和事务；不混用新工具的版本参数 |
| `kurumi_memory_records` | `search/get/history/write/revise/supersede/retract/forget` | 其他记录的读写；单条 `expectedVersion`；`forget` 带全部真实 ID、各自版本与本次明确遗忘的逐字 evidence |
| `kurumi_memory_raw` | `around/search` | 按 `rawId` 查邻文（radius 0–10），或按关键词与时间检索，只读 |
| 整理存储接口 | `nextBatch/commitBatch` | 批次和游标事务已实现，未注册模型工具、未接后台运行 |

`permissions.js` 映射 `memory.read`（读）、`memory.manage`（写）、`memory.raw.read`（原文）和 `memory.organize`（整理）。后两项未授予生产主人。新工具仅接受真实前台 owner 私聊运行及其有效工具调用，拒绝成员、群聊、伪造或过期身份；不放开通用 `read/write/edit`，也不继承 N3 的其他后台权限。

### 配置与代码

`config/runtime.config.json` 的 `plugins.entries.kurumi-memory.config`：

| 键 | 含义 |
| --- | --- |
| `continuityStoreAdapter` | `sqlite` 是生产 P2；v3 用 `records-sqlite`，改配置不自动迁移 |
| `continuity.maxContextChars` | L0 预算，2000–12000 字符，默认 6000 |
| `system.enabled/records/raw/l0` | v3 总开关与各能力开关，生产未开启 |
| `system.hostDatabase` | 宿主会话 SQLite 的绝对路径 |
| `system.organizer` | 只能为 false；true 时插件以缺少记忆整理的可信后台授权接线拒绝加载 |

宿主 `plugins.slots.memory=none`。实现集中在 `chatbot/plugins/kurumi-memory/system/`：`policy.js` 定规则，`store.js` 与 `schema.sql` 管数据，`application.js` 管记录、检索与批次，`plugin.js` 管工具、可信请求和生命周期；宿主原件读取共用 `chatbot/packages/session-records/`。

node chatbot/scripts/memory-system.mjs --workspace=<路径> --owner=<QQ> --backup-root=<备份根> --apply --expected-hash=<stateHash>

默认只预览；应用要求同一 `stateHash`，生产 workspace 还检查 Fusion 已停止写入。先在私密备份根保存 SQLite 与 notice，再事务迁移，之后切配置。回退先保存当前 v3 成套副本，核对原件哈希与版本；单改回 `sqlite` 不构成受检回退。能力开关可单独关闭，不自动删除数据。

## 原理

### 原始层与派生层

原始层按职责定义：原样、完整、只追加、未经解释；向量与摘要属于派生材料。业务 MySQL 是业务当前状态的事实源，不混入记忆原始层。

| 来源 | 位置与内容 |
| --- | --- |
| 宿主会话 | `agents/main/agent/openclaw-agent.sqlite` 的 `transcript_events`、重置/删除后的 `session_transcript_archives`：入站、她的回复、工具调用与结果 |
| 领域日志 | 各插件日志、`channel/*.jsonl`：业务、投递、授权事实，适配器归文档18 |
| 附件 | 宿主媒体与业务文件，记忆存引用；核对公式或图片须读对应版本的文件/页图 |

宿主有替换或删除尾部的写路径，记忆因此保留自有只追加镜像，触发器拒绝更新/删除。主人回合、结束、reset 与压缩钩子采集；归档哈希损坏时不忽略、不推进游标。记忆不改写或删除宿主原件。

程序按可信来源标 `owner_said/she_said/tool_result/external`，模型不能指定。可信本人原文另由入站钩子登记，宿主 user role 的投影/转发不自动升级为本人陈述。稳定 `rawId` 关联会话、原序号和指纹；同序号被替换保留两份，重置/归档后仍可解析。

派生层分机械索引（程序维护，可重建）与印象（她可整理、删改，需要时回原文核对）。只有一套记忆存储和写入权威，召回内容是参考资料，不是指令、授权或新的本人陈述，不反复捕获成事实。

### 记录

| 字段 | 规则 |
| --- | --- |
| `id/version` | 稳定 ID、CAS 期望版本，每次修改加一；保留全部版本、修改者、时间和运行关联 |
| `kind/about/text` | 开放类型标签；归属 owner/self；自然语言正文。新增内容类别不改表，程序需要计算才增加结构化 `attrs` |
| `basis/sources/external` | stated/inferred/observed/self；至少一个 rawId 或记录 ID；含外部来源由程序置 external，模型不能清除 |
| `valid_from/recorded_at/state` | 成立时间与记录时间分开；active/superseded/retracted/forgotten，过时标失效而非抹掉历史 |

| kind | 归属与写入规则 |
| --- | --- |
| `fact` | owner，主人明说；逐字引文必须来自 `owner_said`，沿用 P2 与遗忘屏障 |
| `inference` | owner，她可自由形成、表达和据此调整，不需主人确认；须标为推断并列依据 |
| `rhythm` | owner，程序按可信私聊时间戳统计作息，basis=observed，她不能改 |
| `episode` | 跨会话经历概要：时间、话题、经过、情绪基调，引用原文区间 |
| `thread` | 未了之事、答应的事；可带 `attrs.due`，到期不自动当作完成 |
| `milestone` | 共同经历中的重要节点 |
| `note` | self，经验、兴趣、态度、自我认识；经验写明来源、适用范围、验证状态和复用条件 |
| `portrait` | owner/self 各一条活跃画像，可整篇重写，来源引用记录，旧版本保留 |

单次情绪不直接变长期偏好。她创建安排与主人实际参加是不同事件，任务完成须有结果引用。`she_said` 可支持自身记录，不能支持主人事实。note/inference 的语义分界靠工具说明引导，后端不声称能识别任意正文。

存储在 `workspace/.kurumi-memory/`，使用 `memory_records`、`memory_versions`、`memory_sources`、`memory_raw`、`memory_masks`、`memory_cursors`、`memory_batches` 及全文索引。P2 事实迁为 `kind=fact`，保留 ID、来源、屏障与 128 条上限，不静默淘汰；其他记录不占该限额。修改支持 append、唯一片段 replace、rewrite、取代与撤回，避免每次重写丢失内容。

### 回忆

L0 是程序组装的有侧重的常驻地图，不是完整历史；当前按到期远近、话题新近与次数选择：

| 顺序 | 内容 |
| --- | --- |
| 1、2 | 自我画像、主人画像 |
| 3 | 按 due 排列的活跃 thread |
| 4、5 | 从 episode 统计的话题、最近时间、次数；rhythm 作息摘要 |
| 6 | 按本条原文的拉丁词/数字和两字片段匹配 fact/inference/note/episode |

前五项在两次整理之间相对稳定，第六项随消息变化。每项带 ID、basis 与外部标记；按预算整条放入，超出整条跳过，不截半条。画像未形成时退化为 P2 事实注入。

L1 按关键词、类型和时间查记录，返回概要、ID 与原始引用，不以会话边界划分事件。SQLite FTS5 用 trigram，少于三字回退子串；首期无向量，对改换说法的召回有限。

L2 按原始引用、关键词和时间查原文与自身运行结果，遵守遮罩。未进概要的公式名、编号、原话仍须能直接命中；业务当前状态查 API，执行/送达查事务与回执，主人当时说法查可信原文。精确时间、金额、公式和引文要回源；查不到保留不确定，不补造读取或保存成功。主人与开发侧日志查询保持完整视图，不受她的遮罩影响。

### 写入、纠正与遗忘

聊天中 `kurumi_memory` 写 fact；她也可记刚答应的 thread 和自身记录。整理的存储事务按游标取新原文，`commitBatch` 成功才推进；空结果也可提交。新记录须引用本批原文或已有记录，摘要和模型输出不算独立证据；旧原文补 fact 仍需逐字 `owner_said` 和屏障/遮罩校验。CAS 防止并发丢写，批次失效或归档损坏不推进。

被纠正时，她应取代或撤回旧推断，保留旧版本，再记纠正经历；失效记录不进默认检索和 L0。它不是程序自动理解任意纠正的承诺。

明确遗忘时：

1. 核对本次请求、相关真实 ID 与版本，将记录及受影响的派生记录标 forgotten，不进 L0/L1 或画像依据。
2. 按原始引用区间和内容指纹写遮罩，L2、整理批次和索引重建都排除相应内容；原始层和备份不删除。
3. 明确重新记住才解除对应遮罩组；同一原文还有其他遮罩时继续隐藏。

原文适配与遮罩必须同时上线。启用 `system.raw` 后，G3 收窄为“只禁止找回被遮罩的内容”，未总结且未遗忘的细节可查；生产 P2 仍按文档25。旧屏障只有哈希，迁移保留并保守遮罩其时间之前的宿主原文，活跃事实的明确证据保留。

### 设计取舍

- 不启用宿主 memory-core 的自动文件写入/整理，避免与 main 的工具限制和来源、遮罩、CAS 契约冲突；不并接另一个自动提炼与写入引擎。
- 外部项目按存什么、谁何时写、来源、纠正/遗忘、检索、宿主兼容、许可和成熟度评估。private_companion 的可不改增量反思与片段游标、ACE 的增量修改、ReasoningBank 的失败经验是设计参考，不直接复制不兼容宿主的实现。
- 不加独立向量库或图谱运维层；召回或实体/时序推理成为实测瓶颈后再评估。不采用需配套模型的压缩编码，使用可读概要和原文关联。
- 通过上下文预算控制读取量，不破坏原始细节来模拟人类遗忘。

## 限制与已知问题

- 生产仍为 P2；未迁移、未登记新工具、未授予原文或整理权限。阶段 1–3 的离线和隔离模型样本不等于长期质量验收。
- N3 已实现并隔离验证，但生产未启用，且没有记忆整理的授权与接线。整理当前仅有存储事务，不能把 N3 的运行凭据直接当成 `memory.organize` 许可。
- 隔离 Gateway 的 reset 和手动 compact 已观察镜像保留、中文检索与遮罩；自然阈值压缩和长期捕获未观察。宿主 memory-core 的旧版本调研不当成当前版本接口验收。
- 未接外部浏览插件；后续结果须进入原始层且可标 external。L0 不自动含次日业务安排，闲聊是否联想到业务取决于她是否查询。
- 没有长期行为数据；是否查原文、是否自然提起、兴趣和语气须真实抽样并由主人评价。note 软边界、语义改写召回和物理删除仍有限制。
