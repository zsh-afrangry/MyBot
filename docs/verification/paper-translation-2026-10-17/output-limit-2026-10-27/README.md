# 论文输出上限、失败摘要与延迟通知修复（2026-10-27）

归属：[文档22](../../../22_论文PDF翻译与文件投递.md#后台失败说明)、[N22](../../../待办清单.md#n22-论文默认渠道与失败说明)。状态：**待复验**。主人在[17:03调查](../qq-retest-2026-10-27-1703/README.md)后明确要求移除8192 token限制，并询问DeepSeek官方上限；本轮实施源码、文档、本地提交及生产重载。没有自动重译、真实模型/API/QQ测试外发、开放禁用工具或远端Git写入。

## 结果

- 移除所有厂商共用的`max_output_tokens=8192`。DeepSeek Flash/Pro在受信注册表登记393216（384K），worker实际请求/每次回执及用量快照使用该值；模型参数不能覆盖它。未登记可靠最大值的OpenAI转发渠道省略该参数，使用上游默认，不假定与DeepSeek相同。
- 上限依据2026-10-27查阅的[DeepSeek模型元数据](https://api-docs.deepseek.com/api/list-models/)与[Responses文档](https://api-docs.deepseek.com/api/create-response/)；输出包含推理token，1M上下文不等于384K输出。生产整篇已报告token预算300000、300请求、high、并发、QPS及期限保持。该预算只限制新请求准入，在途请求仍可能超出，不构成金额硬上限。
- Responses未完成时保留白名单`responseStatus/incompleteReason/maxOutputTokens`；明确区分`max_output_tokens`、`content_filter`与未知原因，不保存正文、推理或任意错误消息，不从部分响应拼译稿，不自动轮换渠道掩盖未完成。
- status/list返回任务/产物/投递/通知状态和用量汇总，失败摘要在前；完整逐请求回执、请求人私密绑定、内部路径留在后台记录。300条回执的合成任务返回不足4000字符，后台回执仍完整。
- 队列以插件启动时建立的Node异步资源持有后台工作，清除来自短期工具调用的继承关系；仍保留真实请求人、取消、撤权、停服等待、逐篇串行及无重启自动付费重放。说明继续使用原会话/Agent且全部工具关闭，未开放运行期禁用能力。

旧17:06任务没有保留上游未完成原因，8192输出与旧请求限制相等支持截断判断，不能补写成已经取得上游明确原因。新代码仅改善后续记录，不重写旧任务账本。
