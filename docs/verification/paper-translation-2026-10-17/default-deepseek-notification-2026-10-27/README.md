## 结果与边界

- 未指定组合时选择`deepseek/official/deepseek-flash/high`；显式GPT仍使用naiccc/gpt-6.1-sol与014→030→040，不跨厂商回退。凭据导入脚本显式保留两厂商字段，避免默认切换后误丢GPT密钥。
- 凭据仍在私密运行目录的`paper-credentials.json`，字段`DEEPSEEK_API_KEY`。只核对字段非空、普通文件与0600，不输出密钥、不复制入仓库，未请求官方API验证可用性/余额。
- 旧通知确由程序拼接，且发送时尚未读取worker最终用量。本轮先保存用量、阶段及结构诊断，生成安全白名单`failureSummary`，再触发说明；status/list对历史失败也可即时返回说明，不重放旧通知。
- 原会话、原Agent、实际请求人接收摘要并由宿主生成解释；说明回合全部工具关闭，不新增后台Agent或QQ助手权限。运行前及发送前核对权限，结果不改发给主人。模型失败/超时/空答时发送中文兜底，并为后续问询注入已通知的摘要。
- 只调用一次公开QQ投递接口及原幂等账本；发送回执未知不追加第二条。通知独立记状态；重启时将未确认通知记为未知，不自动重放。文件投递未知时明确“译文已生成”，不会建议重新付费翻译。

`translation_budget_exhausted`解释为本地单篇请求/token上限，不能据此断言账号没钱；真正余额/配额、鉴权、限流、渠道故障、时限、结构/公式校验分别说明。DeepSeek官方[错误码说明](https://api-docs.deepseek.com/quick_start/error_codes/)将402定义为余额不足、401为鉴权失败、429为限流，本轮按确定的HTTP码及安全错误码分类，任意上游错误正文不交给解释模型。早先已恢复的渠道错误不能覆盖最终结构校验等失败原因。

本轮没有提高30万token/300请求限制，没有重试00:23失败任务。[原调查](../runtime-failure-2026-10-27/README.md)的300,963报告用量、030大输入来源待核实结论保持有效；默认切换不构成渠道计量修复。
