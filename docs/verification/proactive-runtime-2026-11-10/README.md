## 失败与修正

本轮不是零失败。完整宿主早期10次失败摘要、请求数和修正保存在checks.json：遗漏既有配置字段；P2引入过宽；undefined允许值被错误兜底拒绝；夹具dmScope及宿主owner投影不足；正常前台取消被外层误报失败。曾怀疑跨插件实例共享问题，但没有证据证明SDK缺陷；实际确认的策略问题是nullish coalescing错误。最终将N3收在现有QQ组件中，原因是单维护者的组合和生命周期更简单。

修正后11场景/27请求、12场景/27请求曾通过；最终增加原生Fetch来源钩子后13场景/30请求通过。所有隔离子进程已停止。文档索引首次检查因boundary里的“real-model judgment”被规则当成真实模型调用声明而拒绝；改成准确且无歧义的行为验收边界后通过，不伪标真实付费调用。

同期另一工作已独立完成主人日志工具启用（12c09ee），导致生产配置/InvocationID更新；N3保持关闭，前后指纹与原因在checks.json分别保存，不冒称整段时间生产从未重启。

详细临时诊断目录在收录脱敏失败证据后退役，不将原始测试会话和密钥复制进仓库。

## 未验收与部署边界

- 30分钟机会、60秒运行、23:00–08:00/15分钟活动是禁用示例，等待主人审核；不是既定生产取值或发言配额。
- 主人四项proactive用途、main窄工具、四类领域读取/公开检索用途、固定本人外发尚未启用；成员、群聊、业务写入、日志后台读取、编码委托和N2整理不在范围内。
- 实际模型的判断、自然表达、成本与长期习惯须在具体授权后观察；本地确定性模型不替代这些结论。
- 既存R8/R7保留原恢复范围，不含本轮新增源码和N3状态；上线前制作匹配恢复点，之后再作启用后的成套恢复验证。
