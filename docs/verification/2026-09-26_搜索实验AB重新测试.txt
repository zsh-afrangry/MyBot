二、实验 B：naiccc 原生搜索

直接请求 https://naiccc.com/v1/responses，仅使用 naiccc 凭证和原生工具声明；没有加载 OpenClaw 或 DeepSeek 客户端。
公开问题：现在查询 SQLite 官方发布历史，给出最新稳定版本、发布日期、一项变化及实际官方来源。

实际请求与结果：
1. tools=[{type:"web_search"}]，tool_choice="auto"：HTTP 200，10.163 秒。
2. tools=[{type:"web_search"}]，tool_choice={type:"web_search"}：HTTP 200，8.994 秒。
3. tools=[{type:"web_search_preview"}]，tool_choice={type:"web_search_preview"}：HTTP 200，8.757 秒。
4. web_search 强制调用并 stream=true：HTTP 200，10.767 秒，收到完整 response.completed 事件。

四次共同结果：response.status=completed，但 output 只有普通 message，没有 web_search_call，没有 url_citation。流式事件也没有搜索执行记录。回答均表示无法实时联网，未给出查询结果。
因此，HTTP 200 只说明模型响应成功，不能视为搜索成功；正文写出的官网链接也不能替代搜索记录。

判定成功原本需要：原生 web_search_call 完成、实际引用与完整回答，并核对答案是否解决查询。本轮均不满足。
结论范围：当前账号、当前模型标识、当前 naiccc /v1/responses 的上述标准及兼容请求没有走通原生搜索。不能据此断言 GPT 本身没有搜索能力、naiccc 永久不支持或其他未测试路由也必然失败。
接口没有明确返回“不支持此工具”错误，因此不能确定是工具字段被忽略、权限、转发兼容性还是上游配置问题。此处不将模型的自述当成唯一证据。

- SQLite Release History：https://sqlite.org/changes.html
- SQLite Download Page：https://sqlite.org/download.html
- SQLite Version Chronology：https://sqlite.org/chronology.html”

判定：GPT 的工具调用、OpenClaw 的 Provider 分发、DeepSeek 接口返回和 GPT 的后续回答均已实际发生；但所需的版本号、发布日期和变化没有获得，因此不能标记“搜索端到端成功”。
来源列表和 Provider 的 kind="answer" 只通过了现有格式解析，未证明搜索有效或事实已核验。现有解析器接受了带来源的无法查询声明，这是本轮直接观察到的问题。
没有保存 DeepSeek 原始响应体，只有真实网络元数据及 Provider 正常化输出。因此本报告不声称已确定 DeepSeek 内部是否执行过搜索，或已查明没有有效结果的根因。
