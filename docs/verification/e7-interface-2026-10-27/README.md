## 参数与连接问题

1. 攻略、FAQ前端传`pageSize`和`keyword`，实际样本未按它们分页/搜索。`size`和`keyWord`生效：攻略从默认12篇缩至2篇，搜索“深渊”总数从12降至2；FAQ分页从15缩至2，搜索“团战”总数从40降至4。大小写不可照搬前端。不能只看HTTP200就认为查询正确。
2. 强度榜`list`返回数组，没有分页对象；传`size:2`仍返回8份。客户端必须自行裁剪，不能假设所有`list/page`遵循相同约定。
3. 神器列表与梅铃详情使用首次响应ETag后，均得到304。这支持条件刷新设计。不是所有接口都有ETag，也未测每一个缓存分支。
4. 带自定义User-Agent的首页请求、同标识直连对照及小型兑换码接口请求均得到403 HTML；普通curl读取成功。现象与请求标识相关，但未查明站点具体WAF规则。没有继续循环换头尝试，也不据此宣布生产client已连通。生产请求标识兼容性仍开放。
5. 无需登录的查询仅按列出的路径成立；不能把整个`/open`空间视作可安全调用。RTA主机此前有限流，本阶段未访问或重试；其它详情、推荐和筛选参数也未逐个验证。

## 固定程序与AI的判断

以下为根据样本作出的实现建议，不是已经部署的能力：

| 用户问题 | 固定程序可完成的部分 | AI可增加的部分 |
| --- | --- | --- |
| “梅铃技能是什么”“露娜专属装备是什么” | 唯一匹配后取详情，展平文本段，保留倍率与强化条件 | 按要求简述或解释术语 |
| “火系刺客谁有灭亡” | 本地效果筛选；样本结果是梅铃、济纽亚 | 理解口语条件；多义条件先澄清 |
| “梅铃怎么配装” | 展示已有20条中的少量样本及日期、来源 | 依据已有测评比较用途；她的测评为空时如实说明 |
| “团战这个机制怎么算” | FAQ搜索与直接答案展示 | 对相近问题澄清、解释计算条件 |
| “这次游戏公告讲什么” | 返回公告标题与PDF原文链接 | 正文解析成功后才可摘要 |
| “我该练谁、怎么组队” | 提供候选资料和对应玩法来源 | 在主人提供目标、已有角色等条件后比较；不得补造个人阵容、缺失攻略或新版本事实 |

推荐先做**固定取数、检索、过滤和格式化，接现有聊天模型理解及解释**。这批结构化数据本身不需要另接一个AI服务或向量数据库。跨多篇长攻略的语义召回是否需要增强，应以后用真实问题验证；PDF/OCR也不能被一句“接AI”替代。

本阶段没有证明E7插件client、缓存更新、权限、真实模型调用或QQ文字/图片往返通过。普通JPG入站与PNG表情验收另见[QQ复测](../qq-image-2026-10-27/retest-0119.md)。

## 复核入口

下列命令会访问真实站点，只在需要复核时少量运行；不要将整张表当批量测试清单。只调用已确认的读取路径，不跟随重定向，遇到拒绝或限流停止：

```bash
curl --silent --show-error --compressed --max-time 20 --max-redirs 0 \
  'https://admin.e7.wiki/api/open/epicseven/hero/card-list'

curl --silent --show-error --compressed --max-time 20 --max-redirs 0 \
  --request POST --header 'Content-Type: application/json' \
  --data '{"hero_code":"mei-lin"}' \
  'https://admin.e7.wiki/api/open/epicseven/hero_equipment_scheme/getSchemeByHeroCode'

curl --silent --show-error --compressed --max-time 20 --max-redirs 0 \
  --request POST --header 'Content-Type: application/json' \
  --data '{"page":1,"size":2,"keyWord":"团战"}' \
  'https://admin.e7.wiki/api/open/epicseven/faq/page'
```

原始响应只用于临时分析，仓库仅保留请求元数据、哈希、字段结构和必要事实，不复制上游全文。`requests.json`的SHA256供后续样本比较，不表示能在不保存原文的情况下独立还原该次响应。
