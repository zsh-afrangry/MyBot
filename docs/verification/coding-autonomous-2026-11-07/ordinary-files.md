## 实现与边界

- 复用原生`exec`及主人`host.exec`，由操作者的可选`writeBoundary.additionalRoots`登记多个真实资料目录；无该字段的配置保留单根。模型不能添加根；拒绝无效、重复/相互包含、包含launcher、缺失及符号链接根，边界失效则整次拒绝。编码服务的项目登记及DSH范围不变。
- 普通文件读取、创建/修改、复制、跨已批准目录移动、改名/后缀、明确删除与目录操作沿用同一终端入口；无需Git。HOME及临时文件仍在原试点。成员、后台、Cron、模型env、提权/远端/PTY/后台模式与超时限制继续生效。
- 主人AGENTS从同一受管配置投影默认workdir与可写根，不向成员投影。模板要求目标不明先问、重名保留、不把整理解释为删除、操作后核对实际结果及部分失败。`cp -n`/`mv -n`验证的是这些命令的选定行为；通用exec没有增加命令语义判定或强制防覆盖事务。
- Linux runner实际报告partial；证据仅证明列出的普通文件写入行为，不证明网络、进程、元数据等全部系统副作用隔离。按需读取原则不因此扩展为无关聊天/凭据读取；受管论文、数据库/账本、权限及业务确认仍走所属接口。改后缀不转换格式。
- 隔离恢复器移除额外资料根并将workdir置回恢复试点，保留主人身份及编码配置；实际资料目录不自动进入Fusion恢复资产。本轮未重新制作恢复点或执行完整恢复演练，原R7/R6证明范围不变。
