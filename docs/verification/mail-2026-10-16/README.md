## 已修复的接缝与真实往返

- 初版SMTP多行响应扫描不完整，EHLO可持续超时；RFC2047分段原76字符超过75上限，现每段最多45字节；地址校验已共用规则。这些缺陷的现行实现不需要再重复展开为开发待办。
- 02:01、02:22两轮QQ失败的主要原因是**宿主毫秒时间戳被邮件Store当秒**，使提案看似已过期。原时点3次no_match：02:01:29、02:23:10、02:24:30；当时approved仅有脚本产生的1条。这些是历史状态，不代表现在仍有3条待确认。
- `eventSeconds`统一候选与授权的单位处理；`email_send`容忍并忽略模型附带的approval字符串，授权仍只读宿主grant。临时生产副本回放与毫秒形状回归通过，未修改生产提案。
- 原测试只用Store自己的秒时钟，遗漏宿主毫秒事件；补齐真实数据形状后通过。此前“02:01草稿根本没建成”的判断已纠正：02:01:09确实创建，schema被拒后模型重试成功，后续失败仍由时间单位造成。
- 适配器迁移使工具与确认backend都消费选定Store，覆盖“入站确认到达替换存储”；默认SQLite仍同步，SMTP留在异步服务层。没有修改确认协议或建立第二套授权。
