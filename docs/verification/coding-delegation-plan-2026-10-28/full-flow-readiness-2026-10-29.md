## 最小试点实现范围

建议先补一条可审阅、可停用的DSH通道，完成后再部署并执行真正的QQ往返。优先评估复用OpenClaw原生ACP的任务生命周期；若不能满足本项目的身份、工作树、审批与投递契约，则为现有任务入口接一个独立执行适配器，不重建QQ入口。

无论采用哪条宿主接线，最小实现都应包含：

1. **登记与准入。** 只接受操作者登记的试点项目ID，由宿主解析真实路径和DSH后端；模型不能提交任意cwd、启动命令、投递对象或身份标志。既有研究任务和旧项目任务按原契约执行。
2. **真实后台任务。** 发起立即返回内部任务标识，持久绑定请求者、外部sessionId、后端、源SHA及工作树；在正确任务上查询、补充、续接与取消。审批请求关联原工具事件，实际取消后核实进程停止。重启状态不明时先核对，不能重复启动实验。
3. **检查与待确认合入。** 使用登记检查和实际diff形成已验证的最小任务提交；失败保存私有快照。合入预览固定任务提交及目标基线，由主人确认后执行；目标变化使旧确认失效。自然语言确认沿用`@kurumi/confirmation-core`，不添加模型可自报“已确认”的参数。
4. **回传与日志。** 把真实状态、必要检查与差异摘要回到原本人QQ；发送前复核权限，投递失败/未知不触发任务重跑。记录可信QQ/宿主run/toolCallId、内部任务、外部会话、检查、确认及回执，统一日志不保存原始提示词、代码、凭据或完整终端输出。

这是一条最小产品闭环的实施范围，不是已有实现清单。无Git目录回写、其他编码后端、桌面接手、项目外文件写入、系统安装及自动合入继续按文档28的分期安排，不作为这一条通道成功的附带结论。

## 真实验收步骤

先建无远端的临时Git项目，包含小型功能及有效测试，故意在源目录保留一份未提交进度；项目ID建议为`dsh-pilot`。不选择主源码仓库或生产数据目录作为第一个合入目标。

| 顺序 | 通过条件 |
| --- | --- |
| 1. 主人从QQ发起 | 真实入站经现有唯一QQ入口，正确识别项目和执行意图；讨论不启动；后台任务返回真实标识 |
| 2. 独立工作树执行 | 固定源分支已提交SHA，不带入源目录未提交内容；DSH实际修改功能并运行检查；主聊天仍可继续 |
| 3. 查询与补充 | QQ查询得到该任务真实状态；补充进入原外部会话，没有新建重复任务或串入其他工作树 |
| 4. 完成并回传 | 复核实际文件和检查输出后形成任务提交，回传差异摘要、检查结果与待合入状态；不能把end_turn直接当成功 |
| 5. 主人审阅确认 | 给主人展示具体任务提交、目标基线与改动，等待本人在QQ确认；确认只作用于这份冻结候选 |
| 6. 合入并复验 | 对临时目标进行本地合入，检查通过；原有未提交内容不丢失；没有push；目标变化/冲突按新候选处理 |
| 7. 指定任务取消 | 另起可观测的短任务，主人从QQ取消；实际进程停止、其他任务与共享服务继续，产物保留 |
| 8. 链路核对 | QQ入站、宿主调用、内部任务、DSH会话、工作树、检查与合入、出站回执可关联；平台受理与本人收件分别记录 |

可自动核对处理器、接口、进程、文件和回执；真人QQ发起、阅读具体差异后确认、查看收到的结果仍需要主人参与。合成入站或模拟OneBot只能标为相应宿主测试层级，不能代替此表。

## 启用前需要说明与确认的范围

现有`kurumi_task`已经在白名单中，也不代表可以直接扩大为DSH任意执行入口。按仓库[开发指引](../../../AGENTS.md#触及禁用限制时必须先告知)，采用专用工具或后端也必须先说明实际外部执行能力，再由主人决定。

拟议试点限于：本人私聊、一个明确登记的临时项目、DSH ACP、任务工作树内开发与检查；必要的外部执行由专用委托边界承载，通用文件/exec/process/message/sessions_spawn仍保持禁用。DSH使用本机实际身份，worktree本身不构成操作系统隔离；需要在实现中明确真实读写、网络与审批限制，不能只靠提示词承诺不越界。

真正部署时会涉及经审阅的受管配置/插件同步、必要的Fusion重启，以及向本人QQ发送测试接收、进展、预览或结果。真实外发与权限变化须有明确授权并记录；不启停共享DSH、SnowLuma或QQ，不修改其他项目，不推送，不开启实验性Auto review。具体配置差异应在最小实现完成后展示并确认，不能把这份方案当作已部署。

当前结论：**全流程前置条件尚未满足，需先进入最小闭环开发。** 没有本轮业务测试结果可登记为通过，也不因用户提出全流程测试就自行修改QQ受管权限。后续实现、启用授权及真实验收应各记实际进展。
