## 接口结果

| 接口与用例 | 结果 | 对接含义 |
| --- | --- | --- |
| SDK `initialize`、`shutdown` | 通过；进程正常退出，无协议解析错误 | 可建立stdio连接；本次没有通过SDK发真实编码任务 |
| SDK `session/cancel` | 实际返回`-32603`、unknown method | 本机SDK没有单会话取消接口；不是可直接采用的完整生命周期通道 |
| Headless未知`--session-id`，`--json` | 退出1，输出可解析的单条JSON error | 无效续接明确失败；本次没有跑完整headless编码任务 |
| ACP握手、新建、模型选择、prompt | 通过 | 真实任务和结构化事件可用 |
| ACP相对cwd、未知会话、错误cwd续接 | 均按预期拒绝，`-32602` | 会话绑定真实绝对工作目录，不能仅按最近会话猜测 |
| ACP列表、关闭、跨进程resume | 通过 | 列表只包含非活动的可恢复会话，不能据此查询正在运行的任务 |
| ACP cancel | 通过；`stopReason=cancelled`，观察到实际子进程停止 | 不能只看请求发送成功，还需核对执行进程和产物 |
| ACP权限允许/拒绝 | 均通过；允许后精确写入，拒绝后文件不存在 | 无界面客户端可以接收并回答权限请求；这不是Auto review已验收 |

ACP请求顺序为`initialize` → `session/new`（绝对cwd）→ `session/set_config_option` → `session/prompt`，通过`session/update`按外部sessionId接收事件。取消使用`session/cancel`通知；关闭使用`session/close`请求；后续新进程以原sessionId、原cwd和`mcpServers: []`执行`session/resume`。本次握手声明支持close/list/resume与MCP HTTP，未声明图片、音频和embedded context支持。

SDK的prompt确认仅代表进入收件队列，不代表任务完成；它目前也不向客户端发起权限请求。不同通道不能共用“prompt返回即完成”的判断。上述结论依据本机安装包的`dsh-sdk-protocol`、`dsh-acp`、`dsh-headless` README与实现；[上游项目](https://github.com/deepseek-ai/deepseek-harness)的master可能已经新增行为，不能覆盖本机版本事实。

## 取消与权限回调

取消测试让模型实际启动一个每200ms更新心跳、最长60秒自退出的Node子进程。探针先确认它正在运行，再向指定会话发送ACP取消。修正后的测试约10ms得到`cancelled`，随后确认宿主机实际子进程停止，1.2秒观察窗口内心跳不再增长；工作树、脚本及已有产物保留。没有通过停止共享DSH服务实现取消。

权限测试分别创建拒绝和允许会话。固定测试控制器依据**sessionId + toolCallId**关联此前`session/update`的`tool_call`内容，只允许该测试会话向指定夹具路径写入约定内容；拒绝用例选择`reject_once`，允许用例选择`allow_once`。两次都实际收到一次写入请求：拒绝用例未生成文件，允许用例生成了正确内容。两次prompt均返回`end_turn`，说明**正常结束不等于任务目标已达成**，必须另外核对文件和拒绝结果。

`session/request_permission`本身只携带工具调用ID及可选决定，客户端必须保留并关联此前工具事件，才能展示动作和目标。该控制器不是通用自动审批器，未加入Fusion，也未验证“等待主人从QQ审批”的往返流程。

## 两次探针修正

1. 首次并行探针在代码检查和14条外部断言通过后，错误地要求`session/list`包含活动会话，因而整份初次探针退出失败。本机实现明确排除活动/激活中的会话。保留这一失败记录，在新进程中核对持久会话列表、错误cwd拒绝、原ID续接、活动后消失与close后重新列出，修正断言后通过；没有丢弃已成功的任务或重跑原编码需求。
2. 首次取消观测把沙箱内PID 2当作宿主机PID，观测失败，未发送ACP取消；测试运行时随后释放。没有向宿主机PID 2发送信号。复测在新工作树中只枚举本次ACP进程的后代，结合命令行与`NSpid`解析真实宿主机进程，再发取消并核对心跳。适配器不能根据模型输出的数字任意终止宿主机进程。

## 接入建议与未覆盖范围

首期优先采用**本机DSH ACP stdio**，下一步评估现有OpenClaw ACP运行时能否承接本机接口，再决定复用运行时或添加薄执行适配器。ACP已提供所需的会话、事件、续接、取消及权限请求；SDK仍缺少必要生命周期接口，Web API和桌面操作不作为本轮首选。

适配器应持久保存内部任务、外部sessionId和规范化cwd，并通过事件维护运行中状态；`session/list`只能辅助核对非活动会话。应区分执行结束、目标完成、检查通过、待合入和取消已确认。跨进程恢复本次覆盖的是有序关闭，不证明崩溃、断线时正在运行的任务均能恢复。

本机实验性`dsh-experimental-auto-review`属于Web profile层，默认未启用；本机说明是审查后在Full access执行，与Codex保留workspace-write边界的机制不同，直接Node副作用也不由内部工具审批完全覆盖。这里只读核对，**未启用、未测试其稳定性或安全性**；不能把ACP单次允许/拒绝测试称为DSH Auto review通过。

仍需实施并分层验证：Fusion任务编排与身份权限、真实项目登记、按需读取项目外信息和依赖安装、主人确认合入/过期确认/冲突、无Git副本回写、统一日志、QQ发起与回传、审批等待、异常重启/连接中断、资源不足与实际规模。现阶段不开放QQ通用exec等能力，也不从此次小项目成功推导自动合入可靠性。
