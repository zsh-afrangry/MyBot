## 关键断言

1. 源目录预留的已暂存、未暂存及未跟踪进度不带入工作树；编码和续接不修改源分支；临时合入前后这些内容及暂存状态保持一致。
2. 必需检查失败不创建正式任务提交。失败改动可保留私有补丁/文件快照；显式回档仅针对已停止任务的最近验证提交。检查期间工作树变化、后端私自提交或候选篡改均拒绝通过。
3. 同一可信调用重试不重复发起/续接模型；任务、会话、工作树与请求者持久绑定。成员、伪造上下文、未知action及串用任务ID被拒。
4. 合入预览固定任务提交、目标HEAD/分支/脏内容、候选及diff hash，并检查整合后的候选。旧预览不能套用到变化后的目标，未跟踪/忽略文件不能被覆盖；多任务最终合入串行。共享confirmation-core验证冻结预览回执和后续当前本人消息，一次性grant在Git外部操作前事务消费；不提供模型自报批准参数。
5. 投递异常/未知单独记录，不触发重跑。任务事件不带原始需求、代码、终端或凭据；实际工具runId从调用钩子解析，旧KnowledgeMap导入路径继续可用。
6. 额外ACP权限一律拒绝并报告；不启用Auto review。取消只影响该任务自有运行与检查进程，核实后才标cancelled；异常重启标待核对，不能自动启动重复实验。
