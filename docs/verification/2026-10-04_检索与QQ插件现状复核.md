## 4. 当前搜索架构与原生替代方案

当前生产链：

    naiccc/gpt-5.6-terra（openai-completions，primary）
      或 deepseek-search/deepseek-v4-flash（openai-responses，fallback）
          → 普通函数 web_search → Tavily 搜索结果
          → 普通函数 web_fetch → Host 抓取网页、抽取文本

web_fetch enabled=true、useTrustedEnvProxy=true、maxChars=maxCharsCap=15000。
deepseek-search 现在是模型 provider 的历史命名，不代表生产 web_search 仍使用旧 DeepSeek 搜索插件。
Tavily 也是安装插件提供的 Host 搜索后端，不是模型内置能力。T3 历史实验使用 Tavily extract 的模拟 fetch，不能直接等同于生产 Host web_fetch。

原生搜索则要求模型 API 请求中声明 type=web_search，让服务端执行；普通函数虽然也叫 web_search，语义不同。成功要检查 web_search_call 与 url_citation，而不能只看 HTTP 200 或文本里的 URL。
官方接口依据：https://developers.openai.com/api/docs/guides/tools-web-search （原调查引用）。

DeepSeek 的 Responses 原生搜索失败结论来自 9 月 30 日调查；不能把 naiccc 的成功推广到 DeepSeek，也不能永久断言 DeepSeek 所有接口永不支持。

当前 2026.9.7 Host 代码确有两条原生路径：

1. codex-native-web-search-core-BKC_bFdr.mjs:13：只接受 openai-chatgpt-responses；显式选择 Tavily 还会得到 managed_provider_selected。
2. native-web-search-policy-DF3LKnkU.mjs：接受普通 openai-responses，但同时要求模型 provider=openai、官方 API 地址，并且搜索 provider 未指定/auto/openai。

本轮直接调用第 2 个已安装判定函数，令搜索 provider=auto：

| 模型 provider | baseUrl | 原生搜索启用 |
| --- | --- | --- |
| naiccc | https://naiccc.com/v1 | false |
| naiccc | https://api.openai.com/v1 | false |
| openai | https://naiccc.com/v1 | false |
| openai | https://api.openai.com/v1 | true |

所以“普通 Responses 都不支持”不准确；“这套 naiccc 自定义地址目前不被 Host 原生接入接受”准确。只改模型 API、provider 名称或 key 都不足以解决。

方案取舍：

- 保留当前 Tavily + fetch：主备模型共用，最小变更；先修时间过滤与新闻核验。已有生产链证据。
- 给 naiccc 接入 Responses 原生搜索：上游历史能力已证实，Host 适配尚未落地；需要受维护的 provider/Host 改动，并验收搜索事件、引用、普通业务工具共存、流式响应、图片及 fallback。直接手改 node_modules 会被升级覆盖。
- 官方 OpenAI / Codex 路径：当前 Host 代码支持，但涉及不同端点或认证；不是现有 naiccc key 改名即可替代，当前业务链未验收。
- DeepSeek 原生搜索：没有与 naiccc 等价的成功证据，不应当作可用替代。
- Exa / Brave / DuckDuckGo：历史材料中主要是可达性探测与备选，不能等同已完成同题端到端验收。Tavily extract 是抓取替代，不是模型原生搜索。

## 7. 本次实际修复、复测及整理结果

### 验收脚本

- 复现 `entries.qqbot.enabled` 异常后，修改两个检索验收脚本共用的安装解析函数：插件 ID 为 `openclaw-qqbot`，包为 `@tencent-connect/openclaw-qqbot`，频道名仍为 `qqbot`；安装路径由包 manifest 校验，不再找旧 `@openclaw/qqbot`。
- 群配置改用现役 `toolPolicy=none`。隔离频道若 `enabled=false`，新版加载器不会注册 QQ 群工具策略，直接调用工具工厂会得到错误的测试环境。隔离配置改为启用频道、使用虚构 QQ 凭据，只注册插件，不启动任何 Gateway/QQ 服务；保留群工具断言，结果为零工具。
- smoke 通过：现役插件加载、私聊 search/fetch/weather 可见、旧搜索工具和 exec/browser/write 不可见、群工具列表为空。
- Host 实网工具测试通过：两次并发 Tavily 搜索成功、SQLite 官方正文 HTTP 200、输出上限 15000、内网 URL 被拒绝。
- 三题真实 naiccc 模型复测通过脚本断言：Q1 搜索一次、读原文两次，42.6 秒；Q5 概念题不联网，7.2 秒；Q6 只调用天气工具、不搜索，8.9 秒。**Q6 返回 forbidden_context**，只证明路由正确，不代表天气成功或真实 QQ owner 门控已通过。

### 原生搜索与时间参数

本轮直接执行当前安装包的原生搜索资格判定函数：naiccc/provider 或 naiccc/baseUrl 任一存在时均返回 false；官方 openai provider + 官方地址 + Responses + auto 才返回 true。9 月 30 日 A–F 原始响应重新计数，A/B/C/D 各 1 个 web_search_call / 1 个引用，E 为 3/2，F 为 0/0。

生产 Tavily 时间参数丢失尚未修复。官方 Search API 支持 time_range 和日期边界，故问题在本地通用适配层，而非上游没有该能力：[Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)。需要同时对齐 Host 工具发现契约、provider schema、参数映射与结果日期；不应把检索词包含“最近”当成时间过滤已修好。模型无 web_fetch 的新闻回复也不能因基础工具复测通过而标记为已解决。

本次没有直接修改安装目录的供应商代码，亦未改为原生搜索路线。下一次实现应单独验收时间参数实际到达下游、原文日期核验、流式引用与业务工具共存。
