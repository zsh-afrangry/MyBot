## 文件与边界

| 文件 | 结果与边界 |
| --- | --- |
| [model-image.json](model-image.json) | 真实QQ CDN图片经 `stageImage`下载，JPEG为1,012,270字节；独立main会话 `deliver=false` 送官方DeepSeek，回执模型无reroute并识别图片内容。存在细节误读，不代表建议正确或真人QQ完整往返通过 |
| [channel-tests.txt](channel-tests.txt) | 当时QQ频道19项回归；CDN精确主机修复保留HTTPS、8MiB、类型和重定向限制，不开放任意URL |
| [stack-lifecycle.json](stack-lifecycle.json) | 当时启停与旧消费者切换记录；不覆盖后来“QQ传输只检查、不启停”的脚本实际往返。当前启停契约见文档10 |

原图域名 `multimedia.nt.qq.com.cn` 曾因只允许不带`.cn`的主机而在频道入口被拒，模型只收到未加载提示。修复后同图在独立会话可下载并输入模型；测试没有重新向用户QQ发验收消息，不扩大为日常新图片体验已验收。证据未保存签名图片URL、凭据或思考正文。

## 迁移来源与后续决定

- 旧bridge角色素材复制到 `roles/`，两份角色卡原件与哈希见[角色来源说明](../../../roles/README.md)；当前使用世凪，旧卡仍保留。
- 一次性迁移脚本 `scripts/fusion/configure-deepseek-persona.mjs`复用旧DeepSeek凭据，未修改旧系统原件；配置和四份人格文件的私密备份位于 `.openclaw-fusion/migration/before-deepseek-whale-2026-10-05/`。它不是日常切换或当前全量恢复入口，旧聊天/记忆/业务数据库未清空。
- 旧版Start脚本曾启动qq-bridge并因systemd互斥停止Fusion。当前只允许一个QQ消费者，脚本不再启停SnowLuma/QQ；完整规则和部署位置归文档10。
- 早期文档建议自然确认、明确提醒免确认等；用户后来明确选择**保留带码确认**，这些建议不是现行待办。提醒列表/账单明确维护可直接执行，各自规则见19/23；一次性提醒固定runner写死“主人”的问题仍归文档21待处理。
