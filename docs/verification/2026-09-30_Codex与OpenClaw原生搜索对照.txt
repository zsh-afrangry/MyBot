# Codex 与 OpenClaw 原生搜索对照

日期：2026-09-30
状态：接口能力与 Host 接入差异已验证；尚未将生产检索链路切换为原生搜索。

## 结论

1. 当前 naiccc 的 gpt-5.6-terra 可以通过 Responses API 执行原生网页搜索。旧记录中的“未走通”不能作为当前不支持的依据。
2. API Key 不是本轮差异的原因：统一前，两边各自的 Key 均成功。按用户授权，已将 OpenClaw 的 OPENAI_API_KEY 更新为 Codex 桌面端当前 Key，重启 Gateway，并核对运行中进程确实使用新值。
3. OpenClaw 当前使用 openai-completions，并把普通函数 web_search 交给 deepseek-search provider。该函数的名称不等于 Responses 原生工具类型 web_search。
4. 当前 Host 的 Codex 原生搜索开关只接受 openai-chatgpt-responses；普通 openai-responses 不符合其启用条件。因此，仅换 Key、仅改 API 类型，或仅打开原生搜索开关，都不能把现有生产配置自动变成已验证的原生搜索链路。
5. 2026-09-26 的原始请求体原样重放后成功。当前证据无法确定四天前失败的内部原因，不将其归因于某个未经证明的服务端改动。

## 边界

- 真实 API 请求仅包含公开 SQLite 查询；未发送 QQ 历史、业务数据库或生产 Agent 提示词。
- 没有向 QQ 发送测试消息，没有修改业务数据库，没有更换生产主模型、接口协议、检索 provider 或工具策略。
- 唯一生产改动是用户明确要求的凭据统一，以及使其生效的 Gateway 重启。
- 请求/响应记录不包含认证头或明文凭据。原环境文件备份为私有文件，不能作为报告附件公开。
- 本次没有运行 T4，没有开展检索速度优化，也没有验收原生搜索的完整生产业务链路。

## Host 实际构造请求与启用条件测试

脚本 audit_host.mjs 直接调用已安装 Host 的模型适配器和原生搜索判定函数。提示词与普通搜索函数定义均为合成数据；onPayload 在发网前主动中止，只捕获生成的请求。报告中的 INTENTIONAL_STOP_BEFORE_NETWORK 是预期诊断行为，不是 API 故障。

现有 openai-completions 适配器生成：

    tools: [{ type: "function", function: { name: "web_search", ... } }]

仅换 openai-responses 适配器仍生成：

    tools: [{ type: "function", name: "web_search", ... }]

真实直连测试启用服务端搜索所用的是：

    tools: [{ type: "web_search" }]

这三种声明不等价。前两种要求客户端执行一个普通函数；第三种要求服务端提供搜索能力。

原生搜索启用函数实测：

- openai-completions：eligible=false；即使在内存副本中启用 openaiCodex，仍为 managed_only / model_not_eligible。
- openai-responses：同样 eligible=false，启用开关也不能改变该判定。
- openai-chatgpt-responses：eligible=true，但它是另一条 ChatGPT/Codex 认证与传输路径。

代码核对还发现，openai-chatgpt-responses 适配器会从 token 提取 accountId，并采用 Codex URL 构造逻辑。这不是把普通 API Key 的协议名称改掉即可等价替代的路径；本次没有尝试强行替换生产配置。

依据位置：
- Host dist/codex-native-web-search-core-DEpF95I7.js：isCodexNativeSearchEligibleModel、resolveCodexNativeSearchActivation。
- @openclaw/ai/dist/openai-completions-B9QLIq2U.mjs：buildParams、convertTools。
- @openclaw/ai/dist/openai-responses-shared-sj2YUPYc.mjs：applyCommonResponsesParams。
- @openclaw/ai/dist/openai-chatgpt-responses-DVC4Bk_A.mjs：extractOpenAICodexAccountId、resolveCodexUrl。

## 对后续方案的影响

应撤回“naiccc / gpt-5.6-terra 当前不能原生搜索”作为选用 Tavily 的前提。Tavily 仍是一条已经验证的独立搜索方案，但不能再说它是由于该模型无法原生搜索而被迫选择的唯一途径。

如果后续选择原生搜索接入，仍需验证 Host 如何声明服务端工具、保留搜索事件和引用、与现有业务函数共存，以及图片、确认机制、异常与回滚路径。这属于下一项生产接入工作，本次没有直接修改 Host。

旧失败的原因尚未完全还原：请求体相同而本次成功，说明旧结论不再能描述当前能力；缺少供应商侧日志及完整历史请求环境，不能确定是上游状态、账号路由、临时故障还是其他兼容性变化。
