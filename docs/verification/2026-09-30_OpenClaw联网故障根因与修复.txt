# OpenClaw 联网故障：根因定位与修复

日期：2026-09-30
状态：根因已用真实 API 请求定位；修复已落地并通过真实链路验证。

## 一、结论（根因）

OpenClaw 里 agent 之所以“连不上网”，不是网络、不是 API Key、也不是模型不支持，
而是**生产检索链路选错了 provider**：

- 修复前 `tools.web.search.provider = "deepseek-search"`。
- `deepseek-search` 由 `personal-search` 插件提供，它把搜索转成一次
  `POST https://api.deepseek.com/responses`，并在请求体里声明
  `tools: [{ "type": "web_search" }]`。
- 但 DeepSeek 这条 Responses 调用**根本不执行服务端网页搜索**：工具被忽略。

因此 agent 拿到的不是检索结果，而是 DeepSeek 凭自身记忆写的答案；
`personal-search` 的解析器随后从这段文本里正则抽取 URL 当作“来源”，
于是产生“看起来搜过了、其实没搜”的假引用。这正是“没法正常联网”的直接原因。

## 二、真实请求证据

使用 `gateway.systemd.env` 中的真实凭据直接请求（消费型测试）：

| 请求 | HTTP | output 条目类型 | web_search_call | url_citation |
| --- | --- | --- | --- | --- |
| DeepSeek `/responses`，`tools=[{type:"web_search"}]`，`tool_choice=web_search` | 200 | reasoning, message | **无** | **0** |
| DeepSeek `/responses`，`tools=[{type:"web_search_preview"}]` | 200 | reasoning, message | 无 | 0 |
| DeepSeek `/responses`，无 tools（对照） | 200 | reasoning, message | 无 | 0 |
| naiccc `/v1/responses`，模型 `gpt-5.6-terra`，`tools=[{type:"web_search"}]` | 200 | reasoning, message, **web_search_call**, reasoning, message | **有** | **1** |

- DeepSeek 返回的 reasoning 原文包含：“I don't have a web search tool available in
  this conversation — no tools listed.”，`status` 为 `completed`，即静默失败。
- naiccc 的 `web_search_call.action.type` 为 `search`，queries 里是真实检索词
  （`site:sqlite.org ...`），并带 `url_citation`。

**即：同一把 Key 下，naiccc/gpt-5.6-terra 的原生联网搜索是真实可用的；
被换掉的只是 OpenClaw 这一侧的搜索接线。**

## 三、为什么不能直接照搬 Codex 的原生搜索

Codex 桌面端能用原生搜索，是因为它走 Responses API 原生 `web_search`。
OpenClaw 的 Host 版本 2026.7.1-2 把这条路写死了：

- `dist/codex-native-web-search-core-DEpF95I7.js` 中
  `isCodexNativeSearchEligibleModel()` 只在
  `modelApi === "openai-chatgpt-responses"` 时返回 true。
- 官方文档 `docs/tools/web.md` 也明确：原生 OpenAI Responses 搜索只适用于
  `provider: openai`、无 baseUrl 或官方 baseUrl 的直连；**不适用于
  OpenAI 兼容代理地址**。naiccc 属于兼容代理，因此不会注入原生工具。
- `openai-chatgpt-responses` 是另一条 ChatGPT/Codex 认证与传输路径，需要
  OpenAI 的 oauth/token 档案，普通第三方 API Key 不等价可用；
  `tools.web.search.provider: "codex"` 也需要 Codex app-server 的 OpenAI 登录。
  当前 `auth_profile_state` 为空，不可用。

结论：在不改 Host（改 `node_modules` 会被 npm 升级覆盖）的前提下，
原生搜索无法接入主模型。因此采用文档《8_检索功能重构.txt》已定的方案。
